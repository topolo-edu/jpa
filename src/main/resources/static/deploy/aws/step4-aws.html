1. AWS 계정 생성 (처음 사용자용)

💡 AWS 계정이란?

AWS 서비스를 사용하기 위한 계정입니다. 신용카드 정보가 필요하지만, 무료 티어로 12개월간 무료로 사용할 수 있습니다.

단계별 계정 생성

1
AWS 공식 사이트 접속

https://aws.amazon.com → "계정 생성" 클릭

2
이메일 주소 입력

AWS 계정 ID로 사용될 이메일 주소 입력

3
비밀번호 설정

강력한 비밀번호 설정 (대소문자, 숫자, 특수문자 포함)

4
신용카드 정보 입력

무료 티어 사용을 위한 신용카드 등록 (실제 과금되지 않음)

5
전화번호 인증

SMS 또는 음성 통화로 인증번호 확인

6
지원 플랜 선택

"기본 지원 - 무료" 선택 (개인 사용자용)

IAM 사용자 생성 (보안을 위해 필수!)

⚠️ 왜 IAM 사용자를 만들어야 하나요?

루트 계정으로 AWS 서비스를 사용하면 보안상 위험합니다. IAM 사용자를 만들어서 필요한 권한만 부여하는 것이 안전합니다.

IAM 사용자 생성 단계

1
AWS 콘솔에서 IAM 서비스 접속

AWS 콘솔 → "IAM" 검색 → IAM 서비스 클릭

2
사용자 생성

"사용자" → "사용자 생성" 클릭

3
사용자 이름 입력

예: "jpa-developer" 또는 "my-aws-user"

4
액세스 유형 선택

"프로그래밍 방식 액세스" 체크 (CLI 사용을 위해)

5
권한 부여

"기존 정책 직접 연결" → "AdministratorAccess" 검색 후 선택

6
사용자 생성 완료

"사용자 생성" 클릭 → 중요! Access Key ID와 Secret Access Key를 안전한 곳에 저장

🔑 Access Key 저장 주의사항

  • • 한 번만 표시: Secret Access Key는 다시 볼 수 없습니다
  • • 안전한 곳에 저장: 메모장이나 비밀번호 관리자에 저장
  • • 절대 공유 금지: GitHub에 올리거나 다른 사람과 공유하지 마세요
  • • 분실 시 재생성: 분실하면 IAM에서 새로 생성해야 합니다

AWS CLI 설치 및 설정

💡 AWS CLI란?

명령줄에서 AWS 서비스를 관리할 수 있는 도구입니다. EC2, S3, RDS 등을 명령어로 생성하고 관리할 수 있습니다.

AWS CLI 설치 (Windows)

# 1. AWS CLI 설치 파일 다운로드
# https://awscli.amazonaws.com/AWSCLIV2.msi 다운로드 후 실행

# 2. 설치 확인
aws --version

# 3. AWS CLI 설정
aws configure

# AWS Access Key ID: [IAM에서 생성한 Access Key ID 입력]
# AWS Secret Access Key: [IAM에서 생성한 Secret Access Key 입력]
# Default region name: ap-northeast-2
# Default output format: json

# 4. 설정 확인
aws sts get-caller-identity

AWS CLI 설치 (Mac/Linux)

# 1. AWS CLI 설치
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install

# 2. 설치 확인
aws --version

# 3. AWS CLI 설정 (Windows와 동일)
aws configure

✅ 설정 완료 확인

`aws sts get-caller-identity` 명령어를 실행했을 때 IAM 사용자 정보가 나오면 성공입니다!

2. VPC 및 네트워크 설정

💡 VPC란?

Virtual Private Cloud의 줄임말로, AWS 클라우드 내에서 격리된 네트워크 환경을 제공합니다. 마치 우리만의 데이터센터를 만드는 것과 같습니다.

VPC 생성 단계

1
VPC 생성

10.0.0.0/16 대역으로 VPC 생성 (65,536개 IP 주소)

2
인터넷 게이트웨이 생성

VPC와 인터넷을 연결하는 관문

3
서브넷 생성

10.0.1.0/24 대역으로 퍼블릭 서브넷 생성 (256개 IP 주소)

4
라우트 테이블 설정

인터넷으로의 트래픽 라우팅 규칙 설정

# 1. VPC 생성
aws ec2 create-vpc \
    --cidr-block 10.0.0.0/16 \
    --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=jpa-vpc}]'

# 출력에서 VpcId 복사 (예: vpc-0abc123def456789)
VPC_ID=vpc-0abc123def456789

# 2. 인터넷 게이트웨이 생성
aws ec2 create-internet-gateway \
    --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=jpa-igw}]'

# 출력에서 InternetGatewayId 복사 (예: igw-0abc123def456789)
IGW_ID=igw-0abc123def456789

# 3. 인터넷 게이트웨이를 VPC에 연결
aws ec2 attach-internet-gateway \
    --vpc-id $VPC_ID \
    --internet-gateway-id $IGW_ID

# 4. 퍼블릭 서브넷 생성
aws ec2 create-subnet \
    --vpc-id $VPC_ID \
    --cidr-block 10.0.1.0/24 \
    --availability-zone ap-northeast-2a \
    --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=jpa-public-subnet}]'

# 출력에서 SubnetId 복사 (예: subnet-0abc123def456789)
SUBNET_ID=subnet-0abc123def456789

# 5. 라우트 테이블 생성
aws ec2 create-route-table \
    --vpc-id $VPC_ID \
    --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=jpa-public-rt}]'

# 출력에서 RouteTableId 복사 (예: rtb-0abc123def456789)
RT_ID=rtb-0abc123def456789

# 6. 서브넷을 라우트 테이블에 연결
aws ec2 associate-route-table \
    --subnet-id $SUBNET_ID \
    --route-table-id $RT_ID

# 7. 인터넷 게이트웨이로의 라우트 추가
aws ec2 create-route \
    --route-table-id $RT_ID \
    --destination-cidr-block 0.0.0.0/0 \
    --gateway-id $IGW_ID

✅ VPC 설정 완료

이제 EC2 인스턴스를 생성할 수 있는 격리된 네트워크 환경이 준비되었습니다!

3. RDS 데이터베이스 설정

💡 RDS란?

Relational Database Service의 줄임말로, AWS에서 제공하는 관리형 데이터베이스 서비스입니다. 백업, 패치, 모니터링 등을 자동으로 처리해줍니다.

RDS 설정 단계

1
RDS 서브넷 그룹 생성

RDS가 사용할 서브넷을 그룹으로 묶어서 정의

2
보안 그룹 생성

데이터베이스 접근을 위한 보안 규칙 설정

3
RDS 인스턴스 생성

MariaDB 데이터베이스 인스턴스 생성

1단계: RDS 서브넷 그룹 생성

# RDS 서브넷 그룹 생성
aws rds create-db-subnet-group \
    --db-subnet-group-name jpa-subnet-group \
    --db-subnet-group-description "JPA Application Subnet Group" \
    --subnet-ids $SUBNET_ID

2단계: RDS 보안 그룹 생성

# RDS 보안 그룹 생성
aws ec2 create-security-group \
    --group-name jpa-rds-sg \
    --description "Security group for RDS database" \
    --vpc-id $VPC_ID

# 출력에서 GroupId 복사 (예: sg-0abc123def456789)
RDS_SG_ID=sg-0abc123def456789

# EC2에서 RDS로의 접근 허용 (3306 포트)
aws ec2 authorize-security-group-ingress \
    --group-id $RDS_SG_ID \
    --protocol tcp \
    --port 3306 \
    --source-group $EC2_SG_ID

3단계: RDS 인스턴스 생성

# MariaDB RDS 인스턴스 생성
aws rds create-db-instance \
    --db-instance-identifier jpa-database \
    --db-instance-class db.t3.micro \
    --engine mariadb \
    --engine-version 10.6.8 \
    --master-username admin \
    --master-user-password "YourSecurePassword123!" \
    --allocated-storage 20 \
    --storage-type gp2 \
    --vpc-security-group-ids $RDS_SG_ID \
    --db-subnet-group-name jpa-subnet-group \
    --backup-retention-period 7 \
    --multi-az false \
    --publicly-accessible false \
    --storage-encrypted true \
    --tags Key=Name,Value=jpa-database

⚠️ 주의사항

  • • 비밀번호 강도: 8자 이상, 대소문자, 숫자, 특수문자 포함
  • • 생성 시간: RDS 인스턴스 생성에는 5-10분 소요
  • • 비용: db.t3.micro는 무료 티어 대상이지만, 12개월 후 과금
  • • 접근 제한: EC2에서만 접근 가능 (publicly-accessible=false)

✅ RDS 설정 완료

RDS 인스턴스가 생성되면 엔드포인트 주소를 확인하여 애플리케이션에서 사용할 수 있습니다!

4. EC2 인스턴스 생성

💡 EC2란?

Elastic Compute Cloud의 줄임말로, AWS에서 제공하는 가상 서버입니다. 선택한 리눅스가 깔린 빈 서버로, Java와 Docker를 설치해야 합니다.

EC2 설정 단계

1
보안 그룹 생성

SSH, HTTP, HTTPS 접근을 위한 보안 규칙 설정

2
키 페어 생성

SSH 접근을 위한 키 페어 생성

3
EC2 인스턴스 생성

Ubuntu 20.04 LTS 기반 인스턴스 생성

1단계: EC2 보안 그룹 생성

# EC2 보안 그룹 생성
aws ec2 create-security-group \
    --group-name jpa-app-sg \
    --description "Security group for JPA application" \
    --vpc-id $VPC_ID

# 출력에서 GroupId 복사 (예: sg-0abc123def456789)
EC2_SG_ID=sg-0abc123def456789

# SSH 접근 허용 (22 포트)
aws ec2 authorize-security-group-ingress \
    --group-id $EC2_SG_ID \
    --protocol tcp \
    --port 22 \
    --cidr 0.0.0.0/0

# HTTP 접근 허용 (80 포트)
aws ec2 authorize-security-group-ingress \
    --group-id $EC2_SG_ID \
    --protocol tcp \
    --port 80 \
    --cidr 0.0.0.0/0

# HTTPS 접근 허용 (443 포트)
aws ec2 authorize-security-group-ingress \
    --group-id $EC2_SG_ID \
    --protocol tcp \
    --port 443 \
    --cidr 0.0.0.0/0

2단계: 키 페어 생성

# 키 페어 생성
aws ec2 create-key-pair \
    --key-name jpa-keypair \
    --query 'KeyMaterial' \
    --output text > jpa-keypair.pem

# 키 페어 권한 설정 (보안을 위해)
chmod 400 jpa-keypair.pem

3단계: EC2 인스턴스 생성

# EC2 인스턴스 생성
aws ec2 run-instances \
    --image-id ami-0c76973fbe0ee100c \
    --count 1 \
    --instance-type t2.micro \
    --key-name jpa-keypair \
    --security-group-ids $EC2_SG_ID \
    --subnet-id $SUBNET_ID \
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=jpa-app-server}]'

# 출력에서 InstanceId 복사 (예: i-0abc123def456789)
INSTANCE_ID=i-0abc123def456789

# 인스턴스 상태 확인
aws ec2 describe-instances --instance-ids $INSTANCE_ID

⚠️ 주의사항

  • • AMI ID: Ubuntu 20.04 LTS (ami-0c76973fbe0ee100c) 사용
  • • 인스턴스 타입: t2.micro (무료 티어 대상)
  • • 키 페어 보관: jpa-keypair.pem 파일을 안전한 곳에 보관
  • • 생성 시간: EC2 인스턴스 생성에는 2-3분 소요

✅ EC2 설정 완료

EC2 인스턴스가 생성되면 SSH로 접속하여 Java와 Docker를 설치할 수 있습니다!

5. S3 버킷 설정

💡 S3란?

Simple Storage Service의 줄임말로, AWS에서 제공하는 무제한 파일 저장소입니다. 이미지, 문서, 동영상 등 모든 종류의 파일을 저장할 수 있습니다.

S3 설정 단계

1
S3 버킷 생성

고유한 이름으로 S3 버킷 생성

2
버킷 정책 설정

이미지 공개 접근을 위한 정책 설정

3
CORS 설정

웹 애플리케이션에서 S3 접근을 위한 CORS 설정

1단계: S3 버킷 생성

# S3 버킷 생성 (고유한 이름 사용)
BUCKET_NAME=jpa-app-files-$(date +%s)
aws s3 mb s3://$BUCKET_NAME

# 버킷 이름 확인
echo "버킷 이름: $BUCKET_NAME"

2단계: 버킷 정책 설정

# 버킷 정책 생성 (이미지 공개 접근 허용)
cat > bucket-policy.json << EOF
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::$BUCKET_NAME/images/*"
        }
    ]
}
EOF

# 버킷 정책 적용
aws s3api put-bucket-policy \
    --bucket $BUCKET_NAME \
    --policy file://bucket-policy.json

3단계: CORS 설정

# CORS 설정 생성
cat > cors-config.json << EOF
{
    "CORSRules": [
        {
            "AllowedHeaders": ["*"],
            "AllowedMethods": ["GET", "POST", "PUT", "DELETE"],
            "AllowedOrigins": ["*"],
            "ExposeHeaders": []
        }
    ]
}
EOF

# CORS 설정 적용
aws s3api put-bucket-cors \
    --bucket $BUCKET_NAME \
    --cors-configuration file://cors-config.json

⚠️ 주의사항

  • • 버킷 이름: 전 세계적으로 고유해야 함 (소문자, 숫자, 하이픈만 사용)
  • • 정책 설정: images/ 폴더만 공개 접근 허용
  • • CORS 설정: 웹 애플리케이션에서 S3 접근을 위해 필요
  • • 비용: S3는 무료 티어 대상 (5GB 저장, 20,000 GET 요청)

✅ S3 설정 완료

S3 버킷이 생성되면 애플리케이션에서 파일을 업로드하고 다운로드할 수 있습니다!

6. EC2에 Docker 설치 및 배포

💡 Docker란?

컨테이너 기술을 사용하여 애플리케이션을 패키징하고 배포하는 도구입니다. Java, Spring Boot 애플리케이션을 쉽게 배포할 수 있습니다.

배포 단계

1
EC2 접속

SSH를 통해 EC2 인스턴스에 접속

2
Docker 설치

Docker와 Docker Compose 설치

3
애플리케이션 배포

Spring Boot 애플리케이션을 Docker로 배포

1단계: EC2 접속

# EC2 인스턴스 접속
ssh -i jpa-keypair.pem ubuntu@EC2_PUBLIC_IP

# 패키지 업데이트
sudo apt update && sudo apt upgrade -y

# Java 17 설치
sudo apt install openjdk-17-jdk -y

# Java 버전 확인
java -version

2단계: Docker 설치

# Docker 설치
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# Docker 서비스 시작 및 자동 시작 설정
sudo systemctl start docker
sudo systemctl enable docker

# 현재 사용자를 docker 그룹에 추가
sudo usermod -aG docker ubuntu

# 권한 적용 (로그아웃 후 재로그인 또는)
newgrp docker

# Docker Compose 설치
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# Docker 권한 확인
docker --version
docker ps
docker-compose --version

3단계: 애플리케이션 배포

# 애플리케이션 디렉토리 생성
mkdir -p /home/ubuntu/jpa-app
cd /home/ubuntu/jpa-app

# 프로젝트 파일 업로드 (로컬에서)
# scp -i jpa-keypair.pem -r ./jpa-project ubuntu@EC2_PUBLIC_IP:/home/ubuntu/jpa-app/

# 또는 Git에서 클론
git clone https://github.com/your-username/jpa-project.git .

도메인 연결 및 SSL 인증서

도메인을 연결하고 SSL 인증서를 설정합니다.

Route 53 호스팅 존 생성

# 호스팅 존 생성
aws route53 create-hosted-zone \
    --name yourdomain.com \
    --caller-reference $(date +%s)

# A 레코드 생성 (EC2 IP 연결)
aws route53 change-resource-record-sets \
    --hosted-zone-id Z1234567890 \
    --change-batch file://dns-record.json

Let's Encrypt SSL 인증서

# Certbot 설치
sudo apt install certbot python3-certbot-nginx

# SSL 인증서 발급
sudo certbot --nginx -d yourdomain.com

# 자동 갱신 설정
sudo crontab -e
# 0 12 * * * /usr/bin/certbot renew --quiet

CloudWatch 설정

애플리케이션 모니터링을 위한 CloudWatch를 설정합니다.

# CloudWatch 에이전트 설치
wget https://s3.amazonaws.com/amazoncloudwatch-agent/ubuntu/amd64/latest/amazon-cloudwatch-agent.deb
sudo dpkg -i amazon-cloudwatch-agent.deb

# CloudWatch 설정 파일 생성
cat > cloudwatch-config.json << EOF
{
    "metrics": {
        "namespace": "JPA/Application",
        "metrics_collected": {
            "cpu": {
                "measurement": ["cpu_usage_idle", "cpu_usage_iowait"],
                "metrics_collection_interval": 60
            },
            "disk": {
                "measurement": ["used_percent"],
                "metrics_collection_interval": 60,
                "resources": ["*"]
            },
            "mem": {
                "measurement": ["mem_used_percent"],
                "metrics_collection_interval": 60
            }
        }
    },
    "logs": {
        "logs_collected": {
            "files": {
                "collect_list": [
                    {
                        "file_path": "/var/log/nginx/access.log",
                        "log_group_name": "jpa-nginx-access",
                        "log_stream_name": "{instance_id}"
                    },
                    {
                        "file_path": "/home/ubuntu/jpa-app/app.log",
                        "log_group_name": "jpa-application",
                        "log_stream_name": "{instance_id}"
                    }
                ]
            }
        }
    }
}
EOF

# CloudWatch 에이전트 시작
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
    -a fetch-config -m ec2 -c file:cloudwatch-config.json -s
