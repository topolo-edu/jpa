학습 목표

GitHub Actions를 사용하여 자동 배포 파이프라인을 구축하여 코드 커밋 시 자동으로 AWS에 배포하는 CI/CD 환경을 구축합니다.

  • • GitHub Actions 워크플로우 작성
  • • 코드 커밋 시 자동 배포
  • • Docker 이미지 빌드 및 푸시
  • • AWS EC2 자동 배포

1. GitHub Actions 기본 개념

1

GitHub Actions란?

GitHub에서 제공하는 CI/CD 플랫폼으로, 코드 저장소와 연동하여 자동화된 워크플로우를 실행합니다.

주요 구성 요소

  • • Workflow: 자동화된 프로세스
  • • Job: 워크플로우의 단계
  • • Step: 작업의 개별 단계
  • • Action: 재사용 가능한 작업

트리거 이벤트

  • • Push: 코드 푸시 시
  • • Pull Request: PR 생성/업데이트 시
  • • Schedule: 정기적 실행
  • • Manual: 수동 실행

2. GitHub 저장소 설정

2

GitHub 저장소 생성 및 설정

프로젝트를 GitHub에 업로드하고 CI/CD를 위한 설정을 합니다.

GitHub 저장소 생성

# 로컬에서 Git 초기화
git init

# 원격 저장소 추가
git remote add origin https://github.com/your-username/jpa-project.git

# 파일 추가 및 커밋
git add .
git commit -m "Initial commit"

# 메인 브랜치로 푸시
git branch -M main
git push -u origin main

GitHub Secrets 설정

GitHub 저장소 → Settings → Secrets and variables → Actions에서 다음 시크릿을 추가합니다:

  • • AWS_ACCESS_KEY_ID: AWS 액세스 키
  • • AWS_SECRET_ACCESS_KEY: AWS 시크릿 키
  • • EC2_HOST: EC2 인스턴스 IP
  • • EC2_USER: EC2 사용자명 (ubuntu)
  • • EC2_SSH_KEY: EC2 SSH 개인키

3. 기본 워크플로우 작성

3

GitHub Actions 워크플로우 파일

main 브랜치에 푸시될 때마다 자동으로 배포하는 워크플로우를 작성합니다.

# .github/workflows/deploy.yml
name: Deploy to AWS

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      
    - name: Set up JDK 11
      uses: actions/setup-java@v3
      with:
        java-version: '11'
        distribution: 'temurin'
        
    - name: Cache Maven dependencies
      uses: actions/cache@v3
      with:
        path: ~/.m2
        key: ${{ runner.os }}-m2-${{ hashFiles('**/pom.xml') }}
        restore-keys: ${{ runner.os }}-m2
        
    - name: Build with Maven
      run: mvn clean package -DskipTests
      
    - name: Build Docker image
      run: docker build -t jpa-app:${{ github.sha }} .
      
    - name: Deploy to EC2
      uses: appleboy/ssh-action@v0.1.5
      with:
        host: ${{ secrets.EC2_HOST }}
        username: ${{ secrets.EC2_USER }}
        key: ${{ secrets.EC2_SSH_KEY }}
        script: |
          cd /home/ubuntu/jpa-app
          git pull origin main
          docker compose down
          docker compose up --build -d

4. Docker Registry 연동

4

Docker Hub 연동

Docker 이미지를 Docker Hub에 푸시하여 EC2에서 사용할 수 있도록 합니다.

Docker Hub Secrets 추가

GitHub Secrets에 다음을 추가합니다:

  • • DOCKER_USERNAME: Docker Hub 사용자명
  • • DOCKER_PASSWORD: Docker Hub 비밀번호

업데이트된 워크플로우

# .github/workflows/deploy.yml (Docker Hub 포함)
name: Deploy to AWS

on:
  push:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      
    - name: Set up JDK 11
      uses: actions/setup-java@v3
      with:
        java-version: '11'
        distribution: 'temurin'
        
    - name: Cache Maven dependencies
      uses: actions/cache@v3
      with:
        path: ~/.m2
        key: ${{ runner.os }}-m2-${{ hashFiles('**/pom.xml') }}
        restore-keys: ${{ runner.os }}-m2
        
    - name: Build with Maven
      run: mvn clean package -DskipTests
      
    - name: Login to Docker Hub
      uses: docker/login-action@v2
      with:
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_PASSWORD }}
        
    - name: Build and push Docker image
      run: |
        docker build -t ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }} .
        docker push ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }}
        docker tag ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }} ${{ secrets.DOCKER_USERNAME }}/jpa-app:latest
        docker push ${{ secrets.DOCKER_USERNAME }}/jpa-app:latest
        
    - name: Deploy to EC2
      uses: appleboy/ssh-action@v0.1.5
      with:
        host: ${{ secrets.EC2_HOST }}
        username: ${{ secrets.EC2_USER }}
        key: ${{ secrets.EC2_SSH_KEY }}
        script: |
          cd /home/ubuntu/jpa-app
          git pull origin main
          docker compose pull
          docker compose up -d

5. 고급 워크플로우 기능

5

테스트 및 배포 단계 분리

테스트와 배포를 분리하여 안정성을 높입니다.

# .github/workflows/ci-cd.yml
name: CI/CD Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      
    - name: Set up JDK 11
      uses: actions/setup-java@v3
      with:
        java-version: '11'
        distribution: 'temurin'
        
    - name: Cache Maven dependencies
      uses: actions/cache@v3
      with:
        path: ~/.m2
        key: ${{ runner.os }}-m2-${{ hashFiles('**/pom.xml') }}
        restore-keys: ${{ runner.os }}-m2
        
    - name: Run tests
      run: mvn test
      
    - name: Generate test report
      uses: dorny/test-reporter@v1
      if: success() || failure()
      with:
        name: Maven Tests
        path: target/surefire-reports/*.xml
        reporter: java-junit

  build:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      
    - name: Set up JDK 11
      uses: actions/setup-java@v3
      with:
        java-version: '11'
        distribution: 'temurin'
        
    - name: Build with Maven
      run: mvn clean package -DskipTests
      
    - name: Login to Docker Hub
      uses: docker/login-action@v2
      with:
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_PASSWORD }}
        
    - name: Build and push Docker image
      run: |
        docker build -t ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }} .
        docker push ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }}
        docker tag ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.sha }} ${{ secrets.DOCKER_USERNAME }}/jpa-app:latest
        docker push ${{ secrets.DOCKER_USERNAME }}/jpa-app:latest

  deploy:
    needs: build
    runs-on: ubuntu-latest
    
    steps:
    - name: Deploy to EC2
      uses: appleboy/ssh-action@v0.1.5
      with:
        host: ${{ secrets.EC2_HOST }}
        username: ${{ secrets.EC2_USER }}
        key: ${{ secrets.EC2_SSH_KEY }}
        script: |
          cd /home/ubuntu/jpa-app
          git pull origin main
          docker compose pull
          docker compose up -d
          
    - name: Health check
      run: |
        sleep 30
        curl -f http://${{ secrets.EC2_HOST }}/actuator/health || exit 1

6. 환경별 배포

6

개발/운영 환경 분리

브랜치별로 다른 환경에 배포하도록 설정합니다.

# .github/workflows/environment-deploy.yml
name: Environment Deploy

on:
  push:
    branches: [ main, develop ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
      
    - name: Set environment variables
      run: |
        if [ "${{ github.ref }}" == "refs/heads/main" ]; then
          echo "ENVIRONMENT=production" >> $GITHUB_ENV
          echo "EC2_HOST=${{ secrets.PROD_EC2_HOST }}" >> $GITHUB_ENV
          echo "EC2_USER=${{ secrets.PROD_EC2_USER }}" >> $GITHUB_ENV
          echo "EC2_SSH_KEY=${{ secrets.PROD_EC2_SSH_KEY }}" >> $GITHUB_ENV
        else
          echo "ENVIRONMENT=development" >> $GITHUB_ENV
          echo "EC2_HOST=${{ secrets.DEV_EC2_HOST }}" >> $GITHUB_ENV
          echo "EC2_USER=${{ secrets.DEV_EC2_USER }}" >> $GITHUB_ENV
          echo "EC2_SSH_KEY=${{ secrets.DEV_EC2_SSH_KEY }}" >> $GITHUB_ENV
        fi
        
    - name: Deploy to ${{ env.ENVIRONMENT }}
      uses: appleboy/ssh-action@v0.1.5
      with:
        host: ${{ env.EC2_HOST }}
        username: ${{ env.EC2_USER }}
        key: ${{ env.EC2_SSH_KEY }}
        script: |
          cd /home/ubuntu/jpa-app
          git pull origin ${{ github.ref_name }}
          docker compose -f docker-compose.${{ env.ENVIRONMENT }}.yml up -d

7. 알림 및 모니터링

7

배포 상태 알림

배포 성공/실패 시 알림을 받을 수 있도록 설정합니다.

# .github/workflows/notify.yml
name: Notify Deployment

on:
  workflow_run:
    workflows: ["Deploy to AWS"]
    types: [completed]

jobs:
  notify:
    runs-on: ubuntu-latest
    if: always()
    
    steps:
    - name: Notify Success
      if: ${{ github.event.workflow_run.conclusion == 'success' }}
      uses: 8398a7/action-slack@v3
      with:
        status: success
        text: 'Deployment to AWS completed successfully! 🎉'
      env:
        SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
        
    - name: Notify Failure
      if: ${{ github.event.workflow_run.conclusion == 'failure' }}
      uses: 8398a7/action-slack@v3
      with:
        status: failure
        text: 'Deployment to AWS failed! ❌'
      env:
        SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

8. 롤백 전략

8

자동 롤백 설정

배포 실패 시 이전 버전으로 자동 롤백하는 전략을 설정합니다.

# .github/workflows/rollback.yml
name: Rollback

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version to rollback to'
        required: true
        default: 'latest'

jobs:
  rollback:
    runs-on: ubuntu-latest
    
    steps:
    - name: Rollback to version ${{ github.event.inputs.version }}
      uses: appleboy/ssh-action@v0.1.5
      with:
        host: ${{ secrets.EC2_HOST }}
        username: ${{ secrets.EC2_USER }}
        key: ${{ secrets.EC2_SSH_KEY }}
        script: |
          cd /home/ubuntu/jpa-app
          
          # 이전 버전으로 롤백
          docker compose down
          docker pull ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.event.inputs.version }}
          docker tag ${{ secrets.DOCKER_USERNAME }}/jpa-app:${{ github.event.inputs.version }} jpa-app:latest
          docker compose up -d
          
          # 헬스 체크
          sleep 30
          curl -f http://localhost/actuator/health || exit 1
