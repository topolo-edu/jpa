비즈니스 메서드와 편의 메서드의 이해

MyBatis → JPA 전환 과정에서 나타나는 메서드 설계 패턴

📊 비즈니스 모델: Course ↔ Curriculum

┌─────────────────┐    1:N    ┌─────────────────┐
│     Course      │◄─────────►│   Curriculum    │
├─────────────────┤           ├─────────────────┤
│ courseNo (PK)   │           │ curriculumNo(PK)│
│ name            │           │ weekNumber      │
│ description     │           │ title           │
│ maxStudents     │           │ description     │
│ currentStudents │           │ materials       │
│ instructorNo(FK)│           │ duration        │
└─────────────────┘           │ courseNo(FK)   │
                               └─────────────────┘

1단계: MyBatis 모델 (데이터 그릇)

특징: SQL 결과를 담기 위한 단순한 데이터 구조

JOIN 쿼리 예제:

2단계: 객체스러운 엔티티 (도메인 주체)

변화: 단순 데이터 그릇 → 의미 있는 행위를 가진 도메인 객체

📌 비즈니스 메서드란?

  • 정의: 도메인 객체가 스스로 처리하는 "의미 있는 행위"
  • 목적: 도메인 규칙/정책/제약사항을 객체 내부에 캡슐화
  • 특징: 단순 필드 변경이 아닌 로직 내장 (검증, 상태 전이 등)
  • 예시: isAvailable(), increaseCurrentStudents(), isFirstWeek()

서비스 단에서의 사용 차이:

❌ 비즈니스 메서드 없을 때:

// 서비스에서 직접 검증
if (course.getCurrentStudents() >= course.getMaxStudents()) {
    throw new IllegalStateException("정원 초과");
}
course.setCurrentStudents(course.getCurrentStudents() + 1);

✅ 비즈니스 메서드 있을 때:

// 객체가 스스로 검증
if (course.isAvailable()) {
    course.increaseCurrentStudents();
}

Course 클래스

@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Course {
    private Long courseNo;
    private String name;
    private String description;
    private Integer maxStudents;
    private Integer currentStudents;
    private User instructor;
    
    // 비즈니스 메서드 도입
    public void increaseCurrentStudents() {
        this.currentStudents++;
    }
    
    public void decreaseCurrentStudents() {
        if (this.currentStudents > 0) {
            this.currentStudents--;
        }
    }
    
    public boolean isAvailable() {
        return this.currentStudents < this.maxStudents;
    }
    
    public boolean isInstructor(User user) {
        return this.instructor.equals(user);
    }
}

3단계: JPA 엔티티 (ORM 매핑 추가) - 기본 단방향

특징: 연관관계는 한쪽에서만 관리, 동기화 대상 없음

📌 용어 정리: JPA 엔티티

  • 정의: JPA 어노테이션이 붙은 도메인 객체
  • 역할: DB 매핑 + 도메인 행위 모두 담당
  • 핵심: 비즈니스 메서드는 JPA와 무관하게 존재
  • 예시: @Entity, @Id, @Column

Course 클래스 (관계의 주인 아님)

@Entity
@Getter
@ToString(exclude = {"instructor", "curriculums"})
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Table(name = "course")
public class Course extends BaseEntity {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long courseNo;
    
    @Column(nullable = false, length = 200)
    private String name;
    
    @Column(length = 2000)
    private String description;
    
    @Column(nullable = false)
    private Integer maxStudents;
    
    @Column(nullable = false)
    private Integer currentStudents = 0;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "instructor_no", nullable = false)
    private User instructor;
    
    // 비즈니스 메서드는 그대로 유지
    public void increaseCurrentStudents() {
        this.currentStudents++;
    }
    
    public boolean isAvailable() {
        return this.currentStudents < this.maxStudents;
    }
}

Curriculum 클래스 (관계의 주인)

@Entity
@Getter
@ToString(exclude = "course")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Table(name = "curriculum")
public class Curriculum extends BaseEntity {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long curriculumNo;
    
    @Column(nullable = false)
    private Integer weekNumber;
    
    @Column(nullable = false, length = 200)
    private String title;
    
    @Column(length = 1000)
    private String description;
    
    @Column(length = 500)
    private String materials;
    
    @Column
    private Integer duration;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "course_no", nullable = false)
    private Course course;  // 관계의 주인이므로 연관관계 설정 가능
    
    // 비즈니스 메서드는 그대로 유지
    public void update(String title, String description, String materials, Integer duration) {
        this.title = title;
        this.description = description;
        this.materials = materials;
        this.duration = duration;
    }
    
    public boolean isFirstWeek() {
        return this.weekNumber == 1;
    }
}

사용 방식: @Entity, @ManyToOne, @JoinColumn 등 ORM 매핑 정보 추가

📌 단방향 관계에서의 CUD 처리 방식

💡 핵심 원칙

• 연관관계 주인(Curriculum)에서만 연관 설정 가능
• 각 엔티티는 개별적으로 생성, 저장, 삭제
• 연관된 객체 저장 시: 주인이 아닌 쪽(Course) 먼저 저장 → 주인(Curriculum)에서 참조 설정

✅ Create (생성)
// 1. Course 먼저 저장
Course course = new Course();
course.setName("JPA 기초");
courseRepository.save(course);

// 2. Curriculum에서 참조 설정
Curriculum curriculum = new Curriculum();
curriculum.setTitle("1주차");
curriculum.setCourse(course); // FK 설정
curriculumRepository.save(curriculum);
✏️ Update (수정)
// 연관관계만 변경
Curriculum curriculum = curriculumRepository.findById(1L);
Course newCourse = courseRepository.findById(2L);

curriculum.setCourse(newCourse); // FK 변경
curriculumRepository.save(curriculum);
❌ Delete (삭제)
// FK 참조 해제 후 삭제
List<Curriculum> curriculums = 
    curriculumRepository.findByCourse(course);
for (Curriculum c : curriculums) {
    c.setCourse(null);
}
curriculumRepository.saveAll(curriculums);

courseRepository.delete(course);

💡 기억하세요: 단방향에서는 연관 대상 엔티티를 먼저 저장하고, 주인 쪽에서 명시적으로 관계를 설정한 후 저장해야 합니다.

양방향의 목적 및 기능

핵심: 양방향 관계는 "탐색", "동기화", "Cascade" 세 가지 기능을 제공

📌 양방향 관계의 세 가지 기능

1. 탐색 (Navigation)

  • • Course → Curriculum: course.getCurriculum()
  • • Curriculum → Course: curriculum.getCourses()
  • • 양방향으로 객체 탐색 가능

2. 동기화 (편의 메서드)

  • • 양쪽 객체 상태 일관성 유지
  • • 편의 메서드로 자동 동기화
  • • 상태 불일치 방지

3. Cascade (생명주기 관리)

  • • 연관 엔티티 함께 저장/삭제
  • • cascade = CascadeType.ALL
  • • 한 번에 여러 엔티티 처리

⚠️ 양방향 설정 시 주의사항

1. 단방향으로도 탐색 가능:

// Course → User (단방향)
Course course = courseRepository.findById(1L);
User instructor = course.getInstructor(); // ✅ 가능

// User → Course (단방향)  
List<Course> courses = courseRepository.findByInstructor(user); // ✅ 가능

2. 양방향 + 편의 메서드 없음 = 의미 없음:

// 양방향 설정했지만 편의 메서드 없음
course.setInstructor(user);
// user.getCourses()에는 course가 포함되지 않음! ❌

// 탐색은 가능하지만
user.getCourses(); // 빈 리스트 반환 (실제로는 course가 있어야 함)

💡 핵심 정리:

  • • 단방향: 탐색은 가능하지만 한 방향으로만
  • • 양방향 + 편의 메서드 없음: 탐색은 되지만 정합성 보장 안됨 (의미 없음)
  • • 양방향 + 편의 메서드: 탐색도 되고 정합성도 보장됨 (완벽)

📌 용어 정의: Aggregate

Aggregate (집합): 여러 엔티티들이 하나의 논리적 단위로 묶인 것

구성: Aggregate Root + 내부 엔티티들

예시 1: Course Aggregate

  • Aggregate Root: Course (엔티티)
  • 내부 엔티티: Curriculum (엔티티)
  • 결합도: 강한 결합 (Curriculum은 Course 없이는 의미 없음)

예시 2: Course ↔ User (Aggregate 간 관계)

  • Aggregate Root: User (엔티티) - 내부 엔티티: 없음
  • 결합도: 느슨한 결합 (서로 독립적)

Aggregate와 양방향 관계의 목적

📌 Aggregate 내부 관계 (관리 편의성)

  • 예시: Course ↔ Curriculum, Order ↔ OrderItem
  • 목적: Aggregate Root가 하위 객체의 생명주기를 완전히 책임
  • 특징: 양방향 필수 + Cascade 권장 + 편의 메서드 필수
  • 코드: course.addCurriculum(), course.removeCurriculum()

📌 Aggregate 간 관계 (탐색 편의성)

  • 예시: Course ↔ User, Product ↔ Category
  • 목적: 탐색(조회) 편의성, 생명주기 독립
  • 특징: 필요시에만 양방향 + Cascade 비권장
  • 코드: course.getInstructor(), user.getCourses()

📊 양방향 관계 기준 정리

구분 예시 목적 양방향 Cascade
Aggregate 내부 Course ↔ Curriculum 관리 편의성 ✅ 필수 ✅ 권장
Aggregate 간 Course ↔ User 탐색 편의성 ❓ 필요시 ❌ 비권장

⚠️ 양방향 설정 시 주의사항

1. 단방향으로도 탐색 가능:

// Course → User (단방향)
Course course = courseRepository.findById(1L);
User instructor = course.getInstructor(); // ✅ 가능

// User → Course (단방향)  
List<Course> courses = courseRepository.findByInstructor(user); // ✅ 가능

2. 양방향 + 편의 메서드 없음 = 의미 없음:

// 양방향 설정했지만 편의 메서드 없음
course.setInstructor(user);
// user.getCourses()에는 course가 포함되지 않음! ❌

// 탐색은 가능하지만
user.getCourses(); // 빈 리스트 반환 (실제로는 course가 있어야 함)

💡 핵심 정리:

  • • 단방향: 탐색은 가능하지만 한 방향으로만
  • • 양방향 + 편의 메서드 없음: 탐색은 되지만 정합성 보장 안됨 (의미 없음)
  • • 양방향 + 편의 메서드: 탐색도 되고 정합성도 보장됨 (완벽)

4단계: 양방향 관계 (편의 메서드 필수)

문제: 양쪽 객체가 동기화되지 않으면 상태 불일치 발생

📌 용어 정리: 편의 메서드

  • 정의: 양방향 연관관계의 양쪽 객체를 일관되게 동기화하는 메서드
  • 목적: 객체 상태와 DB 상태의 일관성 유지
  • 필요성: 양방향 관계에서만 필요 (단방향에서는 불필요)
  • 예시: addMember(), setParent()

Course (관계의 주인 아님)

@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Course {
    @Id
    private Long courseId;
    
    @OneToMany(
        mappedBy = "course",
        cascade = CascadeType.ALL,
        orphanRemoval = true
    )
    private List<Curriculum> curriculums = new ArrayList<>();
    
    // 편의 메서드 (중복/재연결 방지)
    public void addCurriculum(Curriculum curriculum) {
        if (curriculum == null) return;
        if (!this.curriculums.contains(curriculum)) {
            this.curriculums.add(curriculum);
        }
        if (curriculum.getCourse() != this) {
            curriculum.assignToCourse(this);
        }
    }
    
    public void removeCurriculum(Curriculum curriculum) {
        if (curriculum == null) return;
        if (this.curriculums.remove(curriculum)) {
            if (curriculum.getCourse() == this) {
                curriculum.clearCourse();
            }
        }
    }
}

Curriculum (관계의 주인)

@Entity
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Curriculum {
    @Id
    private Long curriculumId;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "course_id", nullable = false)
    private Course course;
    
    // 관계 설정 편의 메서드 (재연결/순환 방지)
    public void assignToCourse(Course newCourse) {
        if (newCourse == null) return;
        if (this.course == newCourse) return;
        if (this.course != null) {
            this.course.getCurriculums().remove(this);
        }
        this.course = newCourse;
        if (!newCourse.getCurriculums().contains(this)) {
            newCourse.getCurriculums().add(this);
        }
    }
    
    // 역관계 해제 편의 메서드
    public void clearCourse() {
        if (this.course == null) return;
        Course old = this.course;
        this.course = null;
        old.getCurriculums().remove(this);
    }
}

❌ 편의 메서드 없이 사용하면:

// 문제가 되는 코드
curriculum.setCourse(course);
// course.getCurriculums()에는 curriculum이 포함되지 않음!

편의 메서드의 핵심:

❌ set을 직접 사용하면:

curriculum.setCourse(course);
// 한쪽만 설정 → 상태 불일치!

✅ add 메서드를 사용하면:

curriculum.assignToCourse(course);
// 내부적으로 양쪽 모두 설정하는 로직 실행
// → 상태 일치!

💡 핵심: 편의 메서드는 JPA가 자동으로 해주는 게 아니라, 개발자가 직접 만든 동기화 로직입니다!

🔍 양방향 관계 사용 예시

1. 관계 설정 (편의 메서드 사용):

// 새로운 Curriculum을 Course에 추가할 때
Course course = courseRepository.findById(1L);
Curriculum newCurriculum = new Curriculum("2주차", "JPA 기초", ...);

// 편의 메서드로 양방향 관계 설정
curriculum.assignToCourse(course);  // 편의 메서드 호출
// 또는
course.addCurriculum(newCurriculum);  // 편의 메서드 호출

curriculumRepository.save(newCurriculum);

2. 탐색 (getter 메서드 사용):

// Course → Curriculum 탐색
Course course = courseRepository.findById(1L);
List<Curriculum> curriculums = course.getCurriculums();  // getter 메서드

for (Curriculum curriculum : curriculums) {
    System.out.println("주차: " + curriculum.getWeekNumber());
    System.out.println("제목: " + curriculum.getTitle());
}

// Curriculum → Course 탐색
Curriculum curriculum = curriculumRepository.findById(1L);
Course course = curriculum.getCourse();  // getter 메서드

System.out.println("강의명: " + course.getName());
System.out.println("강사: " + course.getInstructor().getFullName());

💡 구분: 편의 메서드는 관계를 설정할 때, getter 메서드는 탐색할 때 사용합니다!

5단계: 관계 정리 및 혼합 예시

📌 용어 정리: 비즈니스 메서드 vs 편의 메서드

구분 비즈니스 메서드 편의 메서드
목적 도메인 의미 처리 연관관계 동기화
필요성 도메인 복잡도에 따라 선택적 양방향에서 필수
포함 관계 편의 메서드를 내부에서 호출 가능 비즈니스 로직은 없음
예시 cancel(), approve() addMember(), setParent()

혼합 예시: 비즈니스 메서드 + 편의 메서드

@Entity
public class Course {
    @ManyToOne
    @JoinColumn(name = "curriculum_id")
    private Curriculum curriculum;
    
    // 비즈니스 메서드 (도메인 로직 포함)
    public void activateInCurriculum(Curriculum curriculum) {
        if (this.status != Status.PENDING) {
            throw new IllegalStateException("대기 상태가 아닌 강의는 활성화 불가");
        }
        
        // 편의 메서드 호출 (관계 동기화)
        this.assignToCurriculum(curriculum);
        
        // 비즈니스 로직 계속
        this.status = Status.ACTIVE;
        this.activatedAt = LocalDateTime.now();
    }
    
    // 편의 메서드 (관계 동기화만)
    private void assignToCurriculum(Curriculum curriculum) {
        this.curriculum = curriculum;
        curriculum.getCourses().add(this);
    }
}
