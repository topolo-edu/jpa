1:N 가이드

@OneToMany의 올바른 N:M 관계에서의 사용 방법

🚨 핵심 원칙

"단독 `1:N` 단방향은 쓰지 말고, N:M 관계는 `1:N + N:1`로 구성하는 것이 가장 안전하고 권장된다."

✅ N:M 관계의 올바른 해결 방법

🎯 핵심: N:M을 1:N + N:1로 구성

N:M 관계는 중간 엔티티를 만들어서 1:N + N:1 구조로 풀어야 합니다. 이렇게 하면 각 엔티티의 책임이 명확해지고, 추가 정보도 저장할 수 있습니다.

📚 우리 프로젝트 예시: 수강신청 시스템

User.java

@Entity
public class User {
    @Id @GeneratedValue
    private Long userNo;
    
    private String name;
    private String email;
    
    @OneToMany(mappedBy = "user")  // ✅ 1:N 관계
    private List<Enrollment> enrollments;
}

Enrollment.java (중간 엔티티)

@Entity
public class Enrollment {
    @Id @GeneratedValue
    private Long enrollmentNo;
    
    @ManyToOne  // ✅ User와의 N:1 관계
    @JoinColumn(name = "user_no")
    private User user;
    
    @ManyToOne  // ✅ Course와의 N:1 관계  
    @JoinColumn(name = "course_no")
    private Course course;
    
    private EnrollmentStatus status;
    private LocalDateTime enrolledAt;
    private BigDecimal fee;
    
    // 비즈니스 메서드
    public void approve() {
        this.status = EnrollmentStatus.APPROVED;
    }
}

Course.java

@Entity
public class Course {
    @Id @GeneratedValue
    private Long courseNo;
    
    private String name;
    private String description;
    
    @OneToMany(mappedBy = "course")  // ✅ 1:N 관계
    private List<Enrollment> enrollments;
}

결과: User 1:N Enrollment N:1 Course 구조로, 각 엔티티의 책임이 명확하고 추가 정보(신청일시, 승인상태, 수강료)도 저장 가능합니다.

🤔 양방향 관계는 필요한가?

💡 판단 기준

N:M 관계를 1:N + N:1로 구성할 때, 양방향 관계는 강한 결합이 아닌 경우에는 필요하지 않을 수 있습니다. 오히려 복잡성만 증가시킬 수 있습니다.

❌ 양방향이 불필요한 경우:

  • • 단순한 참조 관계
  • • 강한 결합이 아닌 경우
  • • 복잡성만 증가하는 경우
  • • 단방향으로도 충분한 경우
// 단방향으로도 충분
@ManyToOne
private User user;  // Enrollment에서 User 참조

// User에서 Enrollment 목록이 필요하면
List<Enrollment> enrollments = 
    enrollmentRepository.findByUser(user);

✅ 양방향이 필요한 경우:

  • • Aggregate 내부 관계
  • • 강한 결합 관계
  • • 자주 양방향 탐색이 필요한 경우
  • • 생명주기를 함께 관리하는 경우
// 양방향이 필요한 경우
@OneToMany(mappedBy = "course")
private List<Curriculum> curriculums;  // Course와 Curriculum은 강한 결합

📊 최종 정리

❌ 피해야 할 것

  • • 단독 @OneToMany 사용
  • • 불필요한 양방향 관계 설정
  • • 복잡성만 증가시키는 설계

✅ 권장하는 것

  • • 단순 참조는 @ManyToOne 사용
  • • N:M 관계는 중간 엔티티로 1:N + N:1 구성
  • • 필요한 경우에만 양방향 관계 설정

💡 핵심은 단순함과 명확성입니다. 복잡한 양방향 관계보다는 필요한 만큼만 설정하는 것이 좋습니다.
