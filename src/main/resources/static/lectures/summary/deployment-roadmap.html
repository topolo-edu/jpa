STEP 1

로컬 개발

핵심: Spring Boot + JPA 애플리케이션 개발

./gradlew bootRun
✅ Entity 설계
✅ REST API 개발
✅ 테스트 작성
🏗️
STEP 2

빌드 (JAR)

핵심: 실행 가능한 JAR 파일 생성

./gradlew build

변경된 파일만 다시 컴파일
→ 빠름, 개발/테스트용

./gradlew clean build

build/ 폴더 삭제 후 처음부터
→ 확실함, 배포용 권장 ⭐

📦 결과물: build/libs/jpa-0.0.1-SNAPSHOT.jar
☕
STEP 3

JAR 직접 배포

핵심: 서버에 JAR 복사 후 직접 실행

java -jar app.jar
✅ 가장 단순한 방법
⚠️ 서버 환경 직접 설정 필요

🤔 JAR 직접 배포 vs Docker, 뭐가 다를까?

☕

JAR 직접 배포

전통적인 방식

서버에서 해야 할 일:

1️⃣ OS 업데이트
2️⃣ Java 21 설치
3️⃣ JAR 파일 복사
4️⃣ 환경변수 설정
5️⃣ 포트 설정
6️⃣ java -jar app.jar 실행
❌ 서버마다 환경 다름
❌ Java 버전 충돌 가능
❌ 설정 누락 시 오류
✅ 가장 단순한 방법
🐳

Docker 배포

현대적인 방식

Docker가 해주는 일:

✨ OS 환경 (Ubuntu/Alpine)
✨ Java 21 자동 설치
✨ JAR 파일 포함
✨ 환경변수 세팅
✨ 포트 매핑
✨ 실행 명령어 정의
→ 이미지 하나에 모두 패키징!
✅ 어디서나 동일하게 동작
✅ 버전 관리 쉬움 (태그)
✅ 환경 격리 (충돌 없음)
✅ 롤백 간편 (이전 이미지)

💡 핵심 차이

JAR 직접 배포 = "깡통 서버에 수동으로 세팅" / Docker = "완벽히 세팅된 환경을 통째로 복사"

🐳
STEP 4

Docker 컨테이너화

핵심: 환경에 독립적인 컨테이너 이미지 생성

docker build -t jpa-app . docker run -p 8080:8080 jpa-app

📝 Dockerfile이 이미지를 만들 때 하는 일:

FROM 베이스 이미지 선택 (예: openjdk:21-jdk-slim)
WORKDIR 작업 디렉토리 설정 (예: /app)
COPY JAR 파일을 이미지 안으로 복사
ENV 환경변수 설정 (DB 주소, 포트 등)
EXPOSE 사용할 포트 선언 (예: 8080)
CMD 컨테이너 시작 시 실행 명령어 (예: java -jar app.jar)
💡 이 모든 설정이 하나의 이미지 파일로 패키징됩니다!
✅ Dockerfile 한 번 작성
✅ 어디서나 동일하게 실행
🎼
STEP 5

Docker Compose

핵심: 여러 컨테이너를 한번에 관리 (앱 + DB + 웹서버)

docker-compose up -d

🔐 환경변수는 언제 설정되나요? (프로필, DB 비밀번호 등)

❌ Dockerfile (빌드 타임)
ENV KEY=value

기본값만! 비밀번호 절대 금지

✅ docker run
-e DB_PASSWORD=secret

실행 시 주입

⭐ docker-compose
environment:

yml + .env 조합 (실무)

📄 docker-compose.yml 예시:

services:
  app:
    image: jpa-app
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_URL=jdbc:mariadb://db:3306/jpa
      - DB_PASSWORD=\${DB_PASSWORD}  # .env 파일에서 로드
  db:
    image: mariadb
    environment:
      - MARIADB_ROOT_PASSWORD=\${DB_PASSWORD}

💡 비밀번호는 .env 파일에 따로 관리 (Git 제외)

📱 Spring Boot App
🗄️ MariaDB
🌐 Nginx
🔨
STEP 6

CI (Continuous Integration)

핵심: 코드 푸시 시 자동 빌드 및 테스트

1. Git Push → GitHub
2. 자동 빌드 (./gradlew build)
3. 자동 테스트 실행
4. Docker 이미지 빌드 & Push
📄 설정: .github/workflows/ci.yml
🚀
STEP 7

CD (Continuous Deployment)

핵심: 빌드된 이미지를 자동으로 서버에 배포

1. Docker Hub에서 최신 이미지 Pull
2. 서버에 SSH 접속
3. 기존 컨테이너 중지
4. 새 컨테이너 실행
📄 설정: .github/workflows/cd.yml 또는 통합 파일
☁️
STEP 8

AWS 클라우드 배포

핵심: EC2 인스턴스에 배포 (실제 서비스 운영)

1. EC2 인스턴스 생성 (Ubuntu)
2. Docker 설치
3. Docker Compose로 배포
🖥️ EC2 (서버)
🗄️ RDS (데이터베이스)
☸️
STEP 9 (고급)

Kubernetes 오케스트레이션

핵심: 대규모 컨테이너 관리 및 자동 스케일링

kubectl apply -f deployment.yml
🔄 자동 복구
📈 오토 스케일링
🔀 로드 밸런싱

🔧 환경별 설정 관리 (개발/테스트/운영)

💻

개발 환경 (Local)

내 컴퓨터

• H2 인메모리 DB
• 상세한 로그 출력
• 자동 리로드 (DevTools)
• application-dev.properties
🧪

테스트 환경 (Staging)

운영과 동일한 환경

• 실제 DB (복제본)
• 운영 설정 테스트
• QA 진행
• application-test.properties
🚀

운영 환경 (Production)

실제 서비스

• RDS / 운영 DB
• 최소한의 로그
• 성능 최적화
• application-prod.properties

🔐 비밀정보 관리 (DB 비밀번호, API 키 등)

❌ 절대 하면 안 되는 것
✗ application.properties에 하드코딩
✗ Git에 비밀번호 커밋
✗ 코드에 직접 작성
⚠️ 한 번 Git에 올라가면 히스토리에 영구 보존!
✅ 올바른 방법
✓
.env 파일 사용
→ .gitignore에 추가
✓ 환경변수로 주입
✓
AWS Secrets Manager
→ 클라우드 비밀 관리

📋 실무 예시:

📄 application.properties (Git에 올림)

# 플레이스홀더 사용
spring.datasource.url=\${DB_URL}
spring.datasource.password=\${DB_PASSWORD}
jwt.secret=\${JWT_SECRET}

📄 .env (Git에 안 올림 🚫)

# 실제 값 (.gitignore 필수!)
DB_URL=jdbc:mariadb://localhost:3306/jpa
DB_PASSWORD=mySecretPassword123!
JWT_SECRET=super-secret-key-256bits
💡 프로필 전환: -Dspring.profiles.active=prod 또는 SPRING_PROFILES_ACTIVE=prod 환경변수

🔄 환경 전환 흐름

개발 (local)
→
테스트 (staging)
→
운영 (production)

각 환경은 독립된 DB와 별도의 설정 파일을 사용합니다
