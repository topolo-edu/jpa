1️⃣ 시나리오: 수동 배포 (기존 deploy-server)

실제 AWS EC2 배포 전에 로컬에서 수동 배포를 연습해봅시다. 기존에 실행 중인 deploy-server 컨테이너에 우리 앱을 수동으로 배포하는 과정입니다.

🎯 목표

기존 deploy-server 컨테이너에 Docker를 설치하고, 우리 앱 이미지를 전송하여 실행해보기

📋 전제 조건

  • • 기존 컨테이너: deploy-server (Ubuntu 22.04) 실행 중
  • • Java 설치됨: 컨테이너 내부에 Java가 이미 설치되어 있음
  • • JAR 파일: 컨테이너 내부에 JAR 파일이 이미 있음
  • • 네트워크: appnet 네트워크에 연결됨
  • • 포트: 2222 (SSH), 8081 (기존 앱) 사용 중

⚠️ 중요: 컨테이너 권한 설정

컨테이너 내부에서 Docker를 실행하려면 privileged 모드가 필요합니다.

# 기존 컨테이너 중지 및 삭제
docker stop deploy-server
docker rm deploy-server

# privileged 모드로 다시 생성
docker run -d --name deploy-server --network appnet --privileged -p 2222:22 -p 8081:8080 -v deploy-data:/home ubuntu:22.04 sleep infinity

🖥️ 단계 1: 기존 deploy-server 컨테이너 접속

# 컨테이너에 직접 접속 (root 권한)
docker exec -it deploy-server bash

🔧 단계 2: deploy-server에 Docker 설치

# deploy-server 컨테이너 내부에서 실행 (root 권한)
apt update
apt install -y docker.io

# Docker 데몬 시작 (컨테이너 환경)
dockerd &
✅ 확인: Docker가 정상적으로 설치되었는지 확인합니다.

📦 단계 3: 로컬에서 이미지 빌드 (새 터미널)

# 1. JAR 파일 빌드 (소스코드 변경 시에만)
./gradlew build

# 2. Docker 이미지 빌드
docker build -t jpa-app .

# 3. 이미지 확인
docker images jpa-app
💡 설명: 로컬 Docker 데몬에 이미지가 저장됩니다.

📤 단계 4: 이미지 전송 (새 터미널)

# 새 터미널에서 실행 (로컬 호스트에서)
docker save jpa-app | docker exec -i deploy-server docker load
🔄 과정: 로컬 이미지를 파일로 내보내서 deploy-server로 전송합니다.

🚀 단계 5: deploy-server에서 앱 실행 (새 터미널)

⚠️ 중요: 새 터미널에서 실행하세요!

Docker 데몬이 실행 중인 터미널은 그대로 두고, 새 터미널을 열어서 실행하세요.

# deploy-server 컨테이너에 접속
docker exec -it deploy-server bash

# 앱 실행 (외부 8081 → 앱 8082)
docker run -d -p 8081:8082 -e DB_PASSWORD=1234 --name jpa-app-container localhost/jpa-app:latest
✅ 확인:
  • • 새 앱: http://localhost:8081 (외부 접속)
  • • 포트 매핑: 8081 (외부) → 8082 (컨테이너 내부)

2️⃣ 정상적인 Dockerfile 배포 (포트 8082)

이제 정상적인 방식으로 Dockerfile을 사용해서 8082 포트로 배포해봅시다.

🎯 목표

로컬에서 직접 Dockerfile을 사용해서 8082 포트로 앱을 실행하기

📦 단계 1: JAR 파일 빌드

# JAR 파일 빌드
./gradlew build

# 빌드된 JAR 파일 확인
ls -la build/libs/

🐳 단계 2: Docker 이미지 빌드

# Docker 이미지 빌드
docker build -t jpa-app .

# 이미지 확인
docker images jpa-app

🚀 단계 3: 컨테이너 실행

# 컨테이너 실행 (포트 8082)
docker run -p 8082:8082 -e DB_PASSWORD=1234 jpa-app

# 또는 백그라운드 실행
docker run -d -p 8082:8082 -e DB_PASSWORD=1234 --name jpa-container jpa-app
✅ 확인: http://localhost:8082에서 앱이 실행되는지 확인합니다.
📋 프로파일 설정: 현재 prod 프로파일이 활성화되어 MariaDB에 연결됩니다. DB_PASSWORD=1234 환경변수가 필요합니다.

🔍 문제 진단 방법

앱이 실행되지 않을 때 문제를 찾는 방법들입니다.

1️⃣ 컨테이너 상태 확인

# 실행 중인 컨테이너 확인
docker ps

# 모든 컨테이너 확인 (중지된 것 포함)
docker ps -a

# 컨테이너 상세 정보
docker inspect jpa-container

2️⃣ 로그 확인

# 컨테이너 로그 확인
docker logs jpa-container

# 실시간 로그 확인
docker logs -f jpa-container

# 마지막 50줄 로그 확인
docker logs --tail 50 jpa-container

3️⃣ 포트 확인

# 포트 사용 확인
netstat -tulpn | grep 8082

# 또는 Windows에서
netstat -an | findstr 8082

# Docker 포트 매핑 확인
docker port jpa-container

4️⃣ 컨테이너 내부 확인

# 컨테이너 내부 접속
docker exec -it jpa-container bash

# 컨테이너 내부에서 프로세스 확인
docker exec jpa-container ps aux

# 컨테이너 내부에서 포트 확인
docker exec jpa-container netstat -tulpn

5️⃣ 일반적인 문제들

  • • 포트 충돌: 8082 포트가 이미 사용 중
  • • 이미지 문제: JAR 파일이 없거나 잘못된 경로
  • • Java 실행 오류: Java 버전 불일치 또는 메모리 부족
  • • 데이터베이스 연결: MariaDB 컨테이너가 실행되지 않음
  • • 환경변수: DB_PASSWORD 환경변수가 설정되지 않음
  • • 네트워크 문제: 방화벽이나 Docker 네트워크 설정

🔧 단계 4: 컨테이너 관리

# 실행 중인 컨테이너 확인
docker ps

# 컨테이너 로그 확인
docker logs jpa-container

# 컨테이너 중지
docker stop jpa-container

# 컨테이너 삭제
docker rm jpa-container

# 이미지 삭제
docker rmi jpa-app

🔧 Podman 사용자 참고사항

Podman을 사용하는 경우, Docker와 tar 형식 호환성 문제가 발생할 수 있습니다. 다음 방법을 사용하여 이미지를 전송하세요: 

# Docker 호환 형식으로 저장
podman save jpa-app --format docker-archive > jpa-app-docker.tar

# 컨테이너로 복사
podman cp jpa-app-docker.tar deploy-server:/tmp/

# 컨테이너 내부에서 로드
podman exec -it deploy-server bash
docker load < /tmp/jpa-app-docker.tar
💡 팁: --format docker-archive 옵션을 사용하면 Docker와 호환되는 tar 파일이 생성됩니다.
