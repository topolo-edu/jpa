개요 네트워크 개론

학습 목표

단일 서버부터 멀티 서버, 클라우드까지 네트워크 아키텍처의 진화 과정을 이해하고, 각 구성 요소의 역할과 실제 사용되는 기술들을 파악합니다.

구성 요소 역할

WEB

  • • 역할: 정적 파일 서빙, 리버스 프록시
  • • 기능: SSL 종료, 로드 밸런싱
  • • 포트: 80 (HTTP), 443 (HTTPS)
  • • 실제 사용: Apache, Nginx, IIS

WAS (Web Application Server)

  • • 역할: 비즈니스 로직 처리, API 제공
  • • 기능: 세션 관리, 트랜잭션 처리
  • • 포트: 8080
  • • 실제 사용: Tomcat, Spring Boot, Node.js

데이터베이스

  • • 역할: 데이터 영속성, ACID 보장
  • • 기능: 쿼리 처리, 인덱싱, 백업
  • • 포트: 3306 (MySQL/MariaDB)
  • • 실제 사용: MySQL, PostgreSQL, Oracle

파일 저장소

  • • 역할: 파일 업로드/다운로드
  • • 기능: 객체 저장, CDN 연동
  • • 포트: 9000 (MinIO), 443 (S3)
  • • 실제 사용: 파일시스템, MinIO, AWS S3, Google Cloud Storage

리버스 프록시 (Reverse Proxy)

리버스 프록시란?

역할

  • • 클라이언트 대신 서버에 요청 전달
  • • 응답을 받아서 클라이언트에게 전달
  • • 중간자 역할로 보안과 성능 향상
  • • 로드 밸런싱으로 여러 서버에 분산(멀티 WAS 구조)

장점

  • • 보안: 내부 서버 구조 숨김
  • • 성능: 정적 파일 캐싱, 압축
  • • 확장성: 서버 추가/제거 용이
  • • SSL 종료: 인증서 관리 중앙화

하드웨어 로드 밸런서 도입 시

하드웨어 로드밸런서를 도입하면,
클라이언트 요청은 로드밸런서가 직접 WAS 클러스터에 접근하여 리버스 프록시 및 트래픽 분산 역할을 수행하고,
웹서버는 정적 파일 제공 역할만 담당한다.
또한 정적 파일 요청 역시 로드밸런서가 웹서버에 직접 전달한다.

확장된 구성 요소

로드 밸런서 (Load Balancer)

  • • 역할: 트래픽 분산, 서버 상태 모니터링
  • • 실제 사용: HAProxy, F5, AWS ALB
  • • 장점: 가용성 향상, 성능 향상

세션 저장소 (Redis)

  • • 역할: 세션 데이터 중앙 저장
  • • 문제해결: 멀티 서버 간 세션 동기화
  • • 실제 사용: Redis, Memcached, Hazelcast
  • • 장점: 서버 무상태(Stateless) 구현

데이터베이스 클러스터

  • • Master-Slave: 읽기/쓰기 분리
  • • Master-Master: 양방향 복제
  • • 실제 사용: MySQL Cluster, MongoDB Replica Set
  • • 장점: 데이터 안정성, 읽기 성능 향상

로드 밸런서 구현 방식

소프트웨어 (Nginx)

  • • 구현: nginx.conf 설정 파일
  • • 비용: 무료 (오픈소스)
  • • 성능: 중간 (CPU 사용)
  • • 사용처: 스타트업, 중소기업
  • • 설정: upstream 블록으로 서버 목록 정의

하드웨어 (F5, A10)

  • • 구현: 전용 네트워크 장비
  • • 비용: 높음 (수천만원)
  • • 성능: 매우 높음 (ASIC 칩)
  • • 사용처: 대기업, 금융권
  • • 특징: SSL 가속, DDoS 방어

클라우드 (AWS ALB)

  • • 구현: AWS 관리형 서비스
  • • 비용: 사용량 기반 (시간당)
  • • 성능: 높음 (AWS 인프라)
  • • 사용처: 클라우드 기반 서비스
  • • 특징: 자동 스케일링, SSL 인증서 관리

로드 밸런서 알고리즘

Round Robin (라운드 로빈)

  • • 방식: 서버를 순서대로 번갈아가며 선택
  • • 예시: 서버1 → 서버2 → 서버3 → 서버1...
  • • 장점: 구현이 간단하고 공정한 분산
  • • 단점: 서버 성능 차이를 고려하지 않음

Least Connections (최소 연결)

  • • 방식: 현재 연결 수가 가장 적은 서버 선택
  • • 예시: 연결수 3개, 1개, 5개 → 1개인 서버 선택
  • • 장점: 서버 부하를 고려한 분산
  • • 단점: 연결 상태를 지속적으로 모니터링 필요

데이터베이스 클러스터 - 개발자 관점

Master-Slave (읽기/쓰기 분리)

  • • 연결: Master(쓰기), Slave(읽기) 2개 커넥션
  • • 로직: SELECT는 Slave, INSERT/UPDATE는 Master
  • • 지연시간: Slave는 Master보다 약간 늦음
  • • 장애처리: Slave 장애 시 Master로 읽기 전환
  • • 실제 사용: MySQL Replication, PostgreSQL Streaming

Master-Master (양방향 복제)

  • • 연결: 하나의 Master만 바라보기
  • • 로직: DB가 자동으로 복제 처리
  • • 설정: DB 레벨에서 복제 설정
  • • 장애처리: Master 장애 시 다른 Master로 전환
  • • 주의사항: 동시 쓰기 시 충돌 가능성

💡 개발자 체크리스트

  • • 연결 풀: Master/Slave 각각 별도 커넥션 풀 구성
  • • 트랜잭션: 읽기 전용 트랜잭션은 Slave 사용
  • • 모니터링: 각 DB 서버 상태 및 지연시간 확인
  • • 설정: application.properties에서 데이터소스 분리 설정

세션 동기화 - 개발자 관점

문제 상황

  • • 세션 분실: 서버1에서 로그인 → 서버2로 요청 시 로그아웃
  • • 데이터 불일치: 각 서버마다 다른 세션 데이터
  • • 확장성 제한: 서버별 세션 저장으로 인한 메모리 부족
  • • 장애 전파: 서버 장애 시 해당 서버 세션 모두 손실

해결 방안

  • • Redis 세션: 중앙 집중식 세션 저장소
  • • JWT 토큰: 서버 무상태(Stateless) 인증
  • • Sticky Session: 특정 사용자를 특정 서버로 고정
  • • DB 세션: 데이터베이스에 세션 저장

🔧 Redis 세션 설정 (Spring Boot)

  • • 의존성: spring-session-data-redis 추가
  • • 설정: spring.session.store-type=redis
  • • 연결: spring.redis.host, port 설정
  • • 만료시간: spring.session.timeout 설정

AWS 서비스 매핑

네트워킹

  • • Route 53: DNS 서비스 (도메인 관리)
  • • CloudFront: CDN (전 세계 캐싱)
  • • VPC: 가상 네트워크 (로컬 네트워크 대응)
  • • ALB/NLB: 로드 밸런서

컴퓨팅 & 저장소

  • • EC2: 가상 서버 (로컬 서버 대응)
  • • RDS: 관리형 데이터베이스
  • • S3: 객체 저장소 (MinIO 대응)
  • • EBS: 블록 저장소 (하드디스크 대응)

고가용성 & 스케일링

가용 영역 (AZ)

  • • Multi-AZ: 여러 데이터센터에 분산
  • • 장애 격리: 한 AZ 장애 시 다른 AZ 사용
  • • 실제 사용: us-east-1a, us-east-1b, us-east-1c
  • • 장점: 99.99% 가용성 보장

Auto Scaling

  • • Scale Out: 서버 수 증가 (수평 확장)
  • • Scale Up: 서버 성능 증가 (수직 확장)
  • • 트리거: CPU, 메모리, 네트워크 사용률
  • • 실제 사용: AWS Auto Scaling Groups

Route 53 & CloudFront

Route 53 (DNS)

  • • 역할: 도메인을 IP 주소로 변환
  • • 예시: example.com → 1.2.3.4
  • • 기능: 도메인 등록, DNS 라우팅
  • • 장점: AWS 서비스들과 완벽하게 연동되는 DNS 서비스
  • • 비용: 호스팅 존당 월 $0.50

CloudFront (CDN)

  • • 역할: 전 세계 캐시 서버로 콘텐츠 배포
  • • 기능: 정적 파일 캐싱, DDoS 방어
  • • 장점: 빠른 로딩 속도, 전 세계 사용자 지원
  • • 사용처: 이미지, CSS, JS 파일
  • • 비용: 데이터 전송량 기반 과금

💡 실제 사용 시나리오

  1. 1단계: Route 53에서 도메인 등록 (example.com)
  2. 2단계: CloudFront 배포 생성 (ALB를 Origin으로 설정)
  3. 3단계: Route 53에서 CloudFront URL로 DNS 레코드 설정
  4. 4단계: 사용자가 example.com 접속 → CloudFront → ALB → EC2

🔧 개발자 관점에서의 CloudFront

기존 방식 (온프레미스)
  • • 파일을 서버 디렉토리에 저장
  • • 웹서버에서 정적 파일 서빙
  • • /uploads/images/photo.jpg
  • • Base URL 프로그래밍 필요
  • • 서버 부하 증가
CloudFront 방식 (AWS)
  • • 파일을 S3에 저장
  • • CloudFront가 자동 캐싱
  • • https://d1234.cloudfront.net/images/photo.jpg
  • • Base URL 설정만 하면 끝
  • • 서버 부하 없음
💡 개발자 체크리스트
  • • 파일 업로드: S3에 직접 업로드 (AWS SDK 사용)
  • • URL 생성: CloudFront URL로 변환하여 DB에 저장
  • • 설정: application.properties에 CloudFront 도메인 설정
  • • 장점: 서버 리소스 절약, 전 세계 빠른 접근

핵심 용어 정리

네트워크 용어

  • • DNS: 도메인을 IP로 변환
  • • CDN: 전 세계 캐시 서버
  • • VPC: 가상 사설 네트워크
  • • Subnet: VPC 내 세부 네트워크
  • • Security Group: 방화벽 규칙

스케일링 용어

  • • Scale Out: 서버 수 증가
  • • Scale Up: 서버 성능 증가
  • • Load Balancing: 트래픽 분산
  • • High Availability: 고가용성
  • • Disaster Recovery: 재해 복구

실습에서 사용할 AWS 서비스

EC2 (Elastic Compute Cloud)

  • • 역할: Spring Boot 애플리케이션 실행
  • • 기능: 웹 서버, API 서버
  • • 실습: t2.micro 인스턴스 사용
  • • 포트: 8080 (Spring Boot)

S3 (Simple Storage Service)

  • • 역할: 정적 파일 저장 (이미지, 첨부파일)
  • • 기능: 객체 저장, CDN 연동
  • • 실습: 버킷 생성 및 파일 업로드
  • • 장점: 무제한 저장, 고가용성

RDS (Relational Database Service)

  • • 역할: MySQL 데이터베이스 관리
  • • 기능: 자동 백업, 모니터링
  • • 실습: db.t2.micro 인스턴스
  • • 장점: 관리형 서비스, 보안 강화

💡 실습 구조의 특징

  • • 단순함: 복잡한 네트워킹 없이 핵심 서비스만 사용
  • • 비용 효율: 프리티어 범위 내에서 실습 가능
  • • 학습 효과: EC2, S3, RDS 핵심 서비스 이해에 집중
  • • 접근성: EC2 퍼블릭 IP로 직접 접근 가능
  • • 확장성: 필요시 ALB, CloudFront, Route 53 추가 가능

📝 실습 접근 방법

  • • EC2 퍼블릭 IP: http://[EC2-퍼블릭-IP]:8080 으로 직접 접근
  • • 보안 그룹: 8080 포트를 열어서 외부 접근 허용
  • • 도메인 없음: Route 53, CloudFront 없이도 실습 가능
  • • 로드밸런서 없음: 단일 EC2 인스턴스로 시작
