1

AWS 계정 생성

⚠️ 중요: AWS 계정 생성 시 신용카드 등록이 필요합니다. 프리티어 범위 내에서 사용하면 요금이 부과되지 않지만, 초과 시 과금될 수 있으니 주의하세요!

회원가입 절차

1️⃣ AWS 홈페이지 접속

https://aws.amazon.com/ko/ 접속 후 "AWS 계정 생성" 클릭

📸 이미지: AWS 홈페이지 스크린샷
(aws-homepage.png)

2️⃣ 이메일 및 계정 이름 입력

  • 루트 사용자 이메일 주소 입력
  • AWS 계정 이름 입력 (예: goormjpa-account)
📸 이미지: 계정 생성 1단계
(aws-signup-step1.png)

3️⃣ 연락처 정보 입력

  • 계정 유형 선택: 개인
  • 이름, 전화번호, 주소 등 입력

4️⃣ 결제 정보 입력

  • 신용카드 또는 체크카드 정보 입력
  • 카드 인증을 위해 소액(1달러) 결제 후 환불

5️⃣ 자격 증명 확인 (전화 인증)

  • 전화번호 입력 후 자동 전화 또는 SMS로 인증 코드 수신
  • 인증 코드 입력

6️⃣ 지원 플랜 선택

  • 기본 지원 - 무료 선택

✅ 계정 생성이 완료되면 AWS Management Console에 로그인할 수 있습니다!

2

리전 선택: 서울

AWS는 전 세계에 여러 리전(Region)을 운영합니다. 한국에서 사용할 때는 서울 리전을 선택하는 것이 가장 빠릅니다.

💡 리전 코드: ap-northeast-2 (아시아 태평양 - 서울)

리전 변경 방법

  1. AWS Management Console 우측 상단의 리전 드롭다운 클릭
  2. "아시아 태평양 (서울)" 선택
📸 이미지: 리전 선택 드롭다운
(aws-region-selector.png)

⚠️ 주의: 앞으로 모든 리소스(EC2, RDS, S3 등)는 서울 리전에서 생성해야 합니다. 리전이 다르면 서로 연결되지 않습니다!

3

IAM 사용자 생성

💡 왜 IAM 사용자를 만드나요?

  • • 루트 계정은 모든 권한을 가지므로 보안상 위험합니다.
  • • IAM 사용자는 필요한 권한만 부여하여 안전하게 관리할 수 있습니다.
  • • GitHub Actions 등 자동화 도구에서 사용할 Access Key를 발급받습니다.

IAM 사용자 생성 절차

1️⃣ IAM 서비스로 이동

  • AWS Console 상단 검색창에 "IAM" 입력
  • "IAM" 서비스 클릭
📸 이미지: IAM 검색
(iam-search.png)

2️⃣ 사용자 생성

  • 좌측 메뉴에서 "사용자" 클릭
  • "사용자 생성" 버튼 클릭
📸 이미지: IAM 사용자 목록
(iam-users-list.png)

3️⃣ 사용자 이름 입력

  • 사용자 이름: goormjpa-user
  • "다음" 클릭
📸 이미지: 사용자 이름 입력
(iam-user-name.png)

4️⃣ 권한 설정

  • "직접 정책 연결" 선택
  • 다음 정책들을 검색해서 체크:
    • ✅ AmazonEC2FullAccess
    • ✅ AmazonRDSFullAccess
    • ✅ AmazonS3FullAccess
  • "다음" 클릭
📸 이미지: 권한 정책 선택
(iam-permissions.png)

5️⃣ 검토 및 사용자 생성

  • 설정 내용 확인
  • "사용자 생성" 클릭

✅ IAM 사용자 생성 완료! 이제 Access Key를 발급받겠습니다.

Access Key 발급

💡 Access Key란?

CLI, SDK, GitHub Actions 등 프로그래밍 방식으로 AWS에 접근할 때 사용하는 인증 키입니다.

1️⃣ 생성한 사용자 선택

  • IAM → 사용자 목록에서 goormjpa-user 클릭

2️⃣ 보안 자격 증명 탭

  • "보안 자격 증명" 탭 클릭
  • "액세스 키 만들기" 버튼 클릭
📸 이미지: 보안 자격 증명 탭
(iam-security-credentials.png)

3️⃣ 사용 사례 선택

  • "Command Line Interface(CLI)" 선택
  • 하단의 권장 사항 확인 체크박스 체크
  • "다음" 클릭
📸 이미지: 사용 사례 선택
(access-key-use-case.png)

4️⃣ 설명 태그 추가 (선택)

  • 설명 태그: GitHub Actions for CI/CD
  • "액세스 키 만들기" 클릭

5️⃣ Access Key 저장 ⭐⭐⭐

🚨 매우 중요!

  • • 액세스 키 ID와 비밀 액세스 키가 표시됩니다.
  • • 이 페이지를 벗어나면 다시 볼 수 없습니다!
  • • 반드시 안전한 곳에 저장하세요 (메모장, 비밀번호 관리자 등)

액세스 키 ID: AKIAIOSFODNN7EXAMPLE

비밀 액세스 키: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY

📸 이미지: Access Key 생성 완료
(access-key-created.png)

✅ Access Key 발급 완료! 이제 로컬 PC에 AWS CLI를 설치하겠습니다.

AWS CLI 설치 (로컬 PC)

💡 AWS CLI란?

터미널(명령 프롬프트)에서 명령어로 AWS 서비스를 제어할 수 있게 해주는 도구입니다.

운영체제별 설치 방법

🪟 Windows

방법 1: MSI 인스톨러 사용 (권장)

  1. AWS CLI 설치 파일 다운로드: https://awscli.amazonaws.com/AWSCLIV2.msi
  2. 다운로드한 AWSCLIV2.msi 파일 실행
  3. 설치 마법사에 따라 설치 진행
  4. 설치 완료 후 명령 프롬프트 또는 PowerShell 재시작

방법 2: 명령어로 설치

# PowerShell에서 실행
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi

설치 확인:

aws --version
# 출력 예시: aws-cli/2.15.0 Python/3.11.6 Windows/10 exe/AMD64
🍎 macOS

방법 1: PKG 인스톨러 사용 (권장)

  1. AWS CLI 설치 파일 다운로드: https://awscli.amazonaws.com/AWSCLIV2.pkg
  2. 다운로드한 AWSCLIV2.pkg 파일 실행
  3. 설치 마법사에 따라 설치 진행

방법 2: Homebrew로 설치

brew install awscli

설치 확인:

aws --version
# 출력 예시: aws-cli/2.15.0 Python/3.11.6 Darwin/23.0.0 source/arm64
🐧 Linux

설치 명령어:

curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
sudo apt install unzip   # Ubuntu/Debian
# 또는
sudo yum install unzip   # Amazon Linux/RHEL/CentOS

unzip awscliv2.zip
sudo ./aws/install

설치 확인:

aws --version
# 출력 예시: aws-cli/2.15.0 Python/3.11.6 Linux/5.10.0-28-amd64 source/x86_64.ubuntu.22

✅ AWS CLI 설치 완료! 이제 자격 증명을 설정하겠습니다.

AWS 자격 증명 설정

💡 aws configure란?

로컬 PC에서 AWS CLI가 여러분의 AWS 계정에 접근할 수 있도록 Access Key를 등록하는 과정입니다.

1️⃣ aws configure 실행

aws configure

2️⃣ 정보 입력

4가지 정보를 순서대로 입력합니다:

AWS Access Key ID [None]: AKIAIOSFODNN7EXAMPLE
AWS Secret Access Key [None]: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
Default region name [None]: ap-northeast-2
Default output format [None]: json
항목 입력 값 설명
Access Key ID AKIA... IAM에서 발급받은 액세스 키 ID
Secret Access Key wJal... IAM에서 발급받은 비밀 액세스 키
Region ap-northeast-2 서울 리전
Output format json 출력 형식 (json, yaml, text 등)

3️⃣ 설정 확인

설정된 정보는 다음 위치에 저장됩니다:

Windows: C:\Users\사용자명\.aws\credentials

macOS/Linux: ~/.aws/credentials

설정 확인 명령어:

# 설정된 프로필 확인
aws configure list

# 출력 예시:
#       Name                    Value             Type    Location
#       ----                    -----             ----    --------
#    profile                             None    None
# access_key     ****************AMPLE shared-credentials-file
# secret_key     ****************AMPLE shared-credentials-file
#     region           ap-northeast-2      config-file    ~/.aws/config

⚠️ 보안 주의: ~/.aws/credentials 파일에는 비밀 키가 저장되므로 절대 Git에 커밋하거나 공유하지 마세요!

연결 테스트

AWS CLI가 제대로 설정되었는지 확인하기 위해 몇 가지 명령어를 실행해봅니다.

1️⃣ 현재 사용자 확인

aws sts get-caller-identity

출력 예시:

{
    "UserId": "AIDACKCEVSQ6C2EXAMPLE",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/goormjpa-user"
}

✅ Arn에 goormjpa-user가 표시되면 성공입니다!

2️⃣ S3 버킷 목록 조회

aws s3 ls

아직 S3 버킷을 만들지 않았다면 빈 결과가 나옵니다 (정상):

# 아무것도 출력되지 않음 (정상)

✅ 에러 없이 실행되면 성공입니다! (빈 결과 OK)

3️⃣ EC2 인스턴스 목록 조회

aws ec2 describe-instances

아직 EC2 인스턴스를 만들지 않았다면:

{
    "Reservations": []
}

✅ JSON 형식으로 출력되면 성공입니다!

4️⃣ 리전 확인

aws configure get region

출력:

ap-northeast-2

✅ ap-northeast-2가 출력되면 성공입니다!

🚨 에러가 발생한 경우

"Unable to locate credentials"

→ aws configure를 다시 실행해서 Access Key를 입력하세요.

"An error occurred (UnauthorizedOperation)"

→ IAM 사용자에게 해당 권한이 없습니다. IAM 정책을 확인하세요.

"Could not connect to the endpoint URL"

→ 인터넷 연결을 확인하세요. 또는 리전 설정이 잘못되었을 수 있습니다.
