☁️ 온프레미스 vs 클라우드 환경

💡 클라우드는 "인터넷을 통해 제공되는 컴퓨팅 서비스"입니다!

자체 서버실이나 데이터센터에서 직접 운영하는 대신, AWS 같은 클라우드 제공자의 인프라를 빌려서 사용하는 개념입니다.

🏢

온프레미스 (On-Premise)

자체 서버실 또는 데이터센터 운영

💡 Premise = 건물/부지, On-Premise = 회사 건물 내에 직접 설치

초기 투자 비용 높음: 서버, 네트워크 장비 구매
관리 인력 필요: 시스템 관리자, 네트워크 엔지니어
확장 어려움: 하드웨어 증설에 시간/비용 소요
완전한 제어권: 보안, 네트워크 완벽 통제
장애 대응 책임: 모든 장애 직접 해결
☁️

클라우드 (Cloud)

AWS, GCP, Azure 등의 인프라 임대

초기 비용 없음: 사용한 만큼만 지불
관리 부담 감소: 인프라 관리는 클라우드 제공자가 담당
빠른 확장: 클릭 몇 번으로 서버 증설
전 세계 배포: 여러 리전에 쉽게 배포 가능
고가용성: 자동 백업, 장애 복구 지원

상세 비교

구분 온프레미스 클라우드
초기 비용 높음 (수천만원~수억원) 없음 (종량제)
운영 비용 인건비, 전기세, 유지보수 사용량 기반 요금
확장성 느림 (장비 구매 및 설치) 빠름 (즉시 확장)
관리 책임 전체 (하드웨어~애플리케이션) 애플리케이션만
장애 대응 직접 해결 (24시간 대기) 자동 복구 지원
보안 통제 완전한 통제 일부 제한 (공유 책임 모델)
적합한 경우 규제 산업, 민감한 데이터 스타트업, 빠른 성장 기업

☁️ 클라우드 서비스 제공 형태 (IaaS, PaaS, SaaS)

💡 클라우드는 제공 방식에 따라 3가지로 구분됩니다

개발자 입장에서 "내가 직접 해야 하는 일"이 얼마나 많은지에 따라 IaaS, PaaS, SaaS로 나뉩니다.

🏗️

IaaS

Infrastructure as a Service

인프라를 서비스로

📋 정의

가상 서버, 스토리지, 네트워크만 제공. OS부터 애플리케이션까지 모두 직접 설치/관리

👨‍💻 개발자가 해야 할 일

  • ✅ OS 선택 및 설정 (Ubuntu, Amazon Linux 등)
  • ✅ Java, Node.js 등 런타임 설치
  • ✅ 웹 서버(Nginx) 설치/설정
  • ✅ 데이터베이스 설치/설정
  • ✅ 보안 설정 (방화벽, 인증서)
  • ✅ 배포 스크립트 작성
  • ✅ 서버 모니터링 및 유지보수
대표 서비스:

AWS EC2, Google Compute Engine, Azure VM

🚀

PaaS

Platform as a Service

플랫폼을 서비스로

📋 정의

개발/실행 환경까지 제공. 코드만 작성해서 올리면 자동으로 배포됩니다.

👨‍💻 개발자가 해야 할 일

  • ✅ 코드 작성
  • ✅ 의존성 명시 (package.json, pom.xml)
  • ✅ Git push 또는 파일 업로드
  • ❌ 서버 설정 (플랫폼이 자동 처리)
  • ❌ 런타임 설치 (플랫폼이 자동 처리)
  • ❌ 배포 스크립트 (플랫폼이 자동 처리)
대표 서비스:

Vercel, Heroku, AWS Elastic Beanstalk, Railway, Render

📱

SaaS

Software as a Service

소프트웨어를 서비스로

📋 정의

완성된 소프트웨어를 바로 사용. 개발 없이 웹/앱으로 접속해서 즉시 사용

👨‍💻 개발자/사용자가 해야 할 일

  • ✅ 회원가입/로그인
  • ✅ 서비스 사용 (클릭, 입력)
  • ✅ 필요시 설정 변경
  • ❌ 개발 (이미 완성됨)
  • ❌ 서버 관리 (제공자가 관리)
  • ❌ 배포 (제공자가 관리)
대표 서비스:

Google Workspace, Slack, Notion, Figma, Dropbox

⚡ 추가 개념: Serverless (FaaS)

Serverless는 "서버가 없다"는 의미가 아니라, 개발자가 서버를 의식하지 않아도 된다는 개념입니다. PaaS에서 더 나아가 함수(Function) 단위로 코드를 실행하며, 사용한 만큼만 과금됩니다.

📌 주요 특징

  • ✅ 서버 관리 완전히 불필요 (프로비저닝, 스케일링 자동)
  • ✅ 함수가 실행될 때만 과금 (유휴 시간은 무료)
  • ✅ 자동 스케일링 (트래픽에 따라 자동 확장/축소)
  • ⚠️ 콜드 스타트 문제 (첫 실행 시 지연)
  • ⚠️ 실행 시간 제한 (보통 15분 이내)
AWS Lambda

AWS의 Serverless 컴퓨팅

Azure Functions

Microsoft Azure의 FaaS

Google Cloud Functions

GCP의 이벤트 기반 함수

💡 참고: 이 강의의 Spring Boot 애플리케이션은 전통적인 웹 서버 방식이므로 EC2(IaaS)가 더 적합합니다. Serverless는 짧고 독립적인 작업(예: 이미지 리사이징, 데이터 처리)에 유리합니다.

🎵 약자 및 발음 정리

약자 정식 발음 보통 발음 의미
IaaS Infrastructure as a Service 아이애스 인프라형 서비스
PaaS Platform as a Service 파스 플랫폼형 서비스
SaaS Software as a Service 사스 소프트웨어형 서비스
FaaS Function as a Service 패스 함수형 서비스 (Serverless)
발음만 봐도, 위 네 가지를 한꺼번에 외우기 좋죠 😄

💻 Java 개발자 관점: PaaS vs FaaS 차이

PaaS (Platform as a Service)

배포 단위: 애플리케이션 전체

예시: Spring Boot 프로젝트 전체

실행: 서버가 계속 돌아감 (24/7)

코드: @SpringBootApplication

→ main() 실행되고 톰캣 서버 계속 대기

FaaS (Function as a Service)

배포 단위: 함수 하나

예시: Java 메서드 하나만 배포

실행: 요청 올 때만 실행 (이벤트 기반)

코드: handleRequest()

→ 요청 → 함수 실행 → 응답 → 종료

🤔 쉽게 구분: PaaS는 "프로젝트 전체 배포 (서버 항상 ON)", FaaS는 "함수만 배포 (필요할 때만 ON)"

🎓 이 강의에서 사용하는 방식

IaaS (AWS EC2)를 사용합니다!

왜 IaaS를 배우나요?

  • ✅ 서버 구축부터 배포까지 전체 흐름을 이해
  • ✅ OS, 네트워크, 보안 등 인프라 개념 학습
  • ✅ PaaS/SaaS를 쓰더라도 문제 발생 시 근본 원인 파악 가능
  • ✅ 실무에서 레거시 시스템 유지보수에 필요

📈 최근 트렌드

요즘은 PaaS가 대세!

PaaS가 인기 있는 이유

  • ✅ 코드만 push하면 자동 배포 (git push → 배포 완료)
  • ✅ 서버 설정/관리 불필요 → 개발에만 집중
  • ✅ 자동 스케일링 (트래픽 증가 시 자동 확장)
  • ✅ 무료/저렴한 시작 비용 (Vercel, Railway 등)
💡 실무 팁: 빠른 프로토타입은 PaaS, 복잡한 커스터마이징이나 대규모 시스템은 IaaS + 일부 PaaS 혼합 사용

🚀 요즘 인기 있는 PaaS 서비스들

Vercel

📖 AWS 용어 정의

💡 Elastic (엘라스틱) = 탄력적인, 늘었다 줄었다 할 수 있는

💡 Instance (인스턴스) = 실행 중인 가상 서버/DB 하나

💡 Provisioning (프로비저닝) = 리소스를 준비하고 할당하는 과정

💡 Endpoint (엔드포인트) = 접속 주소/URL

💡 Snapshot (스냅샷) = 특정 시점의 데이터 백업

💡 Throttling (쓰로틀링) = API 호출 횟수 제한

💡 Region (리전) = AWS 데이터센터 위치 (서울, 도쿄 등)

💡 Availability Zone (AZ) = 리전 내 독립된 데이터센터

🖥️

EC2

Elastic Compute Cloud

가상 서버(Virtual Machine)를 제공하는 서비스. 리눅스나 윈도우가 설치된 컴퓨터를 빌려서 사용하는 개념입니다.

예시: Ubuntu 20.04가 설치된 t2.micro 인스턴스
🗄️

RDS

Relational Database Service

관계형 데이터베이스를 쉽게 관리할 수 있는 서비스. MySQL, MariaDB, PostgreSQL 등을 자동으로 백업하고 관리해줍니다.

예시: MariaDB 10.6.8 인스턴스 (자동 백업 포함)
📁

S3

Simple Storage Service

무제한 파일 저장소. 이미지, 동영상, 문서 등을 인터넷을 통해 저장하고 불러올 수 있습니다.

예시: 버킷(jpa-app-files)에 이미지 업로드
🌐

VPC

Virtual Private Cloud

가상 네트워크 환경. 마치 회사의 사설 네트워크처럼 AWS 내에서 격리된 네트워크를 만들 수 있습니다.

예시: 10.0.0.0/16 IP 대역으로 네트워크 생성
💿

AMI

Amazon Machine Image

EC2 인스턴스를 만들 때 사용하는 운영체제 템플릿. 윈도우 설치 CD와 비슷한 개념입니다.

예시: Ubuntu 20.04 LTS AMI
🔒

보안 그룹

Security Group

인스턴스의 방화벽 역할. 어떤 포트(22, 80, 443 등)를 열고 닫을지 설정합니다.

예시: SSH(22), HTTP(80), HTTPS(443) 포트 허용
👤

IAM

Identity and Access Management

AWS 계정 및 권한 관리 서비스. 사용자를 만들고, 어떤 AWS 서비스에 접근할 수 있는지 제어합니다.

예시: "jpa-developer" 사용자 생성, EC2 전체 권한 부여
🔑

키 페어

Key Pair

EC2 인스턴스에 SSH로 접속하기 위한 암호화 키. .pem 파일 형태로 다운로드되며, 비밀번호 대신 사용합니다.

예시: jpa-keypair.pem 파일로 EC2 접속

📊 AWS 과금 방식

💡 AWS는 다양한 과금 방식을 제공합니다

사용 패턴과 예산에 따라 적절한 방식을 선택하면 비용을 크게 절감할 수 있습니다.

💳

온디맨드

On-Demand

필요할 때 즉시 사용하고, 사용한 만큼만 비용을 지불하는 방식입니다. 장기 약정 없이 초 단위로 과금됩니다.

특징:
  • 약정 없음, 언제든 시작/중단 가능
  • 초 단위 과금 (최소 60초)
  • 가장 유연하지만 비용은 가장 높음
💡 어원: On-Demand = "요구가 있을 때", "필요할 때 즉시"
📅

예약 인스턴스

Reserved Instance (RI)

1년 또는 3년 장기 약정으로 인스턴스를 예약하면 온디맨드 대비 최대 75% 할인을 받을 수 있습니다.

특징:
  • 1년/3년 약정 (3년이 할인율 더 높음)
  • 온디맨드 대비 최대 75% 할인
  • 안정적인 서비스에 적합
🎯

스팟 인스턴스

Spot Instance

AWS의 남는 EC2 용량을 경매 방식으로 사용하는 방식입니다. 최대 90% 할인이지만 언제든 중단될 수 있습니다.

특징:
  • 온디맨드 대비 최대 90% 할인
  • AWS가 용량이 필요하면 2분 전 통보 후 중단
  • 배치 작업, 데이터 분석 등에 적합
🎁

프리티어

Free Tier

AWS 계정 생성 후 12개월간 일정량을 무료로 사용할 수 있는 혜택입니다. 이 강의에서 활용합니다!

주요 무료 항목:
  • EC2 t2.micro: 월 750시간
  • RDS db.t3.micro: 월 750시간
  • S3: 5GB 스토리지
과금 방식 할인율 약정 적합한 경우
온디맨드 없음 (정가) 없음 테스트, 단기 사용, 예측 불가능한 워크로드
예약 인스턴스 최대 75% 1년 또는 3년 안정적이고 예측 가능한 서비스 (운영 DB, 웹 서버)
스팟 인스턴스 최대 90% 없음 중단 가능한 작업 (배치, 빅데이터 분석)
프리티어 100% (무료) 12개월 제한 학습, 실습, 개인 프로젝트

EC2 (Elastic Compute Cloud)

가상 서버를 제공하는 AWS의 핵심 컴퓨팅 서비스

주요 특징

  • • 가상 서버: 원하는 OS와 사양으로 서버 생성
  • • 확장성: 필요에 따라 서버 사양 변경 가능
  • • 다양한 인스턴스 타입: t2.micro, t3.small 등
  • • 보안: VPC, 보안 그룹으로 네트워크 격리

실습 설정

  • • 인스턴스 타입: t2.micro (프리티어)
  • • OS: Ubuntu 20.04 LTS
  • • 스토리지: 8GB gp2 (프리티어)
  • • 네트워크: 퍼블릭 서브넷

💡 개발자 관점

  • • SSH 접속: 키 페어를 사용한 보안 접속
  • • Docker 설치: 컨테이너 기반 애플리케이션 실행
  • • 포트 설정: 보안 그룹에서 8080, 80, 443 포트 열기
  • • 환경 변수: RDS, S3 연결 정보 설정
🗄️

RDS (Relational Database Service)

관리형 관계형 데이터베이스 서비스

주요 특징

  • • 관리형 서비스: 백업, 패치, 모니터링 자동화
  • • 고가용성: Multi-AZ 배포로 장애 대응
  • • 보안: 암호화, VPC 격리, IAM 통합
  • • 확장성: 읽기 전용 복제본 생성 가능

실습 설정

  • • 엔진: MariaDB 10.6.8
  • • 인스턴스 클래스: db.t3.micro
  • • 스토리지: 20GB gp2
  • • 백업: 7일간 자동 백업

💡 개발자 관점

  • • 연결 문자열: jdbc:mariadb://[엔드포인트]:3306/[DB명]
  • • 보안 그룹: EC2에서만 3306 포트 접근 허용
  • • 환경 변수: application.properties에서 DB 설정
  • • 모니터링: CloudWatch를 통한 성능 모니터링
📁

S3 (Simple Storage Service)

무제한 객체 저장소 서비스

주요 특징

  • • 무제한 저장: 용량 제한 없음
  • • 고가용성: 99.999999999% 내구성
  • • 버전 관리: 파일 버전 히스토리 관리
  • • 생명주기: 자동 아카이빙 및 삭제

실습 설정

  • • 버킷명: 고유한 이름 (전 세계 유일)
  • • 리전: ap-northeast-2 (서울)
  • • 퍼블릭 액세스: 필요에 따라 설정
  • • CORS: 웹 애플리케이션 접근 허용

💡 개발자 관점

  • • 버킷 정책: 접근 권한 설정
  • • CORS 설정: 브라우저에서 직접 접근 허용
  • • URL 구조: https://[버킷명].s3.[리전].amazonaws.com/[키]
  • • CloudFront 연동: CDN을 통한 빠른 접근

📁 S3 실제 설정 예시

문서는 비공개, 이미지는 공개로 설정하는 일반적인 방법

폴더 구조

my-bucket/
├── documents/          (비공개)
│   ├── contract.pdf
│   ├── report.docx
│   └── manual.pdf
├── images/            (공개)
│   ├── profile/
│   │   ├── user1.jpg
│   │   └── user2.png
│   └── products/
│       ├── item1.jpg
│       └── item2.jpg
└── temp/              (비공개)
    └── uploads/

버킷 정책 (Bucket Policy)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadImages",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/images/*"
    },
    {
      "Sid": "DenyDocumentsAccess",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/documents/*"
    }
  ]
}

3. S3 서비스 클래스

@Service
@Slf4j
public class S3Service {
    
    private final S3Client s3Client;
    private final String bucketName;
    
    public S3Service(@Value("${aws.s3.bucket-name}") String bucketName,
                     @Value("${aws.s3.region}") String region,
                     @Value("${aws.s3.access-key}") String accessKey,
                     @Value("${aws.s3.secret-key}") String secretKey) {
        this.bucketName = bucketName;
        this.s3Client = S3Client.builder()
            .region(Region.of(region))
            .credentialsProvider(StaticCredentialsProvider.create(
                AwsBasicCredentials.create(accessKey, secretKey)))
            .build();
    }
    
    // 파일 업로드
    public String uploadFile(MultipartFile file, String folder) {
        try {
            String fileName = folder + "/" + UUID.randomUUID() + "_" + file.getOriginalFilename();
            
            PutObjectRequest putObjectRequest = PutObjectRequest.builder()
                .bucket(bucketName)
                .key(fileName)
                .contentType(file.getContentType())
                .build();
            
            s3Client.putObject(putObjectRequest, 
                RequestBody.fromInputStream(file.getInputStream(), file.getSize()));
            
            return "https://" + bucketName + ".s3.ap-northeast-2.amazonaws.com/" + fileName;
        } catch (Exception e) {
            log.error("파일 업로드 실패", e);
            throw new RuntimeException("파일 업로드에 실패했습니다.");
        }
    }
    
    // 파일 삭제
    public void deleteFile(String fileUrl) {
        try {
            String key = extractKeyFromUrl(fileUrl);
            DeleteObjectRequest deleteObjectRequest = DeleteObjectRequest.builder()
                .bucket(bucketName)
                .key(key)
                .build();
            
            s3Client.deleteObject(deleteObjectRequest);
        } catch (Exception e) {
            log.error("파일 삭제 실패", e);
            throw new RuntimeException("파일 삭제에 실패했습니다.");
        }
    }
    
    private String extractKeyFromUrl(String fileUrl) {
        // https://bucket-name.s3.region.amazonaws.com/key 형태에서 key 추출
        return fileUrl.substring(fileUrl.lastIndexOf("/") + 1);
    }
}

4. 파일 업로드 컨트롤러

@RestController
@RequestMapping("/api/files")
@Slf4j
public class FileController {
    
    private final S3Service s3Service;
    
    public FileController(S3Service s3Service) {
        this.s3Service = s3Service;
    }
    
    @PostMapping("/upload")
    public ResponseEntity<Map<String, String>> uploadFile(
            @RequestParam("file") MultipartFile file,
            @RequestParam(value = "folder", defaultValue = "uploads") String folder) {
        
        try {
            String fileUrl = s3Service.uploadFile(file, folder);
            
            Map<String, String> response = new HashMap<>();
            response.put("url", fileUrl);
            response.put("originalName", file.getOriginalFilename());
            response.put("size", String.valueOf(file.getSize()));
            
            return ResponseEntity.ok(response);
        } catch (Exception e) {
            log.error("파일 업로드 실패", e);
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(Map.of("error", "파일 업로드에 실패했습니다."));
        }
    }
    
    @DeleteMapping("/delete")
    public ResponseEntity<String> deleteFile(@RequestParam("url") String fileUrl) {
        try {
            s3Service.deleteFile(fileUrl);
            return ResponseEntity.ok("파일이 삭제되었습니다.");
        } catch (Exception e) {
            log.error("파일 삭제 실패", e);
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body("파일 삭제에 실패했습니다.");
        }
    }
}

CORS 설정 (중요!)

S3 버킷에서 CORS를 설정해야 브라우저에서 직접 접근할 수 있습니다.

{
  "CORSRules": [
    {
      "AllowedHeaders": ["*"],
      "AllowedMethods": ["GET", "POST", "PUT", "DELETE", "HEAD"],
      "AllowedOrigins": ["*"],
      "ExposeHeaders": ["ETag"],
      "MaxAgeSeconds": 3000
    }
  ]
}

⚠️ 주의사항

  • • 보안: 운영 환경에서는 AllowedOrigins를 특정 도메인으로 제한
  • • 권한: 버킷 정책에서 적절한 접근 권한 설정
  • • 비용: 데이터 전송량에 따른 과금 발생
  • • 성능: CloudFront와 연동하여 CDN 활용 권장

📚 실습의 이점

실제 운영 환경 경험

EC2에 직접 배포하고 RDS를 연결하면서 실무와 동일한 아키텍처를 구축합니다.

관리형 서비스 이해

RDS의 자동 백업, S3의 고가용성 등 클라우드의 핵심 기능을 직접 체험합니다.

확장 가능한 구조

프리티어로 시작하지만, 필요시 인스턴스 타입만 변경하면 바로 확장 가능한 구조입니다.

포트폴리오에 활용

AWS를 활용한 실제 배포 경험을 면접에서 어필할 수 있습니다.

⚠️ 프리티어 주의사항

  • • 프리티어 기간: AWS 계정 생성 후 12개월간 무료 사용 가능
  • • 사용 시간 제한: EC2와 RDS는 각각 월 750시간까지 무료 (1개 인스턴스 24시간 가동 = 약 720시간)
  • • 인스턴스 타입: EC2는 t2.micro, RDS는 db.t3.micro만 프리티어 대상
  • • 실습 후 종료: 실습이 끝나면 인스턴스를 반드시 중지 또는 삭제하여 과금 방지
  • • 비용 알림 설정: AWS Budgets에서 비용 알림을 설정하면 예상치 못한 과금을 방지할 수 있습니다
