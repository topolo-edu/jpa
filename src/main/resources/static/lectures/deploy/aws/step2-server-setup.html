EC2 인스턴스 생성

💡 EC2란?

Elastic Compute Cloud의 약자로, 가상 서버를 제공하는 서비스입니다. 우리의 Spring Boot 애플리케이션이 실행될 서버입니다.

EC2 생성 설정값

속성 설정값
이름 및 태그 goormjpa
애플리케이션 및 OS 이미지 Ubuntu
인스턴스 유형 t2.micro (프리티어)
키페어 이름 goormjpa
키페어 유형 RSA
프라이빗 키 파일 형식 .pem
방화벽 (보안 그룹) 새 보안 그룹 생성
스토리지 (볼륨) 8 GiB (기본값)

(ec2-dashboard.png)

3️⃣ 애플리케이션 및 OS 이미지 (AMI)

  • Ubuntu 선택
  • Ubuntu Server 24.04 LTS (또는 최신 LTS 버전)
  • 아키텍처: 64비트 (x86)

4️⃣ 인스턴스 유형

📟 CLI로 생성하기 (선택사항)

콘솔 대신 CLI로 EC2를 생성하려면:

# 키 페어 생성 (이미 생성했다면 생략)
aws ec2 create-key-pair \
  --key-name goormjpa \
  --query 'KeyMaterial' \
  --output text > goormjpa.pem

# 키 파일 권한 설정 (Mac/Linux)
chmod 400 goormjpa.pem

# 보안 그룹 생성
SECURITY_GROUP_ID=$(aws ec2 create-security-group \
  --group-name goormjpa-sg \
  --description "Security group for goormjpa" \
  --query 'GroupId' \
  --output text)

# SSH 접근 허용 (내 IP만)
MY_IP=$(curl -s https://checkip.amazonaws.com)
aws ec2 authorize-security-group-ingress \
  --group-id $SECURITY_GROUP_ID \
  --protocol tcp \
  --port 22 \
  --cidr ${MY_IP}/32

# EC2 인스턴스 생성
aws ec2 run-instances \
  --image-id ami-0c9c942bd7bf113a2 \
  --instance-type t2.micro \
  --key-name goormjpa \
  --security-group-ids $SECURITY_GROUP_ID \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=goormjpa}]'

⚠️ ami-0c9c942bd7bf113a2는 서울 리전의 Ubuntu 24.04 AMI ID입니다. 최신 AMI ID는 콘솔에서 확인하세요.

EC2 SSH 접속

생성한 EC2 인스턴스에 SSH로 접속하여 서버가 정상 작동하는지 확인합니다.

1️⃣ 퍼블릭 IP 확인

  • EC2 콘솔 → 인스턴스 목록에서 goormjpa 선택
  • 하단 세부 정보에서 "퍼블릭 IPv4 주소" 복사
  • 예: 3.34.123.45
📸 이미지: 퍼블릭 IP 확인
(ec2-public-ip.png)

2️⃣ SSH 접속

🪟 Windows

Windows 10/11은 기본 SSH 클라이언트가 있습니다. PowerShell 또는 CMD에서:

# goormjpa.pem 파일이 있는 디렉토리로 이동
cd C:\Users\사용자명\Downloads

# SSH 접속 (퍼블릭 IP를 본인의 IP로 변경)
ssh -i goormjpa.pem ubuntu@3.34.123.45

⚠️ 권한 오류가 발생하면 .pem 파일 우클릭 → 속성 → 보안 탭에서 모든 사용자 제거 후 본인만 추가

🍎 macOS / 🐧 Linux

# .pem 파일 권한 설정 (최초 1회만)
chmod 400 ~/Downloads/goormjpa.pem

# SSH 접속 (퍼블릭 IP를 본인의 IP로 변경)
ssh -i ~/Downloads/goormjpa.pem ubuntu@3.34.123.45

접속 성공 시 출력:

Welcome to Ubuntu 24.04 LTS (GNU/Linux 6.8.0-1008-aws x86_64)

ubuntu@ip-172-31-0-123:~$

3️⃣ 서버 정보 확인

# 메모리 확인

# 디스크 확인

RDS 데이터베이스 생성

💡 RDS란?

Relational Database Service의 약자로, 관리형 데이터베이스를 제공합니다. 백업, 패치, 모니터링을 자동으로 해줍니다.

RDS 생성 설정값

속성 설정값
데이터베이스 생성 방식 손쉬운 생성
엔진 유형 MariaDB
DB 인스턴스 크기 프리티어
DB 인스턴스 식별자 goormjpa-db
마스터 사용자 이름 admin
마스터 암호 goorm_rdb_password
자격 증명 관리 자체 관리
EC2 연결 EC2 컴퓨팅 리소스에 연결 (goormjpa)

  • "데이터베이스 생성" 버튼 클릭
📸 이미지: RDS 대시보드
(rds-dashboard.png)

📸 이미지: 손쉬운 생성 선택

3️⃣ 엔진 옵션

S3 버킷 생성

💡 S3란?

Simple Storage Service의 약자로, 파일 저장소를 제공합니다. 이미지, 동영상, 문서 등을 저장하고 URL로 접근할 수 있습니다.

S3 버킷 생성 설정값

속성 설정값
버킷 이름 goormjpa-각자아이디
기타 설정 기본값 사용

1️⃣ S3 서비스로 이동

  • AWS Console 검색창에 "S3" 입력
  • S3 대시보드로 이동
  • "버킷 만들기" 버튼 클릭
📸 이미지: S3 대시보드
(s3-dashboard.png)

2️⃣ 버킷 이름 입력

  • 버킷 이름: goormjpa-본인아이디
  • 예: goormjpa-topolo

⚠️ S3 버킷 이름은 전 세계에서 고유해야 합니다. 다른 사람이 이미 사용 중이면 생성되지 않으므로 본인만의 고유한 이름을 사용하세요!

📸 이미지: 버킷 이름 입력
(s3-bucket-name.png)

3️⃣ 기타 설정

  • 객체 소유권: ACL 비활성화됨 (권장) (기본값)
  • 퍼블릭 액세스 차단 설정: 모든 퍼블릭 액세스 차단 (기본값, 나중에 변경)
  • 버킷 버전 관리: 비활성화 (기본값)
  • 나머지: 기본값 사용

4️⃣ 버킷 만들기

  • "버킷 만들기" 클릭

EC2-S3 연결 (IAM 역할)

💡 왜 IAM 역할이 필요한가요?

EC2에서 S3로 파일을 업로드하려면 권한이 필요합니다. IAM 역할을 EC2에 연결하면 Access Key 없이도 안전하게 S3에 접근할 수 있습니다.

IAM 역할 생성

1️⃣ IAM 서비스로 이동

  • AWS Console 검색창에 "IAM" 입력
  • 좌측 메뉴에서 "역할" 클릭
  • "역할 생성" 버튼 클릭

2️⃣ 신뢰할 수 있는 엔터티 선택

  • 신뢰할 수 있는 엔터티 유형: "AWS 서비스"
  • 사용 사례: "EC2" 선택
  • "다음" 클릭
📸 이미지: EC2 사용 사례 선택
(iam-role-ec2.png)

3️⃣ 권한 정책 추가

  • 검색창에 "AmazonS3FullAccess" 입력
  • AmazonS3FullAccess 체크
  • "다음" 클릭
📸 이미지: S3FullAccess 정책 선택
(iam-role-s3-policy.png)

4️⃣ 역할 이름 지정

  • 역할 이름: EC2-S3-Upload-Role
  • 설명: Role for EC2 to access S3
  • "역할 생성" 클릭

IAM 역할을 EC2에 연결

1️⃣ EC2 인스턴스 선택

  • EC2 콘솔로 이동
  • 인스턴스 목록에서 goormjpa 선택
  • "작업 (Actions)" → "보안 (Security)" → "IAM 역할 수정 (Modify IAM role)" 클릭
📸 이미지: IAM 역할 수정 메뉴
(ec2-modify-iam-role.png)

2️⃣ 역할 선택

  • IAM 역할 드롭다운에서 "EC2-S3-Upload-Role" 선택
  • "IAM 역할 업데이트" 클릭
📸 이미지: IAM 역할 선택
(ec2-attach-iam-role.png)

✅ IAM 역할 연결 완료! 이제 EC2에서 S3에 파일을 업로드할 수 있습니다.

aws s3 cp test.txt s3://goormjpa-topolo/

# 업로드 확인
aws s3 ls s3://goormjpa-topolo/

출력:

upload: ./test.txt to s3://goormjpa-topolo/test.txt

2024-01-15 12:35:20         17 test.txt

4️⃣ 파일 다운로드 테스트

# S3에서 파일 다운로드
aws s3 cp s3://goormjpa-topolo/test.txt ./downloaded-test.txt

# 내용 확인
cat downloaded-test.txt

✅ EC2 ↔ S3 연결 성공! 파일 업로드 및 다운로드가 정상 작동합니다.

8

S3 퍼블릭 액세스 설정

💡 왜 퍼블릭 액세스가 필요한가요?

사용자가 웹 브라우저에서 URL로 직접 이미지나 파일에 접근할 수 있도록 하기 위해서입니다. 예: https://버킷.s3.amazonaws.com/image.jpg

1️⃣ 퍼블릭 액세스 차단 해제

  • S3 콘솔에서 goormjpa-본인아이디 버킷 클릭
  • "권한" 탭 클릭
  • "퍼블릭 액세스 차단 (버킷 설정)" 섹션에서 "편집" 클릭
  • "모든 퍼블릭 액세스 차단" 체크 해제
  • "변경 사항 저장" 클릭
  • 확인 창에서 확인 입력 후 "확인" 클릭
📸 이미지: 퍼블릭 액세스 차단 해제
(s3-public-access.png)

2️⃣ 버킷 정책 편집

  • 같은 "권한" 탭에서 "버킷 정책" 섹션의 "편집" 클릭
  • 아래 JSON을 붙여넣기 (버킷 이름을 본인의 것으로 변경!)
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::goormjpa-topolo/*"
        }
    ]
}

⚠️ goormjpa-topolo를 본인의 버킷 이름으로 변경하세요!

  • "변경 사항 저장" 클릭
📸 이미지: 버킷 정책 편집
(s3-bucket-policy.png)

3️⃣ URL로 접근 테스트

웹 브라우저에서 다음 URL로 접근:

https://goormjpa-topolo.s3.amazonaws.com/test.txt

(버킷 이름을 본인의 것으로 변경)

✅ "Hello from EC2!"가 표시되면 성공입니다!

✅ S3 퍼블릭 액세스 설정 완료! 이제 누구나 URL로 파일에 접근할 수 있습니다.

RDS 외부 접근 설정

💡 왜 외부 접근이 필요한가요?

로컬 PC의 DBeaver, MySQL Workbench 등 DB 클라이언트로 RDS에 직접 접속하여 데이터를 확인하고 관리하기 위해서입니다.

1️⃣ 본인의 공인 IP 확인

  • 웹 브라우저에서 https://www.myip.com/ 또는 https://checkip.amazonaws.com/ 접속
  • 표시된 IP 주소 복사 (예: 123.45.67.89)

⚠️ 회사/집의 공유기를 사용하면 IP가 변경될 수 있습니다. 접속이 안 되면 IP를 다시 확인하세요!

2️⃣ RDS 보안 그룹 확인

  • RDS 콘솔에서 goormjpa-db 클릭
  • "연결 & 보안" 탭에서 "VPC 보안 그룹" 클릭
  • 보안 그룹 페이지로 이동
📸 이미지: RDS 보안 그룹
(rds-security-group.png)

3️⃣ 인바운드 규칙 추가

  • "인바운드 규칙" 탭 클릭
  • "인바운드 규칙 편집" 클릭
  • "규칙 추가" 클릭
  • 다음과 같이 입력:
    • • 유형: MYSQL/Aurora (포트 3306 자동 입력)
    • • 소스: 내 IP 또는 사용자 지정
    • • IP: 123.45.67.89/32 (본인 IP/32)
  • "규칙 저장" 클릭
📸 이미지: 인바운드 규칙 추가
(rds-inbound-rule.png)

4️⃣ 로컬 PC에서 접속 테스트

로컬 PC 터미널에서:

# MariaDB 클라이언트가 없다면 설치 (Mac)
brew install mariadb

# MariaDB 클라이언트가 없다면 설치 (Ubuntu/Debian)
sudo apt install mariadb-client

# RDS 접속 (엔드포인트를 본인의 것으로 변경)
mysql -h goormjpa-db.cxscca6ucgpu.ap-northeast-2.rds.amazonaws.com -u admin -p

# 암호 입력: goorm_rdb_password

접속 성공 시:

MariaDB [(none)]> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| goormjpa           |
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+

✅ RDS 외부 접근 설정 완료! 로컬 PC에서 RDS에 직접 접속할 수 있습니다.
