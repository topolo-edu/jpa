Step 3: 수동 배포

JAR, Docker, Docker Compose를 이용한 EC2 배포

사전 준비 사항

  • Step 1 완료: AWS 계정 생성 및 CLI 설치
  • Step 2 완료: EC2, RDS, S3 환경 구축
  • EC2 SSH 접속 가능 (goormjpa.pem)

배포 방식 비교

구분 JAR Docker Compose
난이도 쉬움 보통 어려움
환경 일관성 낮음 높음 매우 높음
권장 사용처 개발/테스트 단일 앱 복잡한 구성

Part 1: JAR 파일 배포

1. 로컬에서 JAR 빌드

application.yml에 AWS RDS 엔드포인트 설정

spring:
  datasource:
    url: jdbc:mariadb://goormjpa-db.xxxxx.ap-northeast-2.rds.amazonaws.com:3306/goormjpa
    username: admin
    password: goorm_rdb_password

cloud:
  aws:
    credentials:
      instanceProfile: true
    region:
      static: ap-northeast-2
    s3:
      bucket: goormjpa-yourname

빌드 명령어:

# Windows
.\gradlew clean build

# macOS/Linux
./gradlew clean build

→ build/libs/goormjpa-0.0.1-SNAPSHOT.jar 생성

2. EC2로 JAR 파일 업로드

# Windows
scp -i goormjpa.pem .\build\libs\goormjpa-0.0.1-SNAPSHOT.jar ubuntu@EC2_IP:/home/ubuntu/

# macOS/Linux
scp -i ~/Downloads/goormjpa.pem ./build/libs/goormjpa-0.0.1-SNAPSHOT.jar ubuntu@EC2_IP:/home/ubuntu/

3. EC2에 Java 설치

ssh -i goormjpa.pem ubuntu@EC2_IP

sudo apt update
sudo apt install openjdk-17-jdk -y

java -version

4. JAR 실행

포그라운드 실행 (테스트용):

java -jar goormjpa-0.0.1-SNAPSHOT.jar

백그라운드 실행 (권장):

nohup java -jar goormjpa-0.0.1-SNAPSHOT.jar > app.log 2>&1 &

# 로그 확인
tail -f app.log

# 중지
pkill -f goormjpa

5. 보안 그룹 설정

AWS 콘솔 → EC2 → 보안 그룹 → 인바운드 규칙 추가:

  • 유형: 사용자 지정 TCP
  • 포트: 8080
  • 소스: 0.0.0.0/0 (또는 My IP)

6. 접속 테스트

브라우저: http://EC2_IP:8080

Part 2: Docker 배포

1. Dockerfile 작성

프로젝트 루트에 Dockerfile 생성:

# 빌드 단계
FROM gradle:8.5-jdk17 AS build
WORKDIR /app
COPY . .
RUN gradle clean build -x test

# 실행 단계
FROM openjdk:17-jdk-slim
WORKDIR /app
COPY --from=build /app/build/libs/goormjpa-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

2. .dockerignore 작성

.git
.gradle
build
*.md

3. 로컬에서 이미지 빌드

docker build -t goormjpa-app .
docker images

4. 이미지 EC2로 전송

# 이미지 저장
docker save goormjpa-app:latest -o goormjpa-app.tar

# EC2로 전송
scp -i goormjpa.pem goormjpa-app.tar ubuntu@EC2_IP:/home/ubuntu/

5. EC2에 Docker 설치

ssh -i goormjpa.pem ubuntu@EC2_IP

sudo apt update
sudo apt install docker.io -y
sudo systemctl start docker
sudo systemctl enable docker

# 권한 설정
sudo usermod -aG docker $USER
exit
# 재접속

6. 이미지 로드 및 실행

# 이미지 로드
docker load -i goormjpa-app.tar

# 컨테이너 실행
docker run -d \
  --name goormjpa-container \
  -p 8080:8080 \
  --restart unless-stopped \
  goormjpa-app:latest

# 로그 확인
docker logs -f goormjpa-container

7. 컨테이너 관리 명령어

docker ps                              # 실행 중인 컨테이너
docker stop goormjpa-container         # 중지
docker start goormjpa-container        # 시작
docker restart goormjpa-container      # 재시작
docker rm -f goormjpa-container        # 삭제

Part 3: Docker Compose 배포

1. docker-compose.yml 작성

version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    image: goormjpa-app:latest
    container_name: goormjpa-app
    ports:
      - "8080:8080"
    restart: unless-stopped
    networks:
      - goormjpa-network

networks:
  goormjpa-network:
    driver: bridge

2. EC2로 프로젝트 전송

# 압축
tar -czf goormjpa.tar.gz --exclude='.git' --exclude='build' .

# 전송
scp -i goormjpa.pem goormjpa.tar.gz ubuntu@EC2_IP:/home/ubuntu/

3. EC2에 Docker Compose 설치

sudo apt install docker-compose-plugin -y
docker compose version

4. 실행

tar -xzf goormjpa.tar.gz
cd goormjpa

docker compose up -d --build
docker compose logs -f

5. 관리 명령어

docker compose ps          # 상태 확인
docker compose stop        # 중지
docker compose start       # 시작
docker compose restart     # 재시작
docker compose down        # 중지 및 삭제

트러블슈팅

포트 8080이 이미 사용 중

sudo lsof -i :8080
sudo kill -9 PID번호

Docker 빌드 시 메모리 부족 (t2.micro)

# 스왑 메모리 추가
sudo dd if=/dev/zero of=/swapfile bs=128M count=16
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

RDS 연결 실패

  • EC2와 RDS가 같은 VPC에 있는지 확인
  • RDS 보안 그룹에서 EC2 보안 그룹 허용 확인
  • application.yml의 엔드포인트 주소 확인
