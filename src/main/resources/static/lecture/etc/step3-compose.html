3단계: Docker Compose 멀티 컨테이너

여러 컨테이너를 하나의 서비스로 통합 관리

개요 1단계: 로컬 2단계: Dockerfile 3단계: Compose 4단계: AWS 5단계: CI/CD

학습 목표

여러 컨테이너를 하나의 서비스로 통합 관리하여 복잡한 애플리케이션 스택을 쉽게 배포하고 관리합니다.

  • • 애플리케이션 + 데이터베이스 컨테이너
  • • 네트워크 및 볼륨 관리
  • • Nginx 리버스 프록시 설정
  • • 서비스 간 의존성 관리

1. Docker Compose 기본 개념

1

Docker Compose란?

여러 컨테이너로 구성된 애플리케이션을 정의하고 실행하는 도구입니다.

주요 구성 요소

  • • Services: 컨테이너 정의
  • • Networks: 컨테이너 간 통신
  • • Volumes: 데이터 영속성
  • • Environment: 환경변수 설정

장점

  • • 단순한 명령어: docker compose up
  • • 의존성 관리: 서비스 간 순서 제어
  • • 설정 중앙화: YAML 파일로 관리
  • • 확장성: 쉽게 서비스 추가/제거

2. docker-compose.yml 작성

2

기본 구성 파일

애플리케이션과 데이터베이스를 포함한 기본 구성입니다.

# docker-compose.yml
version: '3.8'

services:
  # 애플리케이션 서비스
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - SPRING_DATASOURCE_URL=jdbc:mariadb://db:3306/jpa
      - SPRING_DATASOURCE_USERNAME=jpa_user
      - SPRING_DATASOURCE_PASSWORD=jpa_password
    depends_on:
      - db
    networks:
      - jpa-network

  # 데이터베이스 서비스
  db:
    image: mariadb:10.6
    environment:
      - MYSQL_ROOT_PASSWORD=root_password
      - MYSQL_DATABASE=jpa
      - MYSQL_USER=jpa_user
      - MYSQL_PASSWORD=jpa_password
    volumes:
      - db_data:/var/lib/mysql
    ports:
      - "3306:3306"
    networks:
      - jpa-network

# 네트워크 정의
networks:
  jpa-network:
    driver: bridge

# 볼륨 정의
volumes:
  db_data:

3. Nginx 리버스 프록시 추가

3

Nginx 설정 파일

Nginx를 리버스 프록시로 사용하여 요청을 애플리케이션으로 전달합니다.

nginx.conf

# nginx/nginx.conf
events {
    worker_connections 1024;
}

http {
    upstream app {
        server app:8080;
    }

    server {
        listen 80;
        server_name localhost;

        location / {
            proxy_pass http://app;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        # 정적 파일 캐싱
        location ~* \.(css|js|png|jpg|jpeg|gif|ico|svg)$ {
            proxy_pass http://app;
            expires 1y;
            add_header Cache-Control "public, immutable";
        }
    }
}

업데이트된 docker-compose.yml

# docker-compose.yml (Nginx 포함)
version: '3.8'

services:
  # Nginx 리버스 프록시
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
    depends_on:
      - app
    networks:
      - jpa-network

  # 애플리케이션 서비스
  app:
    build: .
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - SPRING_DATASOURCE_URL=jdbc:mariadb://db:3306/jpa
      - SPRING_DATASOURCE_USERNAME=jpa_user
      - SPRING_DATASOURCE_PASSWORD=jpa_password
    depends_on:
      - db
    networks:
      - jpa-network

  # 데이터베이스 서비스
  db:
    image: mariadb:10.6
    environment:
      - MYSQL_ROOT_PASSWORD=root_password
      - MYSQL_DATABASE=jpa
      - MYSQL_USER=jpa_user
      - MYSQL_PASSWORD=jpa_password
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - jpa-network

networks:
  jpa-network:
    driver: bridge

volumes:
  db_data:

4. 환경별 설정

4

환경변수 파일 분리

개발, 테스트, 운영 환경별로 설정을 분리합니다.

.env 파일

# .env
COMPOSE_PROJECT_NAME=jpa
SPRING_PROFILES_ACTIVE=prod
DB_ROOT_PASSWORD=root_password
DB_NAME=jpa
DB_USER=jpa_user
DB_PASSWORD=jpa_password

환경변수 사용하는 docker-compose.yml

# docker-compose.yml
version: '3.8'

services:
  app:
    build: .
    environment:
      - SPRING_PROFILES_ACTIVE=${SPRING_PROFILES_ACTIVE}
      - SPRING_DATASOURCE_URL=jdbc:mariadb://db:3306/${DB_NAME}
      - SPRING_DATASOURCE_USERNAME=${DB_USER}
      - SPRING_DATASOURCE_PASSWORD=${DB_PASSWORD}
    depends_on:
      - db
    networks:
      - jpa-network

  db:
    image: mariadb:10.6
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_ROOT_PASSWORD}
      - MYSQL_DATABASE=${DB_NAME}
      - MYSQL_USER=${DB_USER}
      - MYSQL_PASSWORD=${DB_PASSWORD}
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - jpa-network

networks:
  jpa-network:
    driver: bridge

volumes:
  db_data:

5. Docker Compose 명령어

5

기본 명령어

Docker Compose를 사용하여 서비스를 관리합니다.

서비스 실행

# 서비스 시작 (백그라운드)
docker compose up -d

# 서비스 시작 (포그라운드)
docker compose up

# 특정 서비스만 시작
docker compose up app db

# 이미지 빌드 후 시작
docker compose up --build

# 강제 재빌드
docker compose build --no-cache

서비스 관리

# 서비스 중지
docker compose down

# 서비스 중지 (볼륨 포함)
docker compose down -v

# 서비스 재시작
docker compose restart

# 특정 서비스 재시작
docker compose restart app

# 서비스 상태 확인
docker compose ps

# 서비스 로그 확인
docker compose logs -f app

6. 볼륨 및 데이터 관리

6

데이터 영속성

컨테이너가 삭제되어도 데이터가 유지되도록 볼륨을 설정합니다.

볼륨 타입

# docker-compose.yml
version: '3.8'

services:
  app:
    build: .
    volumes:
      # 호스트 디렉토리 마운트
      - ./logs:/app/logs
      # 명명된 볼륨 사용
      - app_data:/app/data
    networks:
      - jpa-network

  db:
    image: mariadb:10.6
    volumes:
      # 데이터베이스 데이터 영속성
      - db_data:/var/lib/mysql
      # 초기 데이터 스크립트
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - jpa-network

volumes:
  # 명명된 볼륨 정의
  db_data:
  app_data:

볼륨 관리 명령어

# 볼륨 목록 확인
docker volume ls

# 볼륨 상세 정보
docker volume inspect jpa_db_data

# 볼륨 삭제
docker volume rm jpa_db_data

# 모든 볼륨 삭제
docker volume prune

7. 헬스체크 및 모니터링

7

서비스 상태 모니터링

각 서비스의 상태를 확인하고 자동 복구를 설정합니다.

# docker-compose.yml (헬스체크 포함)
version: '3.8'

services:
  app:
    build: .
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - SPRING_DATASOURCE_URL=jdbc:mariadb://db:3306/jpa
    depends_on:
      db:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    restart: unless-stopped
    networks:
      - jpa-network

  db:
    image: mariadb:10.6
    environment:
      - MYSQL_ROOT_PASSWORD=root_password
      - MYSQL_DATABASE=jpa
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 30s
    restart: unless-stopped
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - jpa-network

networks:
  jpa-network:
    driver: bridge

volumes:
  db_data:

8. 스케일링

8

서비스 확장

애플리케이션 인스턴스를 여러 개 실행하여 부하를 분산합니다.

# 애플리케이션 인스턴스 3개 실행
docker compose up --scale app=3

# 특정 서비스만 스케일링
docker compose up -d --scale app=3

# 스케일링 상태 확인
docker compose ps

# 로드 밸런싱 테스트
curl http://localhost:8080/api/courses
