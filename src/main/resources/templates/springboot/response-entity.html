ResponseEntity 완벽 가이드

HTTP 응답을 세밀하게 제어하는 ResponseEntity의 모든 것

ResponseEntity란?

ResponseEntity는 HTTP 응답의 상태 코드, 헤더, 바디를 모두 제어할 수 있는 Spring의 클래스입니다.

구성 요소

  • 상태 코드 (Status Code): 200 OK, 404 Not Found, 500 Error 등
  • 헤더 (Headers): Content-Type, Authorization, Custom Headers 등
  • 바디 (Body): 실제 응답 데이터 (JSON, XML 등)

일반 반환 

@GetMapping("/orders/{id}")
public Order getOrder(@PathVariable Long id) {
    return orderService.findById(id);
    // 상태 코드: 항상 200 OK
    // 헤더: 기본값만
}
제한: 상태 코드, 헤더 커스터마이징 불가

ResponseEntity 반환 

@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    Order order = orderService.findById(id);
    return ResponseEntity.ok(order);
    // 상태 코드: 원하는 대로 설정 가능
    // 헤더: 추가 가능
}
유연성: 모든 HTTP 응답 요소 제어 가능

기본 사용법

1️⃣ 간단한 성공 응답

// 200 OK + 데이터 반환
@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    Order order = orderService.findById(id);
    return ResponseEntity.ok(order);
}

2️⃣ 생성 성공 응답 (201 Created)

@PostMapping("/orders")
public ResponseEntity<Order> createOrder(@RequestBody OrderRequest request) {
    Order order = orderService.create(request);
    return ResponseEntity
        .status(HttpStatus.CREATED)  // 201
        .body(order);
}

// 또는 간단하게
return ResponseEntity.status(201).body(order);

3️⃣ 삭제 성공 (204 No Content)

@DeleteMapping("/orders/{id}")
public ResponseEntity<Void> deleteOrder(@PathVariable Long id) {
    orderService.delete(id);
    return ResponseEntity.noContent().build();  // 204, 바디 없음
}

4️⃣ 에러 응답

@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    Optional<Order> order = orderService.findById(id);

    if (order.isEmpty()) {
        return ResponseEntity.notFound().build();  // 404
    }

    return ResponseEntity.ok(order.get());  // 200
}

주요 HTTP 상태 코드

2xx 성공

200 OK

요청 성공

ResponseEntity.ok()
201 Created

리소스 생성됨

ResponseEntity.status(201)
204 No Content

성공했지만 반환 데이터 없음

ResponseEntity.noContent()

4xx 클라이언트 에러

400 Bad Request

잘못된 요청

ResponseEntity.badRequest()
401 Unauthorized

인증 필요

ResponseEntity.status(401)
403 Forbidden

권한 없음

ResponseEntity.status(403)
404 Not Found

리소스 없음

ResponseEntity.notFound()

5xx 서버 에러

500 Internal Server Error

서버 내부 오류

ResponseEntity.status(500)
503 Service Unavailable

서비스 이용 불가

ResponseEntity.status(503)

헤더 추가하기

1️⃣ Location 헤더 (리소스 생성 시)

@PostMapping("/orders")
public ResponseEntity<Order> createOrder(@RequestBody OrderRequest request) {
    Order order = orderService.create(request);

    URI location = ServletUriComponentsBuilder
        .fromCurrentRequest()
        .path("/{id}")
        .buildAndExpand(order.getId())
        .toUri();

    return ResponseEntity
        .created(location)  // 201 + Location 헤더
        .body(order);
}

// 응답 헤더:
// Location: http://localhost:8080/api/orders/123

2️⃣ 커스텀 헤더 추가

@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    Order order = orderService.findById(id);

    return ResponseEntity.ok()
        .header("X-Custom-Header", "custom-value")
        .header("X-Total-Count", "100")
        .body(order);
}

3️⃣ HttpHeaders 객체 사용

@GetMapping("/orders")
public ResponseEntity<List<Order>> getOrders() {
    List<Order> orders = orderService.findAll();

    HttpHeaders headers = new HttpHeaders();
    headers.add("X-Total-Count", String.valueOf(orders.size()));
    headers.add("X-Page-Number", "1");
    headers.setCacheControl(CacheControl.maxAge(60, TimeUnit.SECONDS));

    return ResponseEntity.ok()
        .headers(headers)
        .body(orders);
}

빌더 패턴 활용

ResponseEntity는 빌더 패턴을 제공하여 유창한(fluent) 방식으로 응답을 구성할 수 있습니다. 

@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    Order order = orderService.findById(id);

    return ResponseEntity
        .status(HttpStatus.OK)                    // 상태 코드
        .header("X-Custom-Header", "value")   // 헤더 추가
        .contentType(MediaType.APPLICATION_JSON) // Content-Type
        .cacheControl(CacheControl.maxAge(60, TimeUnit.SECONDS)) // 캐시
        .body(order);                            // 응답 바디
}

실무 패턴

패턴 1 ApiResponse 래퍼 클래스

일관된 API 응답 형식을 위한 래퍼 클래스

// ApiResponse.java
public record ApiResponse<T>(
    boolean success,
    String message,
    T data,
    String errorCode
) {
    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(true, "Success", data, null);
    }

    public static <T> ApiResponse<T> error(String message, String errorCode) {
        return new ApiResponse<>(false, message, null, errorCode);
    }
}
// Controller에서 사용
@GetMapping("/orders/{id}")
public ResponseEntity<ApiResponse<Order>> getOrder(@PathVariable Long id) {
    Order order = orderService.findById(id);
    return ResponseEntity.ok(ApiResponse.success(order));
}

// 응답 예시:
// {
//   "success": true,
//   "message": "Success",
//   "data": { "id": 1, "customerName": "홍길동" },
//   "errorCode": null
// }

패턴 2 Optional 우아하게 처리하기 

@GetMapping("/orders/{id}")
public ResponseEntity<Order> getOrder(@PathVariable Long id) {
    return orderService.findById(id)
        .map(ResponseEntity::ok)          // 있으면 200 OK
        .orElse(ResponseEntity.notFound().build());  // 없으면 404
}

// 또는 orElseGet 사용
return orderService.findById(id)
    .map(order -> ResponseEntity.ok()
        .header("X-Order-Status", order.getStatus())
        .body(order))
    .orElseGet(() -> ResponseEntity.notFound().build());

패턴 3 조건부 응답 처리 

@PutMapping("/orders/{id}")
public ResponseEntity<ApiResponse<Order>> updateOrder(
        @PathVariable Long id,
        @RequestBody OrderRequest request) {

    try {
        Order order = orderService.update(id, request);
        return ResponseEntity.ok(ApiResponse.success(order));

    } catch (OrderNotFoundException e) {
        return ResponseEntity
            .status(HttpStatus.NOT_FOUND)
            .body(ApiResponse.error(e.getMessage(), "ORDER_NOT_FOUND"));

    } catch (InvalidOrderStatusException e) {
        return ResponseEntity
            .status(HttpStatus.BAD_REQUEST)
            .body(ApiResponse.error(e.getMessage(), "INVALID_STATUS"));
    }
}

실무 권장사항

✅ 이렇게 하세요

  • 의미 있는 상태 코드 사용
    201 Created, 204 No Content
  • 리소스 생성 시 Location 헤더
    .created(location)
  • 일관된 응답 형식 유지
    ApiResponse 래퍼 클래스
  • 에러 응답에 에러 코드 포함
    errorCode: "ORDER_NOT_FOUND"

❌ 피해야 할 것

  • 모든 응답에 200 OK 사용
    에러도 200 반환
  • 상태 코드와 메시지 불일치
    200 + "Error occurred"
  • 불필요한 헤더 남발
    의미 없는 커스텀 헤더 추가
  • 응답 형식 불일치
    API마다 다른 형식

완전한 실전 예제 

@RestController
@RequestMapping("/api/orders")
@RequiredArgsConstructor
public class OrderController {

    private final OrderService orderService;

    // 1. 목록 조회 - 200 OK + 헤더
    @GetMapping
    public ResponseEntity<ApiResponse<List<Order>>> getOrders() {
        List<Order> orders = orderService.findAll();

        return ResponseEntity.ok()
            .header("X-Total-Count", String.valueOf(orders.size()))
            .body(ApiResponse.success(orders));
    }

    // 2. 단건 조회 - 200 OK or 404 Not Found
    @GetMapping("/{id}")
    public ResponseEntity<ApiResponse<Order>> getOrder(@PathVariable Long id) {
        return orderService.findById(id)
            .map(order -> ResponseEntity.ok(ApiResponse.success(order)))
            .orElse(ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(ApiResponse.error("주문을 찾을 수 없습니다", "ORDER_NOT_FOUND")));
    }

    // 3. 생성 - 201 Created + Location 헤더
    @PostMapping
    public ResponseEntity<ApiResponse<Order>> createOrder(
            @Valid @RequestBody OrderRequest request) {

        Order order = orderService.create(request);

        URI location = ServletUriComponentsBuilder
            .fromCurrentRequest()
            .path("/{id}")
            .buildAndExpand(order.getId())
            .toUri();

        return ResponseEntity
            .created(location)
            .body(ApiResponse.success(order));
    }

    // 4. 수정 - 200 OK
    @PutMapping("/{id}")
    public ResponseEntity<ApiResponse<Order>> updateOrder(
            @PathVariable Long id,
            @Valid @RequestBody OrderRequest request) {

        Order order = orderService.update(id, request);
        return ResponseEntity.ok(ApiResponse.success(order));
    }

    // 5. 삭제 - 204 No Content
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteOrder(@PathVariable Long id) {
        orderService.delete(id);
        return ResponseEntity.noContent().build();
    }
}

핵심 요약

ResponseEntity 구성 요소

  • • 상태 코드 (Status Code)
  • • 헤더 (Headers)
  • • 바디 (Body)

주요 메서드

  • • .ok() - 200 OK
  • • .created(location) - 201 Created
  • • .noContent() - 204 No Content
  • • .notFound() - 404 Not Found

실무 패턴

  • • ApiResponse 래퍼 클래스
  • • Optional 우아한 처리
