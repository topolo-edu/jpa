Repository 레이어

데이터베이스 접근을 담당하는 Repository의 JPA와 MyBatis 방식을 비교합니다

JPA vs MyBatis

JPA (Spring Data JPA)

SQL 자동 생성: 쿼리 작성 불필요
객체 지향적: Entity 중심 개발
DB 독립성: DB 변경 쉬움
러닝 커브: 개념 이해 필요
복잡한 쿼리: JPQL/QueryDSL 필요
추천: 새 프로젝트, 도메인 중심 설계

MyBatis

SQL 직접 작성: 세밀한 제어 가능
복잡한 쿼리: 조인, 서브쿼리 자유롭게
러닝 커브: SQL만 알면 OK
반복 작업: CRUD SQL 수동 작성
DB 종속성: DB 변경 시 SQL 수정
추천: 레거시 시스템, 복잡한 SQL 필요

예제: JPA Repository 

@Repository
public interface OrderRepository extends JpaRepository<Order, Long> {

    // 1. 기본 제공 메서드 (구현 불필요)
    // - save(order)           // INSERT or UPDATE
    // - findById(id)          // SELECT by PK
    // - findAll()             // SELECT ALL
    // - delete(order)         // DELETE
    // - count()               // COUNT(*)
    // - existsById(id)        // EXISTS

    // 2. 메서드 이름으로 쿼리 자동 생성
    List<Order> findByCustomerName(String customerName);
    // SELECT * FROM orders WHERE customer_name = ?

    List<Order> findByCustomerNameContaining(String keyword);
    // SELECT * FROM orders WHERE customer_name LIKE %?%

    List<Order> findByStatusAndOrderDateAfter(OrderStatus status, LocalDateTime date);
    // SELECT * FROM orders WHERE status = ? AND order_date > ?

    List<Order> findByCustomerNameOrderByOrderDateDesc(String name);
    // SELECT * FROM orders WHERE customer_name = ? ORDER BY order_date DESC

    // 3. @Query로 JPQL 직접 작성
    @Query("SELECT o FROM Order o WHERE o.customerName LIKE %:keyword%")
    List<Order> searchByKeyword(@Param("keyword") String keyword);

    // 4. Fetch Join으로 N+1 해결
    @Query("SELECT o FROM Order o JOIN FETCH o.items WHERE o.id = :id")
    Optional<Order> findByIdWithItems(@Param("id") Long id);

    // 5. 네이티브 SQL 사용
    @Query(value = "SELECT * FROM orders WHERE customer_name = ?1",
           nativeQuery = true)
    List<Order> findByNameNative(String name);

    // 6. 수정/삭제 쿼리
    @Modifying
    @Query("UPDATE Order o SET o.status = :status WHERE o.id = :id")
    int updateStatus(@Param("id") Long id, @Param("status") OrderStatus status);

    // 7. 페이징 처리
    Page<Order> findByStatus(OrderStatus status, Pageable pageable);
}

예제: MyBatis Mapper

Java Interface

@Mapper
public interface OrderMapper {

    // 1. 전체 조회
    List<Order> findAll();

    // 2. ID로 조회
    Order findById(Long id);

    // 3. 이름으로 검색
    List<Order> findByCustomerName(String name);

    // 4. 생성
    void insert(Order order);

    // 5. 수정
    void update(Order order);

    // 6. 삭제
    void delete(Long id);

    // 7. 동적 쿼리 (조건부 검색)
    List<Order> searchOrders(OrderSearchDto dto);
}

XML Mapper (src/main/resources/mapper/OrderMapper.xml)

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.example.demo.repository.OrderMapper">

    <!-- 1. 전체 조회 -->
    <select id="findAll" resultType="Order">
        SELECT * FROM orders
    </select>

    <!-- 2. ID로 조회 -->
    <select id="findById" resultType="Order">
        SELECT * FROM orders WHERE id = #{id}
    </select>

    <!-- 3. 이름으로 검색 -->
    <select id="findByCustomerName" resultType="Order">
        SELECT * FROM orders WHERE customer_name LIKE CONCAT('%', #{name}, '%')
    </select>

    <!-- 4. 생성 -->
    <insert id="insert" parameterType="Order"
            useGeneratedKeys="true" keyProperty="id">
        INSERT INTO orders (customer_name, order_date, status)
        VALUES (#{customerName}, #{orderDate}, #{status})
    </insert>

    <!-- 5. 수정 -->
    <update id="update" parameterType="Order">
        UPDATE orders
        SET customer_name = #{customerName},
            status = #{status}
        WHERE id = #{id}
    </update>

    <!-- 6. 삭제 -->
    <delete id="delete">
        DELETE FROM orders WHERE id = #{id}
    </delete>

    <!-- 7. 동적 쿼리 (조건부 검색) -->
    <select id="searchOrders" resultType="Order">
        SELECT * FROM orders
        <where>
            <if test="name != null">
                AND customer_name LIKE CONCAT('%', #{name}, '%')
            </if>
            <if test="status != null">
                AND status = #{status}
            </if>
        </where>
    </select>

</mapper>

JPA Repository 어노테이션

어노테이션 설명 예시
@Repository Repository 컴포넌트 선언
생략 가능 (JpaRepository 상속 시)		 @Repository public interface OrderRepo { }
@Query JPQL 또는 네이티브 SQL 작성
복잡한 쿼리 직접 작성		 @Query("SELECT o FROM Order o")
@Param JPQL 파라미터 바인딩
:name 형태의 이름 기반 파라미터		 @Param("name") String name
@Modifying UPDATE/DELETE 쿼리 실행
@Query와 함께 사용, 반환값은 int		 @Modifying @Query("UPDATE...")
@EntityGraph Fetch Join 간소화
연관 엔티티 한 번에 조회		 @EntityGraph(attributePaths = "items")

MyBatis 어노테이션

어노테이션 설명 예시
@Mapper MyBatis Mapper 인터페이스 선언
필수 어노테이션		 @Mapper public interface OrderMapper { }

간단한 쿼리는 어노테이션으로		 @Select("SELECT * FROM orders")

@Update UPDATE 쿼리

JPA Repository 기본 제공 메서드

JpaRepository<Order, Long>를 상속하면 기본 CRUD 메서드를 자동으로 사용할 수 있습니다.

저장 / 수정

save(order)
// INSERT or UPDATE (ID 존재 여부로 판단)
saveAll(orders)
// 여러 엔티티 한 번에 저장
flush()
// 영속성 컨텍스트 DB 동기화

조회

findById(id)
// ID로 단건 조회 (Optional 반환)
findAll()
// 전체 조회
findAllById(ids)
// ID 목록으로 조회
findAll(pageable)
// 페이징 조회

삭제

delete(order)
// 엔티티 삭제
deleteById(id)
// ID로 삭제
deleteAll()
// 전체 삭제
deleteAllInBatch()
// 배치 삭제 (성능 최적화)

유틸리티

count()
// 전체 개수 (COUNT)
existsById(id)
// 존재 여부 확인 (boolean)
getById(id)
// 프록시 반환 (지연 로딩)
getReferenceById(id)
// 레퍼런스만 반환 (실제 조회 지연)

실무 팁

JPA 사용 시

  • • 메서드 네이밍: findBy, existsBy 등 규칙 활용
  • • Fetch Join: N+1 문제 반드시 해결
  • • @Query 활용: 복잡한 쿼리는 직접 작성
  • • DTO 프로젝션: 필요한 필드만 조회

MyBatis 사용 시

  • • 동적 쿼리: <if>, <choose> 적극 활용
  • • 재사용성: <sql>로 공통 쿼리 분리
  • • ResultMap: 복잡한 매핑은 resultMap 사용
  • • 배치 처리: foreach로 대량 INSERT
