Step 1 vs Step 2 비교

Step 1 (기존)

  • N:1 + N:1 (단방향)
  • 팝업 방식 API
  • Service에 비즈니스 로직 분산
  • 수동 데이터 관리
  • 통계 기능 없음
  • 낙관적 락만

Step 2 (개선)

  • N:1 + 1:N (양방향)
  • 직접 접근 가능
  • 엔티티에 비즈니스 로직 캡슐화
  • Cascade 자동화
  • QueryDSL 통계
  • 낙관적 + 비관적 락

주요 구현 기능

양방향 관계

  • Course ↔ Curriculum
  • Course ↔ Enrollment
  • User ↔ Enrollment
  • 편의 메서드 구현

비관적 락

  • @Lock(PESSIMISTIC_WRITE)
  • 수강신청 동시성 제어
  • 승인/거절 동시성 제어
  • 강의 수정/삭제 동시성 제어

QueryDSL 통계

  • 강의별 상세 통계
  • 강사별 강의 통계
  • 월별 개설 통계
  • 공통 조건 모듈

배치 처리

  • 수강신청 일괄 승인/거절
  • 강의별 일괄 처리
  • 처리 결과 추적
  • 에러 핸들링

@EntityGraph

  • JPQL Fetch Join 간소화
  • 코드 가독성 향상
  • 유지보수성 개선
  • N+1 문제 해결

Cascade & Orphan

  • CascadeType.ALL
  • orphanRemoval = true
  • 자동 데이터 관리
  • 고아 객체 자동 삭제
