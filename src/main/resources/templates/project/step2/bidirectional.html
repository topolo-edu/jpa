양방향 관계와 편의 메서드

Aggregate 패턴 기반 양방향 관계 설계

목록으로

양방향 vs 단방향: 언제 무엇을 사용할까?

핵심 원칙: Aggregate 패턴

Aggregate 내부 관계: 양방향 + Cascade 권장 (생명주기 밀접 관리)

Aggregate 간 관계: 단방향 기본 (Repository로 역방향 조회)

✅ 양방향 (Aggregate 내부)

Course ↔ Curriculum

  • • Course가 Curriculum 생명주기 관리
  • • Course 삭제 시 Curriculum도 삭제
  • • 편의 메서드로 관계 동기화

⚡ 단방향 (Aggregate 간)

Enrollment → User/Course

  • • 독립적인 생명주기
  • • Repository로 역방향 조회 가능
  • • 불필요한 컬렉션 제거

Course ↔ Curriculum 양방향 관계

핵심 설계

// Course.java - OneToMany (부모) @OneToMany(mappedBy = "course", cascade = CascadeType.ALL, orphanRemoval = true) private List<Curriculum> curriculums = new ArrayList<>();
// Curriculum.java - ManyToOne (자식, FK 보유) @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "course_no") private Course course;

편의 메서드 (양방향 동기화)

// Course.java public void addCurriculum(Curriculum curriculum) { curriculums.add(curriculum); curriculum.setCourse(this); // 양방향 동기화 } public void removeCurriculum(Curriculum curriculum) { curriculums.remove(curriculum); curriculum.setCourse(null); // 관계 해제 }

⚠️ 중요: 양방향 관계에서는 편의 메서드로 양쪽을 동시에 설정해야 합니다.

Enrollment → User/Course 단방향 관계

단방향만으로 충분한 이유

// Enrollment.java - ManyToOne만 정의 @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "student_no") private User student; @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "course_no") private Course course;
// User.java, Course.java - OneToMany 없음! // enrollments 컬렉션 제거됨

역방향 조회: Repository 메서드

// EnrollmentRepository.java List<Enrollment> findByStudent(User student); List<Enrollment> findByCourse(Course course); // Service에서 사용 List<Enrollment> myEnrollments = enrollmentRepository.findByStudent(currentUser);

💡 장점: 필요할 때만 쿼리, 불필요한 컬렉션 관리 제거, 메모리 효율 향상

Cascade와 Orphan Removal

CascadeType.ALL

부모의 모든 작업이 자식에게 전파

courseRepository.delete(course); // → 연관된 모든 Curriculum 삭제

orphanRemoval = true

고아 객체 자동 삭제

course.removeCurriculum(c); // → c가 DB에서 삭제됨

주의: Cascade는 Aggregate 내부에만 사용! User ↔ Enrollment에 Cascade 설정 시 User 삭제 시 모든 수강신청이 삭제됨 (위험)

양방향 vs 단방향 설계 비교

구분 양방향 (Course ↔ Curriculum) 단방향 (Enrollment → User/Course)
관계 특성 Aggregate 내부 (밀접한 생명주기) Aggregate 간 (독립적 생명주기)
컬렉션 관리 List<Curriculum> + 편의 메서드 컬렉션 없음 (메모리 효율)
역방향 조회 course.getCurriculums() enrollmentRepository.findByStudent()
Cascade ✅ ALL + orphanRemoval ❌ Cascade 없음
사용 시점 부모-자식 강한 종속 독립적인 엔티티 간 관계

양방향 관계 주의사항

❌ 무한 루프

toString, equals에서 양방향 참조 시 StackOverflow

@ToString(exclude = "curriculums")

❌ LazyInitializationException

트랜잭션 밖에서 컬렉션 접근 시 예외 발생

// fetch join으로 해결
