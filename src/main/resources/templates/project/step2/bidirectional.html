양방향 관계란?

Step 1 vs Step 2 비교

Step 1 (단방향)

  • • Course → Curriculum (N:1)
  • • Course → Enrollment (N:1)
  • • User → Enrollment (N:1)
  • • 팝업 방식 API 필요

Step 2 (양방향)

  • • Course ↔ Curriculum (N:1 + 1:N)
  • • Course ↔ Enrollment (N:1 + 1:N)
  • • User ↔ Enrollment (N:1 + 1:N)
  • • 직접 접근 가능

Course ↔ Curriculum 양방향 관계

Course 엔티티

@Entity public class Course { // 기존 필드들... @OneToMany(mappedBy = "course", cascade = CascadeType.ALL, orphanRemoval = true) private List<Curriculum> curriculums = new ArrayList<>(); // 편의 메서드 public void addCurriculum(Curriculum curriculum) { curriculums.add(curriculum); curriculum.setCourse(this); } public void removeCurriculum(Curriculum curriculum) { curriculums.remove(curriculum); curriculum.setCourse(null); } public int getCurriculumCount() { return curriculums.size(); } }

Curriculum 엔티티

@Entity public class Curriculum { // 기본 필드들 private Integer weekNumber; // 주차 private String title; // 제목 private String description; // 설명 private String materials; // 준비물 private Integer duration; // 소요 시간 (분) // Course와의 양방향 관계 @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "course_no", nullable = false) private Course course; // 양방향 관계를 위한 setter public void setCourse(Course course) { this.course = course; } }

사용 예시

// Course에서 Curriculum 직접 접근 Course course = courseRepository.findById(courseNo); List<Curriculum> curriculums = course.getCurriculums(); int count = course.getCurriculumCount(); // 편의 메서드로 관계 설정 Curriculum newCurriculum = Curriculum.builder() .title("1주차: JPA 기초") .build(); course.addCurriculum(newCurriculum);

Course ↔ Enrollment 양방향 관계

Course 엔티티 (Enrollment 추가)

@OneToMany(mappedBy = "course", cascade = CascadeType.ALL, orphanRemoval = true) private List<Enrollment> enrollments = new ArrayList<>(); // Enrollment 편의 메서드 public void addEnrollment(Enrollment enrollment) { enrollments.add(enrollment); enrollment.setCourse(this); this.currentStudents++; } public void removeEnrollment(Enrollment enrollment) { enrollments.remove(enrollment); enrollment.setCourse(null); if (this.currentStudents > 0) { this.currentStudents--; } } public boolean isEnrolledBy(User student) { return enrollments.stream() .anyMatch(enrollment -> enrollment.getStudent().equals(student)); }

Enrollment 엔티티

@Entity public class Enrollment { @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "student_no", nullable = false) private User student; @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "course_no", nullable = false) private Course course; // 양방향 관계를 위한 setter public void setCourse(Course course) { this.course = course; } public void setStudent(User student) { this.student = student; } }

User ↔ Enrollment 양방향 관계

@Entity public class User { // 기존 필드들... @OneToMany(mappedBy = "student", cascade = CascadeType.ALL, orphanRemoval = true) private List<Enrollment> enrollments = new ArrayList<>(); // 편의 메서드 public void addEnrollment(Enrollment enrollment) { enrollments.add(enrollment); enrollment.setStudent(this); } public boolean isEnrolledIn(Course course) { return enrollments.stream() .anyMatch(enrollment -> enrollment.getCourse().equals(course)); } public List<Enrollment> getApprovedEnrollments() { return enrollments.stream() .filter(Enrollment::isApproved) .toList(); } }

Cascade와 Orphan Removal

설정된 Cascade 옵션

  • CascadeType.ALL: 모든 연관 엔티티에 대해 부모의 모든 작업 전파
  • orphanRemoval = true: 부모에서 제거된 자식 엔티티 자동 삭제
// Course 삭제 시 연관된 Curriculum과 Enrollment도 자동 삭제 Course course = courseRepository.findById(courseNo); courseRepository.delete(course); // → course.getCurriculums()의 모든 Curriculum 삭제 // → course.getEnrollments()의 모든 Enrollment 삭제 // Course에서 Curriculum 제거 시 자동 삭제 course.removeCurriculum(curriculum); // → curriculum이 DB에서 자동 삭제됨 (고아 객체)

장점과 주의사항

장점

  • 직접 접근 가능 (팝업 API 불필요)
  • 비즈니스 로직 엔티티에 캡슐화
  • 자동 데이터 관리 (Cascade)
  • 고아 객체 자동 삭제
  • 코드 가독성 향상

주의사항

  • 양방향 관계 일관성 유지 필요
  • 편의 메서드 사용 필수
  • 무한 루프 주의 (toString, equals)
  • LazyInitializationException 주의
  • 성능 고려 (N+1 문제)
