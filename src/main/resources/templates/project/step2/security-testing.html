필수 체크 항목 (우선순위)

1. SQL Injection (SQL 인젝션)

Critical (치명적)

사용자 입력을 SQL 쿼리에 직접 넣으면 전체 DB 탈취 가능

취약한 코드

// ❌ JPQL에 직접 문자열 결합 String name = request.getParameter("name"); String jpql = "SELECT u FROM User u WHERE u.name = '" + name + "'"; List<User> users = em.createQuery(jpql).getResultList(); // 공격: name = "admin' OR '1'='1" // 결과: SELECT u FROM User u WHERE u.name = 'admin' OR '1'='1' // → 모든 사용자 조회됨!

안전한 코드

// ✅ 파라미터 바인딩 사용 String name = request.getParameter("name"); String jpql = "SELECT u FROM User u WHERE u.name = :name"; List<User> users = em.createQuery(jpql) .setParameter("name", name) .getResultList(); // ✅ Spring Data JPA 사용 userRepository.findByName(name);

테스트 방법

  1. 검색창에 ' OR '1'='1 입력
  2. 모든 데이터가 나오면 취약함
  3. 에러 또는 결과 없으면 안전함

2. 인증/인가 누락 (Broken Access Control)

Critical (치명적)

로그인 없이 또는 다른 사람의 데이터를 마음대로 수정 가능

취약한 코드

// ❌ 누구나 수강신청 취소 가능 @DeleteMapping("/{enrollmentId}") public void cancel(@PathVariable Long enrollmentId) { enrollmentService.cancel(enrollmentId); } // 공격: DELETE /api/enrollments/999 // → 다른 사람 수강신청도 취소됨!

안전한 코드

// ✅ 본인 확인 @DeleteMapping("/{enrollmentId}") public void cancel( @PathVariable Long enrollmentId, @AuthenticationPrincipal UserDetails user) { Enrollment enrollment = enrollmentRepository .findById(enrollmentId).orElseThrow(); // 본인 것만 취소 가능 if (!enrollment.getUserNo().equals(user.getUserNo())) { throw new AccessDeniedException("권한 없음"); } enrollmentService.cancel(enrollmentId); }

테스트 방법

  1. 로그아웃 상태에서 API 호출 → 401 에러 나와야 함
  2. 다른 사람 ID로 수정 요청 → 403 에러 나와야 함
  3. Postman에서 Authorization 헤더 없이 테스트

3. 민감정보 노출 (Sensitive Data Exposure)

High (높음)

비밀번호, 개인정보가 평문으로 저장되거나 API 응답에 노출

체크 1: 비밀번호 암호화

❌ 평문 저장

password: "1234"

✅ BCrypt 암호화

password: "$2a$10$N9qo..."

체크 2: API 응답 필터링

❌ 비밀번호 노출

{ "userNo": 1, "name": "홍길동", "password": "$2a$10$..." ← 노출! }

✅ @JsonIgnore 사용

@JsonIgnore private String password; // 응답: { "userNo": 1, "name": "홍길동" }

테스트 방법

  1. DB에서 SELECT * FROM users → password 컬럼이 암호화되어 있어야 함
  2. API 응답 확인 → password, ssn 같은 필드 없어야 함
  3. 개발자 도구 Network 탭에서 응답 JSON 확인

4. XSS (Cross-Site Scripting)

High (높음)

사용자 입력에 <script> 태그를 넣으면 다른 사용자 브라우저에서 실행

취약한 코드 (Thymeleaf)

<!-- ❌ th:utext (HTML 그대로 렌더링) --> <p th:utext="${course.description}"></p> // 공격: description = "<script>alert('XSS')</script>" // → 스크립트 실행됨!

안전한 코드

<!-- ✅ th:text (HTML 이스케이프) --> <p th:text="${course.description}"></p> // 결과: &lt;script&gt;alert('XSS')&lt;/script&gt; // → 텍스트로 보임 (실행 안 됨)

테스트 방법

  1. 강의 설명에 <script>alert('XSS')</script> 입력
  2. 저장 후 페이지 새로고침
  3. alert 창이 뜨면 취약함 / 텍스트로 보이면 안전함

5. CSRF (Cross-Site Request Forgery)

Medium (중간)

로그인한 사용자가 악의적인 링크를 클릭하면 의도하지 않은 요청 실행

공격 시나리오

  1. 사용자가 우리 사이트에 로그인 (세션 쿠키 생성)
  2. 공격자가 이메일로 악의적인 링크 전송
  3. 링크 클릭 시 자동으로 수강신청 취소 요청 전송
  4. 세션 쿠키가 자동으로 포함되어 요청 성공

취약함 (CSRF 비활성화)

// SecurityConfig.java http.csrf().disable(); ← ❌ 위험!

안전함 (CSRF 활성화)

// SecurityConfig.java http.csrf().csrfTokenRepository( CookieCsrfTokenRepository.withHttpOnlyFalse() ); ← ✅ 안전 // Thymeleaf 폼 <form th:action="@{/api/enrollments}" method="post"> <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}"/> </form>

테스트 방법

Spring Security 기본 설정은 CSRF 활성화됨
csrf().disable() 코드 검색 → 있으면 제거

6. 민감한 엔드포인트 노출 (Actuator)

Medium (중간)

/actuator/env 같은 엔드포인트에서 DB 비밀번호 등 노출 가능

취약한 설정

# application.properties management.endpoints.web.exposure.include=* # 결과: /actuator/env 접근 가능 # → DB 비밀번호, API 키 노출!

안전한 설정

# application.properties management.endpoints.web.exposure.include=health,info,metrics # 운영 환경 (application-prod.properties) management.endpoints.web.base-path=/internal-monitor management.server.port=9090 spring.security.user.name=admin spring.security.user.password=강력한비밀번호

테스트 방법

  1. 브라우저에서 /actuator/env 접속
  2. DB 비밀번호가 보이면 취약함
  3. 403 에러 또는 접근 불가하면 안전함

보안 테스트 방법 (난이도별)

Level 1: 브라우저 직접 테스트 (추천)

초보자 OK

도구 불필요! 크롬 개발자 도구만으로 충분

SQL Injection

' OR '1'='1

검색창에 입력 → 모든 데이터 나오면 취약

XSS

<script>alert(1)</script>

텍스트 입력란에 입력 → alert 뜨면 취약

민감정보 노출

F12 → Network

API 응답에 password 있으면 취약

Level 2: Postman (권장)

설치 필요

API 테스트 도구로 인가 체크 및 토큰 테스트

다운로드

https://www.postman.com/downloads/

테스트 예시

  1. 로그인 없이 API 호출 → 401 확인
  2. 다른 사람 ID로 수정 → 403 확인
  3. 토큰 없이 요청 → 에러 확인

실습 예제

DELETE
http://localhost:8080/api/enrollments/999

← 다른 사람 수강신청 ID (본인 것 아님)

✅ 기대 결과: 403 Forbidden (권한 없음)

❌ 취약함: 200 OK (삭제 성공)

Level 3: IntelliJ HTTP Client (빠름)

IntelliJ 사용 시

IntelliJ IDEA에 내장된 HTTP 테스트 파일 (.http)

# security-test.http 파일 생성

### SQL Injection 테스트 GET http://localhost:8080/api/courses?name=' OR '1'='1 ### 인가 체크 - 다른 사람 수강신청 취소 DELETE http://localhost:8080/api/enrollments/999 Authorization: Bearer {{token}} ### 민감정보 노출 확인 GET http://localhost:8080/api/users/1

장점: 버전 관리 가능, 팀원과 공유 가능, 빠른 실행 (Ctrl+Enter)

Level 4: OWASP ZAP (자동 스캔)

선택 (고급)

전문 보안 도구 - 자동으로 취약점 찾아줌 (시간 오래 걸림)

⚠️ 주의: 7일 프로젝트에서는 Level 1~2면 충분합니다.
시간 여유 있을 때만 시도하세요.

설치 방법 보기 (클릭)
docker run -p 8090:8090 -i zaproxy/zap-stable zap-webswing.sh
  1. http://localhost:8090 접속
  2. URL 입력: http://host.docker.internal:8080
  3. "Automated Scan" 클릭
  4. 10~20분 대기
  5. 리포트 확인

추천 조합

1단계 (필수): 브라우저 직접 테스트 (SQL Injection, XSS)

2단계 (필수): Postman으로 인가 체크

3단계 (선택): IntelliJ HTTP Client로 자동화

4단계 (여유 시): OWASP ZAP 자동 스캔

💡 소요 시간: Level 1~2만 해도 30분~1시간이면 충분합니다!

👇

After: "수강신청 API 개발 및 보안 취약점 5개 발견·수정"

  • SQL Injection 방지 (파라미터 바인딩)
  • 인가 체크 누락 수정 (본인 검증 로직 추가)
  • 비밀번호 평문 저장 → BCrypt 암호화
  • API 응답에서 민감정보 제외 (@JsonIgnore)
  • Actuator 엔드포인트 제한 (운영 환경 포트 분리)

핵심 정리

  • 필수 체크 3가지: SQL Injection, 인가 누락, 비밀번호 암호화
  • 테스트 방법: 수동 입력 테스트 → OWASP ZAP 자동 스캔
  • 발표 자료: "보안 취약점 N개 발견 및 수정" 어필
  • 소요 시간: 1~2시간 (6가지 항목 체크)
