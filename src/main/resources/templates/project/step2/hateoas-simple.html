RESTful API Level 3 - 링크로 다음 행동 안내하기

목록으로

HATEOAS란?

Hypermedia As The Engine Of Application State

API 응답에 "다음에 할 수 있는 행동(링크)"을 함께 보내주는 방식

비유로 이해하기

웹사이트에서 상품을 보면 "장바구니 담기", "즉시 구매", "리뷰 보기" 버튼이 보이듯이, API 응답에도 "다음에 뭘 할 수 있는지" 링크로 알려주는 것

현재 API vs HATEOAS

현재: 데이터만 반환

{ "courseNo": 1, "name": "JPA 마스터", "description": "JPA 핵심 개념", "maxStudents": 30 }

❌ 클라이언트는 URL을 알아서 조합해야 함
→ /api/courses/1/curriculums 하드코딩

HATEOAS: 데이터 + 링크

{ "courseNo": 1, "name": "JPA 마스터", "description": "JPA 핵심 개념", "maxStudents": 30, "_links": { "self": { "href": "/api/courses/1" }, "curriculums": { "href": "/api/courses/1/curriculums" }, "students": { "href": "/api/courses/1/students" }, "enroll": { "href": "/api/enrollments" } } }

✅ 클라이언트는 링크를 따라가기만 하면 됨
→ URL 변경에도 유연함

백엔드 관점: 무엇이 바뀌나?

1 의존성 추가

// build.gradle dependencies { implementation 'org.springframework.boot:spring-boot-starter-hateoas' }

2 컨트롤러만 수정 (Service, Repository는 그대로)

현재 코드:

@GetMapping("/{courseNo}") public ResponseEntity<CourseDto> getCourse(@PathVariable Long courseNo) { CourseDto course = courseService.getCourse(courseNo); return ResponseEntity.ok(course); }

HATEOAS 적용:

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.*; @GetMapping("/{courseNo}") public ResponseEntity<EntityModel<CourseDto>> getCourse(@PathVariable Long courseNo) { CourseDto course = courseService.getCourse(courseNo); // EntityModel로 감싸고 링크 추가 EntityModel<CourseDto> resource = EntityModel.of(course); resource.add(linkTo(methodOn(CourseController.class).getCourse(courseNo)).withSelfRel()); resource.add(linkTo(methodOn(CourseController.class).getCurriculums(courseNo)).withRel("curriculums")); resource.add(linkTo(methodOn(CourseController.class).getStudents(courseNo)).withRel("students")); return ResponseEntity.ok(resource); }

3 응답 형태 변화

{ "courseNo": 1, "name": "JPA 마스터", "description": "JPA 핵심 개념", "maxStudents": 30, "_links": { "self": { "href": "http://localhost:8080/api/courses/1" }, "curriculums": { "href": "http://localhost:8080/api/courses/1/curriculums" }, "students": { "href": "http://localhost:8080/api/courses/1/students" } } }

핵심: _links 객체가 추가됨 (데이터는 동일)

장단점 요약

장점

  • ✅ API 탐색 가능
  • ✅ URL 변경에 유연
  • ✅ 가능한 행동 명시
  • ✅ RESTful 완성도 향상

단점

  • ❌ 응답 크기 증가
  • ❌ 개발 복잡도 증가
  • ❌ 실무에서 잘 안 씀
  • ❌ 프론트엔드 작업 증가

실무에서는?

  • 대부분의 프로젝트: Level 2(HTTP 메서드 + 상태 코드)로 충분
  • HATEOAS 도입 케이스: Public API, 외부 개발자용 API
  • 우리 프로젝트: 학습 목적으로 개념만 이해하면 충분

정리

HATEOAS: API 응답에 "다음 행동 링크" 추가

변경 사항: 의존성 추가 + 컨트롤러만 수정

응답 변화: _links 객체 추가

실무: 필수 아님, 선택 사항

💡 더 실용적인 대안: GraphQL (다음 강의 참고)
