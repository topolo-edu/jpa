HATEOAS란?

정의

HATEOAS (Hypermedia As The Engine Of Application State)

REST API 응답에 다음에 할 수 있는 행동(링크)을 함께 제공하여, 클라이언트가 서버의 상태 변화를 하이퍼미디어 링크로 탐색할 수 있게 하는 원칙

핵심 개념

  • 자기 발견(Self-Descriptive): API 응답만 보고 다음 행동을 알 수 있음
  • 느슨한 결합(Loose Coupling): 클라이언트가 URL을 하드코딩하지 않음
  • 진화 가능성(Evolvability): API 구조 변경 시 클라이언트 수정 최소화

Richardson RESTful 성숙도 모델

Level 0: The Swamp of POX

기초

단일 엔드포인트, HTTP POST만 사용 (RPC 스타일)

POST /api { "method": "getCourse", "params": { "id": 1 } }

Level 1: Resources

리소스 분리

리소스별로 엔드포인트 분리

POST /api/courses/1 GET /api/courses/1

Level 2: HTTP Verbs

현재 우리 수준

HTTP 메서드와 상태 코드 활용

GET /api/courses/1 → 200 OK POST /api/courses → 201 Created PUT /api/courses/1 → 200 OK DELETE /api/courses/1 → 204 No Content

Level 3: HATEOAS

목표

하이퍼미디어 링크로 다음 행동 제공

GET /api/courses/1 { "courseNo": 1, "name": "JPA 마스터", "_links": { "self": { "href": "/api/courses/1" }, "curriculums": { "href": "/api/courses/1/curriculums" }, "students": { "href": "/api/courses/1/students" }, "enroll": { "href": "/api/enrollments", "method": "POST" } } }

HATEOAS의 장단점

장점

  • 클라이언트가 URL 하드코딩 불필요
  • API 구조 변경 시 유연함
  • 서버가 가능한 행동을 명시
  • API 탐색 가능성 향상
  • 상태에 따른 동적 링크 제공

단점

  • 응답 크기 증가 (링크 정보)
  • 클라이언트 구현 복잡도 증가
  • 실무에서 잘 사용하지 않음
  • 학습 곡선 존재
  • 표준화 부족

현재 API vs HATEOAS 적용 API

Before: 현재 API (Level 2)

{ "courseNo": 1, "name": "JPA 마스터", "description": "JPA 핵심 개념", "instructor": { "userNo": 10, "name": "김영수" }, "maxStudents": 30, "status": "ACTIVE" }

문제: 클라이언트는 다음 행동을 위해 URL을 하드코딩해야 함
→ /api/courses/1/curriculums
→ /api/courses/1/students

After: HATEOAS 적용 (Level 3)

{ "courseNo": 1, "name": "JPA 마스터", "description": "JPA 핵심 개념", "instructor": { "userNo": 10, "name": "김영수" }, "maxStudents": 30, "status": "ACTIVE", "_links": { "self": { "href": "/api/courses/1" }, "curriculums": { "href": "/api/courses/1/curriculums" }, "students": { "href": "/api/courses/1/students" }, "update": { "href": "/api/courses/1", "method": "PUT" }, "delete": { "href": "/api/courses/1", "method": "DELETE" }, "enroll": { "href": "/api/enrollments", "method": "POST" } } }

개선: 클라이언트는 링크를 따라가기만 하면 됨
→ URL 변경 시에도 클라이언트 수정 불필요

Spring HATEOAS 구현 가이드

Step 1 의존성 추가

// build.gradle dependencies { implementation 'org.springframework.boot:spring-boot-starter-hateoas' }

Step 2 DTO에 링크 추가

RepresentationModel 상속 또는 EntityModel 사용

방법 1: RepresentationModel 상속

import org.springframework.hateoas.RepresentationModel; public class CourseResponse extends RepresentationModel<CourseResponse> { private Long courseNo; private String name; private String description; private InstructorDto instructor; private Integer maxStudents; private String status; // getters/setters }

방법 2: EntityModel 사용 (더 간단)

import org.springframework.hateoas.EntityModel; // 기존 DTO 그대로 사용 public record CourseDto( Long courseNo, String name, String description, InstructorDto instructor, Integer maxStudents, String status ) {}

Step 3 Controller에서 링크 추가

현재 코드

@GetMapping("/{courseNo}") public ResponseEntity<CourseDto> getCourse(@PathVariable Long courseNo) { CourseDto course = courseService.getCourse(courseNo); return ResponseEntity.ok(course); }

HATEOAS 적용 (EntityModel 사용)

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.*; @GetMapping("/{courseNo}") public ResponseEntity<EntityModel<CourseDto>> getCourse(@PathVariable Long courseNo) { CourseDto course = courseService.getCourse(courseNo); // EntityModel로 감싸고 링크 추가 EntityModel<CourseDto> resource = EntityModel.of(course); // self 링크 resource.add(linkTo(methodOn(CourseController.class) .getCourse(courseNo)) .withSelfRel()); // 커리큘럼 링크 resource.add(linkTo(methodOn(CourseController.class) .getCurriculums(courseNo)) .withRel("curriculums")); // 수강생 링크 resource.add(linkTo(methodOn(CourseController.class) .getStudents(courseNo)) .withRel("students")); // 수정 링크 resource.add(linkTo(methodOn(CourseController.class) .updateCourse(courseNo, null)) .withRel("update")); // 삭제 링크 resource.add(linkTo(methodOn(CourseController.class) .deleteCourse(courseNo)) .withRel("delete")); return ResponseEntity.ok(resource); }

Step 4 상태에 따른 조건부 링크

현재 강의 상태에 따라 가능한 행동만 링크 제공

// ACTIVE 상태일 때만 수강신청 링크 제공 if (course.getStatus().equals("ACTIVE")) { resource.add(linkTo(methodOn(EnrollmentController.class) .enroll(null)) .withRel("enroll")); } // PENDING 상태일 때만 활성화 링크 제공 if (course.getStatus().equals("PENDING")) { resource.add(linkTo(methodOn(CourseController.class) .activate(courseNo)) .withRel("activate")); } // 정원이 남았을 때만 수강신청 링크 if (course.getCurrentStudents() < course.getMaxStudents()) { resource.add(linkTo(methodOn(EnrollmentController.class) .enroll(null)) .withRel("enroll")); }

Step 5 목록 응답에 HATEOAS 적용

import org.springframework.hateoas.CollectionModel; @GetMapping public ResponseEntity<CollectionModel<EntityModel<CourseDto>>> getCourses() { List<CourseDto> courses = courseService.getAllCourses(); // 각 Course에 링크 추가 List<EntityModel<CourseDto>> resources = courses.stream() .map(course -> { EntityModel<CourseDto> resource = EntityModel.of(course); resource.add(linkTo(methodOn(CourseController.class) .getCourse(course.getCourseNo())) .withSelfRel()); return resource; }) .toList(); // 전체 목록 링크 CollectionModel<EntityModel<CourseDto>> result = CollectionModel.of(resources); result.add(linkTo(methodOn(CourseController.class) .getCourses()) .withSelfRel()); // 생성 링크 result.add(linkTo(methodOn(CourseController.class) .createCourse(null)) .withRel("create")); return ResponseEntity.ok(result); }

실무에서의 HATEOAS

현실적인 평가

  • 대부분의 실무 프로젝트는 Level 2에서 멈춤
  • 프론트엔드 팀과의 협업에서 링크 기반 탐색보다 명확한 엔드포인트 선호
  • GraphQL, gRPC 등 다른 대안 존재
  • 공수 대비 실익이 크지 않음

HATEOAS가 유용한 경우

  • Public API 제공: 외부 개발자가 API를 쉽게 탐색
  • API 문서 자동화: 링크로 가능한 행동 표현
  • 워크플로우 가이드: 상태 전환 로직을 서버가 제어
  • 학습 목적: RESTful API 원칙 이해

결론 및 권장 사항

✅ 학습 가치: RESTful API 성숙도 모델을 이해하고 Level 3를 경험해볼 가치는 있음

⚠️ 실무 적용: 팀 상황과 요구사항에 따라 선택적으로 적용 (Level 2로도 충분한 경우가 많음)

🎯 권장: 우리 프로젝트에서는 이론 학습 후, 1~2개 엔드포인트에만 적용해보고 판단
