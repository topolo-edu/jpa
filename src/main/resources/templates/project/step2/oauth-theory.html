OAuth 2.0 소셜 로그인

"Google로 로그인" 버튼 만들기

목록으로

OAuth 2.0이란?

쉽게 이해하기

"Google로 로그인" 버튼을 본 적 있나요?

우리 사이트에 회원가입하지 않고, Google 계정으로 로그인할 수 있게 해주는 기술이 바로 OAuth 2.0입니다.

비유로 이해하기

1

기존 방식: 우리 사이트에 이메일/비밀번호 등록 → 우리가 비밀번호 관리

2

OAuth 방식: "Google로 로그인" 클릭 → Google이 인증 → 우리는 결과만 받음

왜 사용하나요?

  • 사용자 편의: 비밀번호 기억 안 해도 됨
  • 회원가입 장벽 낮춤: 클릭 한 번에 로그인
  • 보안: 우리가 비밀번호 관리 안 해도 됨
  • 신뢰: Google/GitHub이 이미 검증한 사용자

OAuth 2.0 동작 과정

간단하게 정리하면

1

사용자: "Google로 로그인" 버튼 클릭

2

우리 서버: 사용자를 Google 로그인 페이지로 이동

3

사용자: Google에 로그인하고 "앱 접근 허용" 클릭

4

Google: 인증 코드를 우리 서버로 전달

5

우리 서버: 인증 코드로 사용자 정보 요청

6

Google: 사용자 정보 (이메일, 이름 등) 전달

7

우리 서버: DB에 사용자 저장/조회 후 로그인 완료

핵심 포인트

사용자의 비밀번호를 우리가 받지 않는다!

Google이 인증을 대신 해주고, "이 사람 맞아요"라는 확인만 받는 방식입니다.

현재 프로젝트에 OAuth 추가하기

우리 프로젝트의 현재 상태

Form 로그인 (세션 기반) - 이메일/비밀번호로 로그인

→ 여기에 "Google로 로그인" 기능을 추가하는 것

로그인 방식 비교

항목 현재 (Form 로그인) 추가 후 (+ OAuth)
이메일 로그인 ✅ 사용 중 ✅ 그대로 유지
Google 로그인 ❌ 없음 ✅ 추가
GitHub 로그인 ❌ 없음 ✅ 추가 가능
세션 관리 Spring Session Spring Session (동일)
인증 필터 UsernamePasswordAuthenticationFilter + OAuth2LoginAuthenticationFilter

핵심 아이디어

  • OAuth는 "로그인 방법 하나 더 추가"일 뿐
  • 로그인 성공 후 세션 생성 (기존과 동일)
  • 이후 모든 요청은 세션 쿠키로 인증
  • 기존 Form 로그인 코드 변경 없음

Spring Boot OAuth 2.0 구현 가이드

Step 1 Google Cloud Console에서 OAuth 앱 등록

  1. 1. Google Cloud Console 접속
  2. 2. 프로젝트 생성 또는 선택
  3. 3. "API 및 서비스" → "사용자 인증 정보" 이동
  4. 4. "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID" 선택
  5. 5. 애플리케이션 유형: 웹 애플리케이션
  6. 6. 승인된 리디렉션 URI 추가:
    • • 로컬 개발: http://localhost:8080/login/oauth2/code/google
    • • 실제 배포: https://yourdomain.com/login/oauth2/code/google
  7. 7. Client ID와 Client Secret 복사

중요: 로컬 개발과 배포 환경은 별도의 OAuth 클라이언트를 만들거나, 하나의 클라이언트에 여러 리디렉션 URI를 등록할 수 있습니다.

Step 2 의존성 추가

// build.gradle dependencies { implementation 'org.springframework.boot:spring-boot-starter-oauth2-client' // 기존 Security 의존성은 그대로 유지 }

이게 전부! 한 줄만 추가하면 됩니다.

Step 3 application.yml 설정

spring: security: oauth2: client: registration: google: client-id: YOUR_GOOGLE_CLIENT_ID client-secret: YOUR_GOOGLE_CLIENT_SECRET scope: - profile - email redirect-uri: "{baseUrl}/login/oauth2/code/{registrationId}" # GitHub 추가 예시 github: client-id: YOUR_GITHUB_CLIENT_ID client-secret: YOUR_GITHUB_CLIENT_SECRET scope: - user:email - read:user

Step 4 User 엔티티에 OAuth 필드 추가

@Entity @Table(name = "users") public class User extends BaseEntity { // 기존 필드들... // OAuth 관련 필드 추가 @Column(name = "provider") private String provider; // "google", "github", "local" @Column(name = "provider_id") private String providerId; // OAuth provider의 사용자 ID // password는 OAuth 사용자의 경우 null 가능 @Column(name = "password") private String password; // nullable for OAuth users }

Step 5 CustomOAuth2UserService 구현

@Service @RequiredArgsConstructor public class CustomOAuth2UserService extends DefaultOAuth2UserService { private final UserRepository userRepository; @Override public OAuth2User loadUser(OAuth2UserRequest userRequest) { OAuth2User oauth2User = super.loadUser(userRequest); // Provider 정보 String provider = userRequest.getClientRegistration().getRegistrationId(); String providerId = oauth2User.getAttribute("sub"); // Google의 경우 "sub" String email = oauth2User.getAttribute("email"); String name = oauth2User.getAttribute("name"); // DB에서 사용자 찾기 또는 생성 User user = userRepository.findByProviderAndProviderId(provider, providerId) .orElseGet(() -> { User newUser = User.builder() .email(email) .name(name) .provider(provider) .providerId(providerId) .role(Role.STUDENT) .build(); return userRepository.save(newUser); }); // OAuth2User 반환 (User 정보 포함) return new CustomOAuth2User(user, oauth2User.getAttributes()); } }

Step 6 SecurityConfig에 OAuth 설정 추가

@Configuration @EnableWebSecurity @RequiredArgsConstructor public class SecurityConfig { private final CustomOAuth2UserService oauth2UserService; @Bean public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception { http // 기존 Form 로그인 설정 (그대로 유지) .formLogin(form -> form .loginPage("/auth/login") .defaultSuccessUrl("/", true) .permitAll() ) // OAuth2 로그인 추가 .oauth2Login(oauth2 -> oauth2 .loginPage("/auth/login") // Form 로그인과 동일한 페이지 .userInfoEndpoint(userInfo -> userInfo .userService(oauth2UserService) ) .defaultSuccessUrl("/", true) // 로그인 성공 후 홈으로 ); return http.build(); } }

핵심: 기존 Form 로그인 설정은 그대로 두고, .oauth2Login()만 추가

Step 7 로그인 페이지에 OAuth 버튼 추가

<!-- /auth/login 페이지 (Thymeleaf) --> <form th:action="@{/login}" method="post"> <!-- 기존 이메일/비밀번호 입력 --> <input type="email" name="username" placeholder="이메일"> <input type="password" name="password" placeholder="비밀번호"> <button type="submit">로그인</button> </form> <!-- 소셜 로그인 버튼 추가 --> <div class="social-login"> <p>또는</p> <a href="/oauth2/authorization/google" class="google-btn"> <i class="fab fa-google"></i> Google로 로그인 </a> <a href="/oauth2/authorization/github" class="github-btn"> <i class="fab fa-github"></i> GitHub로 로그인 </a> </div>

핵심: /oauth2/authorization/{provider}는 Spring Security가 자동으로 제공하는 엔드포인트

테스트 방법

로컬 테스트

  1. 1. 서버 실행: ./gradlew bootRun
  2. 2. 브라우저에서 http://localhost:8080/auth/login 접속
  3. 3. "Google로 로그인" 버튼 클릭
  4. 4. Google 계정으로 로그인 및 권한 허용
  5. 5. 자동으로 홈 페이지(/)로 리다이렉트
  6. 6. 로그인 상태 확인 (세션 생성됨)

동작 확인

로그인 후 다음 정보를 확인할 수 있습니다:

  • ✅ DB에 사용자 저장 확인 (provider = "google")
  • ✅ 세션 쿠키 생성 확인 (브라우저 개발자 도구)
  • ✅ 로그인 후 페이지 접근 가능 확인

OAuth 도입 장단점

장점

  • 사용자 편의성 (비밀번호 기억 불필요)
  • 회원가입 장벽 낮춤
  • 이메일 인증 생략 가능
  • 신뢰할 수 있는 제3자 인증
  • 비밀번호 관리 부담 감소

주의사항

  • 외부 서비스 의존성 증가
  • Provider 장애 시 로그인 불가
  • 사용자 계정 통합 복잡도
  • 개인정보 제3자 제공 동의 필요
  • 이메일 중복 처리 필요

이메일 중복 처리 전략

같은 이메일로 로컬 가입 + Google 로그인 시 충돌 가능

// 전략 1: 계정 통합 (권장) if (existingUser != null && existingUser.getProvider().equals("local")) { // 기존 로컬 계정에 OAuth 연동 existingUser.setProvider("google"); existingUser.setProviderId(providerId); } // 전략 2: 별도 계정 유지 // provider + email을 복합키로 사용

정리

OAuth란? "Google로 로그인" 같은 소셜 로그인 기능

우리 프로젝트: 기존 Form 로그인 유지 + OAuth 추가 (선택지 늘리기)

구현 시간: 약 1시간 (Google 앱 등록 + 의존성 + 설정 + 버튼 추가)

변경 사항: User 엔티티에 필드 2개 추가, SecurityConfig 한 줄 추가, 버튼 추가

💡 실무 팁: 대부분의 서비스는 Google, Kakao, Naver 중 2~3개 제공
첫 구현은 Google 추천 (설정이 가장 간단)
