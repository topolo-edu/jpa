배치 처리 DTO

BatchEnrollmentRequest

// 수강신청 일괄 처리 요청 DTO @Data @Builder @NoArgsConstructor @AllArgsConstructor public class BatchEnrollmentRequest { @NotEmpty(message = "처리할 수강신청 ID 목록은 필수입니다.") private List<Long> enrollmentIds; @NotNull(message = "처리 액션은 필수입니다. (APPROVE 또는 REJECT)") private BatchAction action; private String reason; // 처리 사유 (선택 사항) public int getEnrollmentCount() { return enrollmentIds != null ? enrollmentIds.size() : 0; } public boolean isApprove() { return BatchAction.APPROVE.equals(action); } public enum BatchAction { APPROVE, REJECT } }

BatchEnrollmentResponse

// 수강신청 일괄 처리 응답 DTO @Data @Builder public class BatchEnrollmentResponse { private BatchEnrollmentRequest.BatchAction action; private int totalCount; private int successCount; private int failureCount; private List<EnrollmentProcessResult> results; private List<String> errors; // 정적 팩토리 메서드 public static BatchEnrollmentResponse success(BatchEnrollmentRequest.BatchAction action, int totalCount, List<EnrollmentProcessResult> results) { long success = results.stream().filter(EnrollmentProcessResult::isSuccess).count(); long failure = results.stream().filter(r -> !r.isSuccess()).count(); return BatchEnrollmentResponse.builder() .action(action) .totalCount(totalCount) .successCount((int) success) .failureCount((int) failure) .results(results) .build(); } @Data @Builder public static class EnrollmentProcessResult { private Long enrollmentId; private boolean success; private String message; private String error; } }

배치 처리 Service 구현

1. 일반 배치 처리

@Transactional public BatchEnrollmentResponse batchProcessEnrollments(BatchEnrollmentRequest request) { // 1. 수강신청 조회 (비관적 락) List<Enrollment> enrollments = enrollmentRepository.findByIdsForBatchUpdate(request.getEnrollmentIds()); // 2. 처리 가능한 수강신청이 없으면 예외 발생 if (enrollments.isEmpty()) { throw new BusinessException(ErrorCode.ENROLLMENT_BATCH_NO_ITEMS); } // 3. 개별 처리 List<EnrollmentProcessResult> results = enrollments.stream() .map(enrollment -> processEnrollment(enrollment, request.getAction(), request.getReason())) .collect(Collectors.toList()); // 4. 응답 생성 return BatchEnrollmentResponse.success(request.getAction(), request.getEnrollmentCount(), results); } // 개별 수강신청 처리 private EnrollmentProcessResult processEnrollment(Enrollment enrollment, BatchEnrollmentRequest.BatchAction action, String reason) { try { // 대기 상태가 아닌 수강신청은 처리할 수 없음 if (enrollment.getStatus() != EnrollmentStatus.PENDING) { throw new BusinessException(ErrorCode.ENROLLMENT_ALREADY_PROCESSED); } if (action == BatchEnrollmentRequest.BatchAction.APPROVE) { enrollment.approve(); return EnrollmentProcessResult.builder() .enrollmentId(enrollment.getEnrollmentNo()) .success(true) .message("승인 완료") .build(); } else { enrollment.reject(); return EnrollmentProcessResult.builder() .enrollmentId(enrollment.getEnrollmentNo()) .success(true) .message("거절 완료") .build(); } } catch (Exception e) { return EnrollmentProcessResult.builder() .enrollmentId(enrollment.getEnrollmentNo()) .success(false) .error(e.getMessage()) .build(); } }

2. 강의별 배치 처리

@Transactional public BatchEnrollmentResponse batchProcessEnrollmentsByCourse(Long courseNo, BatchEnrollmentRequest.BatchAction action, String reason) { // 1. 강의 조회 Course course = courseRepository.findById(courseNo) .orElseThrow(() -> new IllegalArgumentException("존재하지 않는 강의입니다")); // 2. 대기 중인 수강신청 조회 (비관적 락) List<Enrollment> enrollments = enrollmentRepository.findPendingByCourseForBatchUpdate(course); // 3. 처리 가능한 수강신청이 없으면 예외 발생 if (enrollments.isEmpty()) { throw new BusinessException(ErrorCode.ENROLLMENT_BATCH_NO_ITEMS); } // 4. 개별 처리 List<EnrollmentProcessResult> results = enrollments.stream() .map(enrollment -> processEnrollment(enrollment, action, reason)) .collect(Collectors.toList()); // 5. 응답 생성 return BatchEnrollmentResponse.success(action, enrollments.size(), results); }

@EntityGraph 최적화

@EntityGraph 장점

  • 코드 간소화: JPQL JOIN FETCH 대신 어노테이션으로 간단하게
  • 가독성 향상: 메서드명만으로도 어떤 연관 엔티티를 가져오는지 명확
  • 유지보수성: 연관 엔티티 변경 시 어노테이션만 수정하면 됨
  • 재사용성: 여러 메서드에서 동일한 @EntityGraph 재사용 가능

CourseRepository @EntityGraph 적용

// 기존: JPQL JOIN FETCH @Query("SELECT c FROM Course c JOIN FETCH c.instructor WHERE c.courseNo = :courseNo") Optional<Course> findByIdWithInstructor(Long courseNo); // 개선: @EntityGraph @EntityGraph(attributePaths = {"instructor"}) Optional<Course> findByIdWithInstructor(Long courseNo); // 수정용 조회 (비관적 락 + @EntityGraph) @Lock(LockModeType.PESSIMISTIC_WRITE) @EntityGraph(attributePaths = {"instructor"}) Optional<Course> findByIdForUpdate(Long courseNo);

EnrollmentRepository @EntityGraph 적용

// 기존: JPQL JOIN FETCH @Query("SELECT e FROM Enrollment e JOIN FETCH e.student JOIN FETCH e.course WHERE e.id = :enrollmentId") Optional<Enrollment> findByIdForUpdate(Long enrollmentId); // 개선: @EntityGraph @Lock(LockModeType.PESSIMISTIC_WRITE) @EntityGraph(attributePaths = {"student", "course"}) Optional<Enrollment> findByIdForUpdate(Long enrollmentId); // 학생-강의별 조회 (비관적 락 + @EntityGraph) @Lock(LockModeType.PESSIMISTIC_WRITE) @EntityGraph(attributePaths = {"student", "course"}) Optional<Enrollment> findByStudentAndCourseForUpdate(User student, Course course);

N+1 문제 해결

N+1 문제란?

1개의 쿼리로 N개의 엔티티를 조회한 후, 각 엔티티의 연관 엔티티에 접근할 때마다 추가 쿼리가 발생하는 문제

해결 방법

1. @EntityGraph

  • • 연관 엔티티를 한 번에 조회
  • • 코드 간소화
  • • 가독성 향상

2. Batch Size 설정

  • • application-jpa.properties 설정
  • • default_batch_fetch_size=100
  • • 자동으로 IN 쿼리로 최적화

설정 확인

# application-jpa.properties # N+1 방지 spring.jpa.properties.hibernate.default_batch_fetch_size=100 # Batch Insert/Update 설정 spring.jpa.properties.hibernate.jdbc.batch_size=50
