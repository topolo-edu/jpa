AWS CloudWatch (배포 후 추천)

CloudWatch란?

AWS에서 제공하는 모니터링 서비스 - EC2 생성하면 자동으로 메트릭 기록됨

Actuator vs CloudWatch:
• Actuator: "지금 이 순간" 서버 상태 확인 (실시간)
• CloudWatch: "지난 24시간" 서버 추이 확인 (과거 데이터 그래프)

왜 CloudWatch를 사용하나요?

  • 과거 데이터 그래프: "어제 오후 3시에 CPU 급등" 같은 패턴 확인
  • 자동 알림: CPU 80% 넘으면 이메일/Slack 알림
  • 문제 원인 추적: "서버 다운 시점에 메모리 100% 도달" 분석
  • 발표 자료: "24시간 안정성 모니터링" 그래프 첨부

무료 vs 유료

✅ 무료 (기본 메트릭)

  • • CPU 사용률
  • • 네트워크 트래픽
  • • 디스크 I/O
  • • 5분 간격 자동 수집
  • • 로그 5GB/월 무료

❌ 유료 (고급 기능)

  • • 1분 간격 상세 모니터링 ($2.10/월)
  • • Custom Metrics ($0.30/월/메트릭)
  • • 로그 5GB 초과 ($0.50/GB)

💡 7일 프로젝트: 기본 메트릭만 써도 충분! (무료)

CloudWatch 사용법 (초간단)

1

EC2 인스턴스 생성

EC2 만들면 자동으로 CloudWatch에 메트릭 전송 시작
→ 추가 설정 불필요!

2

AWS Console에서 확인

AWS Console → CloudWatch → Metrics → EC2 → 자동으로 그래프 생성됨 (설정 안 해도!)
3

알림 설정 (선택)

CPU 80% 넘으면 알림 받기:

CloudWatch → Alarms → Create Alarm
→ Metric: EC2 > CPU Utilization
→ Threshold: 80%
→ Action: SNS Topic (이메일/Slack)

Actuator vs CloudWatch 어떤 걸 써야 할까?

기능 Actuator CloudWatch 기본
현재 서버 상태 확인 ✅ 즉시 확인 ✅ 5분 지연
과거 데이터 (1시간 전) ❌ ✅
그래프/차트 ❌ JSON만 ✅ 예쁜 그래프
알림 설정 ❌ ✅
설정 복잡도 ⭐ 매우 쉬움 ⭐⭐ 쉬움 (자동)
비용 무료 무료 (기본)
발표 자료 활용 ⭐⭐ 보통 ⭐⭐⭐⭐ 우수

💡 추천 조합: Actuator (실시간 확인) + CloudWatch (과거 분석)
설정 시간: 0분 (EC2 만들면 자동으로 CloudWatch 연동됨)

발표 자료 활용 예시

Before (Actuator만 사용)

"서버를 AWS EC2에 배포했습니다. Actuator로 헬스 체크 가능합니다."

👇

After (Actuator + CloudWatch)

"서버를 AWS EC2에 배포하고 CloudWatch로 24시간 모니터링을 구축했습니다."

  • Actuator: 실시간 헬스 체크 및 메트릭 조회
  • CloudWatch: 24시간 CPU/메모리 사용률 그래프 (스크린샷 첨부)
  • 알림 설정: CPU 80% 초과 시 이메일 자동 발송
  • 안정성 증명: "24시간 가동 중 장애 0건"
