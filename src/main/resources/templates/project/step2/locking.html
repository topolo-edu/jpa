비관적 락과 동시성 제어

@Lock, 동시성 제어, 트랜잭션 관리

목록으로

락킹 전략 개요

낙관적 락 (Optimistic Lock) - Step 1

  • @Version 어노테이션 사용
  • 충돌 시 OptimisticLockException
  • 재시도 로직 필요
  • 높은 동시성 성능

비관적 락 (Pessimistic Lock) - Step 2

  • @Lock(PESSIMISTIC_WRITE) 사용
  • DB 레벨에서 락 획득
  • 재시도 로직 불필요
  • 낮은 동시성 성능

CourseRepository 비관적 락

// 수강신청용 Course 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Course> findByIdForEnrollment(Long courseNo); // 강의 수정용 Course 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Course> findByIdForUpdate(Long courseNo); // 수강 가능한 강의 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Course> findAvailableByIdForEnrollment(Long courseNo); // 강사별 강의 수정용 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Course> findByIdAndInstructorForUpdate(Long courseNo, User instructor); // 강사별 강의 삭제용 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Course> findByIdAndInstructorForDelete(Long courseNo, User instructor);

EnrollmentRepository 비관적 락

// 수강신청 수정용 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Enrollment> findByIdForUpdate(Long enrollmentId); // 학생-강의별 수강신청 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) Optional<Enrollment> findByStudentAndCourseForUpdate(User student, Course course); // 강의별 상태별 수강신청 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) List<Enrollment> findByCourseAndStatusForUpdate(Course course, EnrollmentStatus status); // 대기 중인 수강신청 조회 (비관적 락) @Lock(LockModeType.PESSIMISTIC_WRITE) List<Enrollment> findPendingEnrollmentsForUpdate();

Service에서 비관적 락 활용

수강신청 (EnrollmentService)

@Transactional public Enrollment enroll(Long courseNo, Long studentNo) { // 1. 수강 가능한 강의 조회 (비관적 락) Course course = courseRepository.findAvailableByIdForEnrollment(courseNo) .orElseThrow(() -> new IllegalArgumentException("수강 불가능한 강의입니다")); // 2. 중복 수강신청 확인 (비관적 락) User student = userRepository.findById(studentNo) .orElseThrow(() -> new IllegalArgumentException("존재하지 않는 학생입니다")); enrollmentRepository.findByStudentAndCourseForUpdate(student, course) .ifPresent(enrollment -> { throw new IllegalArgumentException("이미 수강신청한 강의입니다"); }); // 3. 수강신청 생성 및 양방향 관계 설정 Enrollment enrollment = Enrollment.builder() .student(student) .course(course) .status(EnrollmentStatus.PENDING) .build(); course.addEnrollment(enrollment); return enrollmentRepository.save(enrollment); }

강의 수정 (CourseService)

@Transactional public Course update(Long courseNo, CourseUpdateRequest request, User instructor) { // 강의 조회 (비관적 락) Course course = courseRepository.findByIdAndInstructorForUpdate(courseNo, instructor) .orElseThrow(() -> new IllegalArgumentException("수정 권한이 없습니다")); // 강의 정보 수정 course.updateInfo(request.getName(), request.getDescription(), request.getMaxStudents()); return courseRepository.save(course); }

강의 삭제 (CourseService)

@Transactional public void delete(Long courseNo, User instructor) { // 강의 조회 (비관적 락) Course course = courseRepository.findByIdAndInstructorForDelete(courseNo, instructor) .orElseThrow(() -> new IllegalArgumentException("삭제 권한이 없습니다")); // Cascade.ALL + orphanRemoval로 연관 데이터 자동 삭제 courseRepository.delete(course); // → course.getCurriculums()의 모든 Curriculum 삭제 // → course.getEnrollments()의 모든 Enrollment 삭제 }

동시성 제어 시나리오

시나리오 1: 동시 수강신청

상황: 2명의 학생이 동시에 마지막 1자리 강의에 수강신청

비관적 락 적용:

  • • Student A: Course 조회 시 락 획득
  • • Student B: Course 조회 시 락 대기
  • • Student A: 수강신청 완료 후 락 해제
  • • Student B: 락 획득 후 수강 불가능 확인

결과: 정확히 1명만 수강신청 성공

시나리오 2: 동시 강의 수정

상황: 강사가 동시에 같은 강의 정보 수정

비관적 락 적용:

  • • Request A: Course 조회 시 락 획득
  • • Request B: Course 조회 시 락 대기
  • • Request A: 수정 완료 후 락 해제
  • • Request B: 락 획득 후 최신 데이터로 수정

결과: 데이터 일관성 보장

시나리오 3: 동시 승인/거절

상황: 관리자가 동시에 같은 수강신청 처리

비관적 락 적용:

  • • Request A: Enrollment 조회 시 락 획득
  • • Request B: Enrollment 조회 시 락 대기
  • • Request A: 승인 완료 후 락 해제
  • • Request B: 락 획득 후 이미 처리됨 확인

결과: 중복 처리 방지

주의사항

비관적 락 사용 시 주의사항

  • 데드락 위험: 여러 엔티티를 락할 때 순서를 일관성 있게 유지
  • 성능 저하: 락 대기 시간으로 인한 응답 지연
  • 트랜잭션 길이: 락을 오래 유지하지 않도록 트랜잭션 최적화
  • 예외 처리: 락 획득 실패 시 적절한 예외 처리
