LazyInitializationException

엔티티 반환 오류, 해결 방법, DTO 변환

목록으로

LazyInitializationException이란?

발생 원인

JPA에서 @OneToMany 또는 @ManyToMany 관계의 연관 엔티티에 LAZY 로딩으로 설정되어 있을 때, 영속성 컨텍스트가 종료된 후 해당 연관 엔티티에 접근하려고 할 때 발생하는 예외입니다.

핵심 원리

엔티티가 Service를 넘어 Controller까지 넘어갔다면 이미 영속성 컨텍스트를 벗어난 상태입니다. 이는 SELECT 쿼리로 데이터를 가져오는 개념이므로, 애초에 Record나 DTO로 변환해서 반환하는 것이 올바른 접근입니다!

발생 시점

1 vs N 관계에서의 발생

✅ 오류 없음

1 → N 접근: Course에서 Curriculum 목록 접근

Course course = courseRepository.findById(1L); List<Curriculum> curriculums = course.getCurriculums(); // ✅ 정상 동작

❌ 오류 발생

N → 1 접근: Curriculum에서 Course 접근

Curriculum curriculum = curriculumRepository.findById(1L); Course course = curriculum.getCourse(); // ❌ LazyInitializationException

정확한 발생 지점

// Service 메서드 public Course getCourse(Long courseNo) { Course course = courseRepository.findById(courseNo).orElseThrow(); return course; // 영속성 컨텍스트 종료 } // Controller 메서드 @GetMapping("/courses/{courseNo}") public Course getCourse(@PathVariable Long courseNo) { Course course = courseService.getCourse(courseNo); List<Curriculum> curriculums = course.getCurriculums(); // ❌ 여기서 오류 발생! return course; }

@Transactional의 역할

클래스 단위 vs 메서드 단위

클래스 단위 @Transactional

@Transactional @Service public class CourseService { public Course getCourse(Long courseNo) { Course course = courseRepository.findById(courseNo); List<Curriculum> curriculums = course.getCurriculums(); // ✅ 안전 return course; } }

메서드 단위 @Transactional

@Service public class CourseService { @Transactional public Course getCourse(Long courseNo) { Course course = courseRepository.findById(courseNo); List<Curriculum> curriculums = course.getCurriculums(); // ✅ 안전 return course; } }

@Transactional 없을 때

❌ 오류 발생

@Service public class CourseService { // @Transactional 없음 public Course getCourse(Long courseNo) { Course course = courseRepository.findById(courseNo); List<Curriculum> curriculums = course.getCurriculums(); // ❌ 오류 발생! return course; } }

해결 방법

방법 1: @Transactional 추가

✅ Service에 @Transactional 추가

@Transactional @Service public class CourseService { public Course getCourse(Long courseNo) { Course course = courseRepository.findById(courseNo).orElseThrow(); List<Curriculum> curriculums = course.getCurriculums(); // ✅ 안전 return course; } }

방법 2: Fetch Join 사용

✅ Repository에서 Fetch Join

// Repository @Query("SELECT c FROM Course c JOIN FETCH c.curriculums WHERE c.courseNo = :courseNo") Optional<Course> findByIdWithCurriculums(Long courseNo); // Service public Course getCourse(Long courseNo) { Course course = courseRepository.findByIdWithCurriculums(courseNo).orElseThrow(); List<Curriculum> curriculums = course.getCurriculums(); // ✅ 안전 return course; }

방법 3: DTO 변환 (권장)

✅ Service에서 DTO로 변환

// DTO 생성 public record CourseResponse( Long courseNo, String name, String description, List<CurriculumResponse> curriculums ) {} // Service public CourseResponse getCourse(Long courseNo) { Course course = courseRepository.findByIdWithCurriculums(courseNo).orElseThrow(); List<CurriculumResponse> curriculums = course.getCurriculums().stream() .map(CurriculumResponse::from) .toList(); return new CourseResponse( course.getCourseNo(), course.getName(), course.getDescription(), curriculums ); }

권장 사항

DTO 사용 권장

  • 엔티티 노출 방지: 내부 구조를 외부에 노출하지 않음
  • API 안정성: 엔티티 변경이 API에 영향을 주지 않음
  • 성능 최적화: 필요한 데이터만 전송
  • 보안: 민감한 정보 노출 방지

@Transactional 사용 시 주의사항

  • 트랜잭션 범위: 필요한 범위에만 적용
  • 성능 고려: 불필요한 트랜잭션은 성능 저하
  • 읽기 전용: 조회만 하는 경우 @Transactional(readOnly = true) 사용
  • 예외 처리: 트랜잭션 롤백 조건 고려

요약

핵심 포인트

  1. 발생 원인: 영속성 컨텍스트 종료 후 LAZY 로딩된 연관 엔티티 접근
  2. 발생 시점: N → 1 관계에서 N 엔티티의 1 엔티티 접근 시
  3. 해결 방법: @Transactional 추가, Fetch Join 사용, DTO 변환
  4. 권장 사항: Service에서 DTO로 변환하여 반환
  5. 핵심 원리: 엔티티가 Service를 넘어 Controller까지 넘어갔다면 이미 영속성 컨텍스트를 벗어난 상태
