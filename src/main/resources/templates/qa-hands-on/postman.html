5. 실습 2: Collection 만들기 (2분)

API를 폴더로 묶어서 관리하면 나중에 찾기 쉽고, 팀과 공유할 수 있습니다.

📁 Collection 이름
Order API
📝 포함할 API (5개)
  • 1. POST /api/orders - 주문 생성
  • 2. GET /api/orders - 전체 조회
  • 3. GET /api/orders/{id} - 단건 조회
  • 4. PUT /api/orders/{id} - 수정
  • 5. DELETE /api/orders/{id} - 삭제
🌍 Environment 설정
변수명
baseUrl
값
http://localhost:8080
사용법: {{baseUrl}}/api/orders

📸 이미지 필요: postman-collection.png

스크린샷 가이드
  1. 1. 좌측 "Collections" 탭
  2. 2. "Order API" 폴더에 5개 Request 저장된 상태
  3. 3. Environment 설정 화면도 함께 캡처

6. 실습 3: 에러 테스트 (2분)

정상 케이스만 테스트하면 안 됩니다! 에러 상황도 반드시 확인하세요.

400

Bad Request

잘못된 요청 데이터
테스트 방법:
"customerName": "" (빈 문자열) 
{
  "message": "고객명은 필수입니다",
  "status": 400
}
401

Unauthorized

인증 없이 접근
테스트 방법:
Authorization 헤더 제거 
{
  "message": "로그인이 필요합니다",
  "status": 401
}
404

Not Found

존재하지 않는 리소스
테스트 방법:
GET /api/orders/99999 
{
  "message": "주문을 찾을 수 없습니다",
  "status": 404
}
500

Server Error

서버 내부 오류
테스트 방법:
서버 중지 후 요청 
{
  "message": "서버 오류가 발생했습니다",
  "status": 500
}

7. 실무 Tip 💡

Tip 1 Pre-request Script

로그인 토큰을 자동으로 갱신하는 스크립트 

// Pre-request Script 탭
pm.sendRequest({
    url: '{{baseUrl}}/api/auth/login',
    method: 'POST',
    body: {
        username: 'test',
        password: '1234'
    }
}, function (err, res) {
    pm.environment.set('token',
        res.json().token);
});

Tip 2 Tests 탭 자동 검증

응답이 올바른지 자동으로 확인 

// Tests 탭
pm.test("Status is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Has id field", function () {
    var json = pm.response.json();
    pm.expect(json.id).to.exist;
});

Tip 3 Collection Runner

모든 API를 한 번에 실행

  1. 1. Collection 선택
  2. 2. "Run" 버튼 클릭
  3. 3. 전체 API 자동 실행
  4. 4. 통과/실패 확인

Tip 4 Export & Share

팀원과 Collection 공유하기

  1. 1. Collection 우클릭
  2. 2. "Export" 선택
  3. 3. JSON 파일 저장
  4. 4. Git에 커밋하여 공유
