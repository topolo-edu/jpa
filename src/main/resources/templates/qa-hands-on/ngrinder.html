3. 설치하기 (5분)

사전 요구사항: Docker가 설치되어 있어야 합니다

1

docker-compose.yml 파일 생성

version: '3'
services:
  controller:
    image: ngrinder/controller:latest
    ports:
      - "8300:80"
    volumes:
      - ./ngrinder-controller:/opt/ngrinder-controller

  agent:
    image: ngrinder/agent:latest
    environment:
      - CONTROLLER_ADDR=controller:80
    depends_on:
      - controller
2

Docker Compose 실행

# nGrinder 시작
docker-compose up -d

# 로그 확인

4. 실습 1: 첫 성능 테스트 (15분)

실습 목표

Order 생성 API에 100명이 동시 접속했을 때 성능을 측정합니다

1

테스트 스크립트 작성

경로: 상단 메뉴 "Script" → "Create a script" → "Groovy" 선택 

import static net.grinder.script.Grinder.grinder
import static org.junit.Assert.*
import static org.hamcrest.Matchers.*
import net.grinder.plugin.http.HTTPRequest
import net.grinder.script.GTest
import net.grinder.scriptengine.groovy.junit.GrinderRunner
import net.grinder.scriptengine.groovy.junit.annotation.BeforeThread
import net.grinder.scriptengine.groovy.junit.annotation.BeforeProcess
import org.junit.Before
import org.junit.Test
import org.junit.runner.RunWith

@RunWith(GrinderRunner)
class OrderTest {

    public static GTest test
    public static HTTPRequest request

    @BeforeProcess
    public static void beforeProcess() {
        test = new GTest(1, "Order API Test")
        request = new HTTPRequest()
        test.record(request)
    }

    @BeforeThread
    public void beforeThread() {
        grinder.statistics.delayReports = true
    }

    @Test
    public void test() {
        // POST 요청 - 주문 생성
        def body = """{"customerName":"홍길동","items":[{"productName":"노트북","quantity":1,"price":1500000}]}"""
        def headers = [
            ("Content-Type"): "application/json"
        ]

        def response = request.POST("http://host.docker.internal:8080/api/orders",
                                        body.getBytes(), headers)

        // 응답 검증
        assertThat(response.statusCode, is(200))
    }
}

주의: localhost 대신 host.docker.internal 사용!
Docker 컨테이너에서 호스트 접근 시 필요

5. 실습 2: N+1 문제 개선 Before/After (20분)

실습 목표

N+1 쿼리 문제를 Fetch Join으로 해결하고, 성능 개선 효과를 측정합니다

🐢

Before: N+1 문제

// OrderRepository.java
@Query("SELECT o FROM Order o")
List<Order> findAll();

// 1번 쿼리: Order 전체 조회
// + N번 쿼리: 각 Order의 items 조회
// 총 1 + N번 쿼리 실행! 😱

예상 결과

  • • TPS: 50
  • • 평균 응답시간: 2000ms
  • • 쿼리 수: 1 + N개
🚀

After: Fetch Join

// OrderRepository.java
@Query("SELECT o FROM Order o " +
       "JOIN FETCH o.items")
List<Order> findAllWithItems();

// 1번 쿼리로 모두 조회!
// LEFT JOIN 사용 ✅

예상 결과

  • • TPS: 500 ⬆️ 10배
  • • 평균 응답시간: 150ms ⬇️ 13배
  • • 쿼리 수: 1개

6. 실무 Tip 💡

Tip 1 Ramp-Up 활용

갑자기 100명이 아니라 점진적으로 증가시키기

0초 → 30초 → 60초
0명 → 50명 → 100명

실제 사용자 접속 패턴과 유사

Tip 2 Think Time 설정

사용자가 페이지 보는 시간 대기 시간 추가 

@Test
public void test() {
    request.GET("...")

    // 3초 대기 (사용자가 결과 보는 시간)
    grinder.sleep(3000)

    request.POST("...")
}

Tip 3 Agent 여러 대 사용

더 큰 부하를 주고 싶다면 Agent 추가

  • • Agent 1대: 최대 ~1000 Vuser
  • • Agent 3대: 최대 ~3000 Vuser
docker-compose.yml에서 agent 복제

Tip 4 리포트 저장

테스트 결과를 CSV/이미지로 다운로드

  1. 1. Detailed Report 열기
  2. 2. "Download CSV" 클릭
  3. 3. 그래프 우클릭 → 이미지 저장
  4. 4. PPT에 삽입
