테스트 자동화 가이드

REST API 프로젝트의 품질을 보장하기 위한 테스트 도구와 자동화 프로세스를 단계별로 학습합니다.

총 소요시간: 약 3시간
4단계 학습 과정
Order API 기반 실습

학습 로드맵

Step 1

Postman

REST API의 기본적인 동작을 수동으로 테스트하는 방법을 학습합니다.

소요시간: 10분
목표: API 엔드포인트 검증
테스트 범위: Controller 계층
Step 2

JUnit

단위 테스트와 통합 테스트를 작성하여 자동화된 테스트 환경을 구축합니다.

소요시간: 40분
목표: 테스트 커버리지 60% 이상
테스트 범위: 전체 레이어
Step 3

nGrinder

부하 테스트를 통해 애플리케이션의 성능을 측정하고 병목 지점을 파악합니다.

소요시간: 30분
목표: TPS 측정 및 최적화
설치: Docker Compose
Step 4

JMeter

선택

Apache JMeter를 사용한 성능 테스트와 HTML 리포트 생성 방법을 학습합니다.

소요시간: 30분
목표: HTML 대시보드 생성
설치: Java 11+ 필요

CI/CD 자동화

GitHub Actions를 사용하여 코드 푸시 시 자동으로 테스트가 실행되도록 설정합니다.

소요시간: 20분
목표: 자동 테스트 파이프라인
설치: 불필요

종합 실습

모든 도구를 활용하여 완전한 QA 프로세스를 구축하는 실전 미션입니다.

소요시간: 60-90분
형식: 체크리스트 기반
목표: 전체 프로세스 완성

왜 테스트 자동화가 필요한가?

코드 품질 보장

자동화된 테스트는 코드 변경 시 기존 기능이 정상적으로 동작하는지 즉시 확인할 수 있습니다.

개발 시간 절약

초기에는 테스트 작성에 시간이 소요되지만, 장기적으로는 버그 수정 시간을 크게 줄일 수 있습니다.

리팩토링 자신감

테스트가 있으면 코드 구조를 개선할 때 기능이 깨지지 않는다는 확신을 가질 수 있습니다.

살아있는 문서

잘 작성된 테스트 코드는 해당 기능이 어떻게 동작하는지 설명하는 문서 역할을 합니다.

테스트 도구별 범위

도구 테스트 범위 목적
Postman API 엔드포인트 (Controller 계층) HTTP 요청/응답 검증
JUnit 전체 레이어 (Entity, Service, Repository, Controller) 비즈니스 로직 및 통합 테스트
nGrinder / JMeter 애플리케이션 전체 (End-to-End) 성능 및 부하 테스트

참고: Postman은 API 레벨만 테스트하지만, JUnit은 Entity 비즈니스 로직부터 Controller까지 모든 계층을 테스트할 수 있습니다.

  2. 2. JUnit + 커버리지 (40분)
  3. 3. nGrinder (30분)
  4. 4. JMeter 비교 (30분)
  5. 5. CI/CD 자동화 (20분)
  6. 6. 종합 실습 (60분)
