🤔 nGrinder가 있는데 왜 JMeter를?

솔직히 말하면: 7일 프로젝트나 포트폴리오에서는 nGrinder만으로 충분합니다.
하지만 대기업 취업을 목표로 한다면? JMeter는 거의 필수입니다.

📌 실무 사례:

  • • 삼성SDS, LG CNS 등 SI 대기업: JMeter 표준 도구
  • • 금융권(은행, 증권): JMeter + 사내 플러그인 조합
  • • 네이버, 카카오 일부 팀: nGrinder 선호 (한국 기업이라)
  • • 쿠팡, 배민 등 스타트업: k6, Locust 등 최신 도구 사용

1단계: JMeter 설치

① 사전 준비: Java 11 이상 

# Java 버전 확인
java -version

# 출력 예시:
# openjdk version "17.0.2" 2022-01-18
# ✅ 11 이상이면 OK!

Java가 없다면: https://adoptium.net/ 에서 설치

② JMeter 다운로드

📸 이미지 필요: jmeter-download.png

📋 스크린샷 가이드 (클릭)
  1. 1. 브라우저에서 https://jmeter.apache.org/download_jmeter.cgi 접속
  2. 2. Binaries 섹션에서 apache-jmeter-5.x.zip (Windows) 또는 .tgz (Mac/Linux) 다운로드
  3. 3. 다운로드 페이지 전체 스크린샷 캡처

③ 압축 해제 및 실행 

# Windows
압축 해제 → apache-jmeter-5.6.3\bin\jmeter.bat 실행

# Mac/Linux
tar -xzf apache-jmeter-5.6.3.tgz
cd apache-jmeter-5.6.3/bin
./jmeter.sh

📸 이미지 필요: jmeter-gui.png

📋 스크린샷 가이드 (클릭)
  1. 1. jmeter.bat (또는 .sh) 실행
  2. 2. Swing GUI 창이 뜨면 전체 화면 캡처
  3. 3. 좌측 트리 구조 (Test Plan) 보이게

2단계: 첫 성능 테스트 (nGrinder와 동일 시나리오)

목표: nGrinder Lv.3에서 했던 것과 똑같은 주문 API 테스트를 JMeter로 해보기
→ 두 도구의 차이를 몸으로 체감하는 것이 핵심!

① Thread Group 추가 (= nGrinder의 VUser 설정)

GUI 경로:

Test Plan 우클릭 → Add → Threads (Users) → Thread Group
설정 항목 값 의미
Number of Threads 100 동시 사용자 100명
Ramp-Up Period 10 10초에 걸쳐 점진적 증가
Loop Count 10 각 사용자가 10번 반복

📸 이미지 필요: jmeter-thread-group.png

📋 스크린샷 가이드 (클릭)
  1. 1. Thread Group 추가 후 우측 패널 캡처
  2. 2. Number of Threads, Ramp-Up, Loop Count 입력 필드 보이게

② HTTP Request 추가 (POST /api/orders)

GUI 경로:

Thread Group 우클릭 → Add → Sampler → HTTP Request
필드 입력값
Protocol http
Server Name or IP localhost
Port Number 8080
HTTP Request Method POST
Path /api/orders

Body Data 탭으로 이동하여 입력:

{
  "customerName": "홍길동",
  "items": [
    {
      "itemName": "노트북",
      "quantity": 1,
      "price": 1500000
    }
  ]
}

HTTP Header Manager 추가:

GUI 경로:

HTTP Request 우클릭 → Add → Config Element → HTTP Header Manager

Add 버튼 클릭하여 추가:

Name: Content-Type | Value: application/json

📸 이미지 필요: jmeter-http-request.png

📋 스크린샷 가이드 (클릭)
  1. 1. HTTP Request 설정 화면 캡처
  2. 2. Protocol, Server Name, Port, Method, Path 보이게
  3. 3. Body Data 탭의 JSON도 함께 캡처

③ Listener 추가 (결과 확인용)

추가할 Listener 3개:

Thread Group 우클릭 → Add → Listener → View Results Tree Thread Group 우클릭 → Add → Listener → Summary Report Thread Group 우클릭 → Add → Listener → Aggregate Report
Listener 용도
View Results Tree 각 요청/응답 상세 확인 (디버깅용)
Summary Report TPS, 평균 응답 시간 요약
Aggregate Report 더 상세한 통계 (50%, 90%, 95% percentile)

④ 테스트 실행 및 결과 확인

실행:

상단 메뉴 → Run → Start (또는 Ctrl+R)

📸 이미지 필요: jmeter-aggregate-report.png

📋 스크린샷 가이드 (클릭)
  1. 1. 테스트 실행 후 Aggregate Report 클릭
  2. 2. Average, 90% Line, Throughput 열 보이게
  3. 3. 전체 테이블 캡처

예상 결과 (Fetch Join 적용 후)

  • • Average: 150ms 내외
  • • 90% Line: 200ms 내외
  • • Throughput: 500+ requests/sec
  • • Error %: 0.00%

3단계: HTML 대시보드 생성 (발표용)

JMeter의 핵심 강점: GUI 테스트 후 jmeter -g 명령으로 멋진 HTML 리포트를 자동 생성!
→ 이 리포트를 발표 자료로 쓰면 정말 전문가처럼 보임 👔

① 테스트 플랜 저장

File → Save Test Plan as → order-api-test.jmx

② CLI 모드로 테스트 실행 (리포트용) 

# Windows
jmeter -n -t order-api-test.jmx -l results.jtl

# Mac/Linux
./jmeter.sh -n -t order-api-test.jmx -l results.jtl

# 옵션 설명:
# -n : Non-GUI 모드 (CLI)
# -t : Test plan 파일
# -l : 결과 로그 파일

③ HTML 대시보드 생성 

# Windows
jmeter -g results.jtl -o html-report

# Mac/Linux
./jmeter.sh -g results.jtl -o html-report

# 옵션 설명:
# -g : 로그 파일 지정
# -o : 출력 폴더 (자동 생성)

html-report/index.html 파일이 생성됨!
→ 브라우저로 열면 프로페셔널한 대시보드 확인 가능 📊

📸 이미지 필요: jmeter-html-dashboard.png

📋 스크린샷 가이드 (클릭)
  1. 1. html-report/index.html 브라우저로 열기
  2. 2. 대시보드 상단 (Test and Report information 섹션) 캡처
  3. 3. Statistics 표와 그래프 포함되게

Pro Tips: JMeter 고급 활용

Plugins Manager 설치

JMeter 기본 기능만으로는 부족? Plugins Manager로 확장!

설치 방법:

  1. 1. jmeter-plugins.org 접속
  2. 2. plugins-manager.jar 다운로드
  3. 3. lib/ext 폴더에 복사
  4. 4. JMeter 재시작 → Options → Plugins Manager

추천 플러그인: 3 Basic Graphs, PerfMon, Composite Graph

CSV Data Set Config

매번 같은 데이터 말고 다양한 고객명으로 테스트하려면?

customers.csv 파일 생성:

customerName
홍길동
김철수
이영희
박민수

CSV Data Set Config 추가:

Thread Group 우클릭 → Config Element → CSV Data Set Config

사용: Body Data에서 ${customerName}으로 참조

Constant Throughput Timer

"정확히 TPS 100 유지"처럼 일정한 처리량을 원한다면?

추가 방법:

Thread Group 우클릭 → Timer → Constant Throughput Timer

설정:

  • • Target Throughput: 6000 (분당 6000 = 초당 100)
  • • Calculate Throughput based on: all active threads

→ TPS가 일정하게 유지됨!

BeanShell / JSR223 Sampler

복잡한 로직 (동적 토큰, 암호화 등)이 필요하다면?

JSR223 PreProcessor 추가:

HTTP Request 우클릭 → Pre Processors → JSR223 PreProcessor

예시: 랜덤 가격 생성

import java.util.Random;
Random rand = new Random();
int price = 1000000 + rand.nextInt(1000000);
vars.put("randomPrice", String.valueOf(price));

Body에서 사용: "price": ${randomPrice}

면접에서 자주 나오는 질문

Q1: JMeter와 nGrinder 차이가 뭔가요?

A: nGrinder는 웹 기반이라 설치가 쉽고 한글 지원이 완벽합니다. JMeter는 GUI 기반이지만 플러그인 생태계가 방대하고 글로벌 표준이라 대기업에서 선호합니다. 저는 빠른 테스트는 nGrinder, 정식 리포트는 JMeter HTML 대시보드를 사용합니다.

Q2: GUI 모드와 CLI 모드 차이는?

A: GUI 모드는 테스트 시나리오를 만들 때 사용하고, 실제 성능 테스트는 CLI 모드(-n 옵션)로 실행해야 정확합니다. GUI는 자체적으로 리소스를 많이 먹기 때문입니다.

Q3: TPS 목표치는 어떻게 정하나요?

A: 비즈니스 요구사항에 따라 다릅니다. 예를 들어 1초에 100명이 주문할 수 있어야 한다면 TPS 100이 목표입니다. 이번 프로젝트에서는 TPS 500을 달성했고, 이는 초당 500건의 주문 처리가 가능하다는 의미입니다.

언제 JMeter를 써야 할까?

JMeter 추천 상황

  • 대기업 취업 목표 (삼성SDS, LG CNS, SI 업체)
  • 정식 성능 리포트가 필요한 경우 (HTML 대시보드)
  • 복잡한 시나리오 (다단계 트랜잭션, 조건 분기 등)
  • 플러그인 활용이 필요한 경우 (DB, FTP, MQTT 등)
  • 글로벌 표준 도구 경험을 쌓고 싶을 때

nGrinder 추천 상황

  • 7일 프로젝트 (시간이 부족할 때)
  • 빠른 성능 체크가 목적 (N+1 확인 등)
  • Docker 환경을 선호하는 경우
  • 한국 기업 (네이버, 카카오, 쿠팡 등) 지원 시
  • 웹 UI가 편한 초보자
